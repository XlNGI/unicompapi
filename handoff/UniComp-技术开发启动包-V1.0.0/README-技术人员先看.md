# UniComp｜技术开发启动包 V1.0.0

本包用于把 UniComp 现有 Codex 文档归档与最新 UI / 产品 / 技术交接资料，一次性交给技术开发团队。

## 一、包内内容

### 00-交接原件

- `docs.rar`  
  最开始由 Codex 输出的原始文档归档。保持原样，用于审计、追溯和了解此前工作。

- `UniComp-AI-最终UI与开发交接包-V1.2.1.zip`  
  当前最新、最高优先级的 UI、产品边界、技术规则、Codex 实现说明和权威设计图。

### 01-Codex启动指令

- `AGENTS-项目级追加规则.md`
- `Codex-首次接管并启动开发-一次性指令.md`
- `Codex-后续阶段任务指令模板.md`

### 02-技术人员操作说明

- `技术人员接收与启动步骤.md`
- `资料优先级与禁止事项.md`
- `建议开发阶段与验收门禁.md`

### 03-最终UI交接包-已解压

已解压的 V1.2.1 最终交接包，便于 Codex 直接读取，不必依赖压缩包读取能力。

### 04-文件校验

保存两个交接原件和整个技术启动包的 SHA-256 校验信息。

---

## 二、必须明确

本启动包主要是产品、UI、规则和开发交接资料。

技术人员还必须拥有：

1. UniComp 实际 Git 代码仓库；
2. 仓库的读写权限；
3. Windows 与 macOS 构建环境或对应 CI；
4. 必要的模型服务测试账号或测试凭证；
5. 代码签名、安装包和发布权限（进入发布阶段时）。

没有实际代码仓库时，Codex只能新建工程，不能接着现有代码开发。

---

## 三、资料优先级

发生冲突时：

1. 项目负责人最新明确决策；
2. `UniComp-AI-最终UI与开发交接包-V1.2.1`；
3. 项目根目录最新 `AGENTS.md` 与正式开发记录；
4. `docs.rar` 中的原始 Codex 文档；
5. 现有旧代码、旧 UI 和历史归档。

旧代码和旧 UI 只能作为审计参考，不得反向限制新版本。

---

## 四、推荐使用方式

不要把两个压缩包直接覆盖到代码仓库。

建议在代码仓库根目录创建：

```text
handoff/
└─ UniComp-技术开发启动包-V1.0.0/
```

把本包完整解压到该目录，然后打开**代码仓库根目录**给 Codex。

首次任务直接粘贴：

`01-Codex启动指令/Codex-首次接管并启动开发-一次性指令.md`

Codex应先完成接管审计、规则合并和开发计划，再在没有阻断项时开始第一阶段工程实现。
