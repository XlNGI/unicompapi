# 技术人员接收与启动步骤

## 1. 准备实际代码仓库

必须先拿到 UniComp 的 Git 仓库，而不是只拿本资源包。

执行：

```bash
git clone <UniComp仓库地址>
cd <UniComp仓库目录>
git status
git switch -c develop/unicomp-v1-rebuild
```

分支名可按团队规则调整，但不要直接在主分支开发。

## 2. 放入交接包

在仓库根目录创建：

```text
handoff/
└─ UniComp-技术开发启动包-V1.0.0/
```

把本压缩包完整解压进去。

不要把 `docs.rar` 直接覆盖到仓库现有 `docs/`。

## 3. 打开 Codex

使用 Codex 桌面客户端时：

- 打开实际 Git 仓库根目录；
- 确认 Codex 可以读取仓库和 `handoff/`；
- 新建开发任务；
- 粘贴“一次性启动指令”。

使用 Codex CLI 时，在仓库根目录启动 Codex。

## 4. 粘贴首次指令

复制：

```text
handoff/UniComp-技术开发启动包-V1.0.0/
└─ 01-Codex启动指令/
   └─ Codex-首次接管并启动开发-一次性指令.md
```

整份内容粘贴给 Codex。

## 5. 第一轮不应该直接得到什么

第一轮不应该出现：

- 直接重写全部项目；
- 直接实现所有页面；
- 删除旧代码；
- 修改权威设计图；
- 重新规划产品；
- 跳过审计和测试；
- 只回复建议却没有实际执行。

## 6. 第一轮应该产出什么

至少应产出：

- 接管审计报告；
- 现状差距清单；
- 开发总计划；
- 技术风险与验证计划；
- 页面与设计图映射；
- 测试与验收总表；
- 合并后的根目录 AGENTS.md；
- PLANS.md；
- 当前基线测试结果；
- 阶段 1 的真实代码和验证结果，或明确阻断项。

## 7. 人工检查点

技术负责人检查：

- 最终资料优先级是否写入 AGENTS.md；
- 是否删除了多图参考和批量创作；
- 是否保留八项最终导航；
- 对话页是否没有直接生成按钮；
- 是否开始使用 Design Tokens；
- 是否保留 Windows / macOS 双平台；
- 是否没有写死模型与费用；
- 是否运行了真实测试；
- 是否没有破坏旧代码。

## 8. 后续开发

每次只给 Codex 一个阶段任务，使用：

`Codex-后续阶段任务指令模板.md`

不要一次让 Codex“把所有功能全部做完”，否则验收和错误定位会失控。
