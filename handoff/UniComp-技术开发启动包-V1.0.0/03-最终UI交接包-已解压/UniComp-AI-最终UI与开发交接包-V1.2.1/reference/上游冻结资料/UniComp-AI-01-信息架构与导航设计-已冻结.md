## 1. 文档目的

本文确定 UniComp AI V1.0 的产品级信息架构和导航体系，用于回答：

- 用户打开应用后先看见什么；
- 项目、创作、任务、作品、模型与设置分别放在哪里；
- 图片和视频两条创作主线如何在同一桌面应用中组织；
- 哪些界面属于常驻页面，哪些属于任务过程中的临时界面；
- 用户在项目、任务和作品之间如何连续切换而不丢失上下文；
- Windows 与 macOS 如何保持同一产品结构。

本文不定义最终颜色、字体、尺寸、三栏宽度、组件外观或具体动画；这些内容在后续桌面框架和 Design System 文档中确定。

## 2. 信息架构冻结依据

### 2.1 核心对象

信息架构必须长期保持以下对象边界：

- **项目：** 持续创作的本地容器；
- **素材：** 被导入、引用或复用的图片、视频、文本等输入；
- **上下文：** 用户明确选入当前任务的人物、品牌、商品、场景、脚本等信息；
- **创作草稿：** 尚未正式提交的本次创作配置；
- **任务：** 一次真实执行及其上传、提交、生成、下载和恢复过程；
- **作品：** 已成功保存到本地、能够预览或继续创作的结果；
- **文件：** 本地磁盘上的真实媒体或项目数据；
- **服务商、模型和能力声明：** 三个不可混淆的能力层级。

### 2.2 核心闭环

```text
项目与素材
→ 创作草稿
→ 提示词确认
→ 外发与费用确认
→ 任务中心
→ 结果处理与本地保存
→ 作品库
→ 继续编辑或再次创作
```

### 2.3 架构原则

1. 项目是创作主容器，不以聊天记录替代；
2. 图片与视频是项目内的两类创作工作台，不拆成两个独立应用；
3. 任务中心负责过程事实，不负责长期作品管理；
4. 作品库负责已落地结果，不把远端链接或未完成下载当作品；
5. 模型与服务商是支撑域，不抢占创作主视觉；
6. 提示词确认、外发授权和费用确认属于创作提交过程，不成为一级导航；
7. 项目内素材、项目任务和项目作品可以被快速访问，但全局事实仍分别由任务中心与作品库统一管理；
8. 所有未实测模型能力通过动态声明显示，不在导航和页面名称中写死模型名称。

## 3. 一级信息架构

UniComp AI V1.0 采用五个一级功能入口：

```text
UniComp AI
├─ 项目
├─ 任务
├─ 作品
├─ 模型
└─ 设置
```

### 3.1 “项目”

**定位：** 应用默认入口和主要创作容器。

承担：

- 新建项目；
- 打开本地项目；
- 最近项目；
- 最近创作；
- 继续未完成草稿；
- 进入图片或视频工作台；
- 管理当前项目素材与上下文；
- 查看当前项目的任务和作品摘要。

不承担：

- 全局任务状态的唯一管理；
- 全局作品整理；
- 服务商和 API Key 配置；
- 传统“首页数据看板”。

### 3.2 “任务”

**定位：** 全局任务过程中心。

承担：

- 图片、视频、识别、编辑、提示词增强、下载、保存和批量任务的统一追踪；
- 真实状态、等待时间、最近查询、费用状态；
- 取消、恢复、重试、过期和需要用户处理；
- 批次与子任务关系；
- 从任务返回来源项目或打开已保存作品。

不承担：

- 长期作品整理；
- 修改历史任务事实；
- 自动跨服务商重新提交。

### 3.3 “作品”

**定位：** 本地 AI 创作资产库。

承担：

- 图片与视频统一浏览；
- 按项目、类型、时间、模型、收藏、文件状态等筛选；
- 预览、版本关系、来源追溯；
- 重命名、收藏、导出、删除和批量整理；
- 继续编辑、再次生成、图片转视频等后续创作。

不承担：

- 展示尚未完成本地保存的结果为正式作品；
- 隐藏文件丢失、损坏或外置盘断开状态；
- 用作品删除覆盖任务曾发生的事实。

### 3.4 “模型”

**定位：** 模型与服务商能力管理。

承担：

- 服务商、模型和能力声明三层管理；
- 国内在线、海外在线、本机、局域网和自定义兼容接口；
- API Key 输入、替换、测试和删除；
- 连接状态、身份核验状态、能力来源和最后验证时间；
- 启用、停用、默认偏好和能力比较。

不承担：

- 把连接成功写成全部能力已验证；
- 将第三方兼容接口冒充官方服务；
- 在创作过程中替代用户进行静默模型切换。

### 3.5 “设置”

**定位：** 当前设备上的本地偏好和系统行为设置。

承担：

- 存储目录；
- 备份、恢复和迁移；
- 代理、网络和证书相关设置入口；
- 通知；
- 外观与无障碍偏好；
- 隐私、诊断和日志偏好；
- 软件版本信息及已批准的更新方式。

不承担：

- 首次服务商授权；
- 单次任务外发授权；
- 永久空白付费授权；
- UniComp 账号和云端后台。

## 4. 一级导航最终建议

### 4.1 导航顺序

全局导航固定建议为：

1. 项目；
2. 任务；
3. 作品；
4. 模型；
5. 设置。

排序理由：

- 用户首先围绕项目创作；
- 任务是进行中的过程；
- 作品是已经落地的结果；
- 模型与设置只在需要配置时进入。

### 4.2 不设置“首页”一级入口

项目入口本身承担应用起始页职责，因此不再增加含义模糊的“首页”。

避免出现：

- 首页；
- 项目；
- 创作；

三个互相重叠的入口。

### 4.3 不设置“聊天”一级入口

普通对话只能作为视觉创作辅助，不成为导航骨架。

### 4.4 不将“图片”和“视频”设为全局一级导航

图片与视频需要共享：

- 当前项目；
- 素材；
- 上下文；
- 提示词确认；
- 外发授权；
- 任务中心；
- 作品库。

因此它们属于项目内创作模式，而非两个相互割裂的全局应用。

## 5. 项目入口信息架构

### 5.1 项目中心

用户启动应用后默认进入“项目中心”。

项目中心包含以下内容区域：

1. **继续创作**
   - 最近打开项目；
   - 最近未完成草稿；
   - 需要用户处理的项目任务；
   - 最近保存作品。

2. **项目列表**
   - 最近项目；
   - 全部本地项目；
   - 项目封面或最近作品；
   - 项目路径与可用状态；
   - 最近活动时间。

3. **新建与打开**
   - 新建本地项目；
   - 打开已有项目；
   - 从备份恢复或迁移项目的入口；
   - 快速开始图片或视频创作。

4. **异常状态**
   - 项目路径失效；
   - 外置盘断开；
   - 项目数据损坏；
   - 权限不足；
   - 项目正在迁移或恢复。

项目中心不使用统计 KPI 卡片，不制造管理后台感。

### 5.2 快速开始规则

“快速创建图片”或“快速创建视频”必须明确项目归属：

- 当前已有活动项目：进入该项目并创建本地草稿；
- 没有活动项目：先创建或选择项目；
- 不允许生成无项目归属的孤立任务。

## 6. 项目内信息架构

打开项目后，项目内部采用四个稳定区域：

```text
当前项目
├─ 概览
├─ 图片
├─ 视频
└─ 素材与上下文
```

### 6.1 项目概览

承担：

- 项目目标和描述；
- 最近草稿；
- 进行中和需处理任务摘要；
- 最近作品；
- 最近素材；
- 快速进入图片或视频创作；
- 项目路径与本地保存状态。

项目概览不是数据看板，重点是“继续做什么”。

### 6.2 图片工作区

图片工作区内部模式：

```text
图片
├─ 生成
├─ 识别
├─ 编辑
├─ 转提示词
├─ 多图参考
└─ 批量
```

说明：

- “生成”覆盖文生图及单图参考的常规入口；
- “多图参考”独立呈现每张素材用途和发送范围；
- “识别”“编辑”“转提示词”保留各自结果结构和后续动作；
- “批量”用于多个独立草稿和子任务，不把批量隐藏成数量参数。

### 6.3 视频工作区

视频工作区内部模式：

```text
视频
├─ 文生视频
├─ 图生视频
├─ 批量
└─ 基础编辑
```

说明：

- 文生视频是视频创作首要入口；
- 长文本、故事、脚本和营销内容先形成可编辑镜头草稿，不自动提交；
- 图生视频必须展示图片用途、图片理解结果和运动要求；
- 基础编辑面向 AI 生成结果，不模拟专业剪辑软件。

### 6.4 素材与上下文

统一管理：

- 用户导入素材；
- 当前项目历史作品；
- 人物、品牌、商品、场景、风格、脚本等上下文；
- 每项内容的来源；
- 使用限制；
- 当前任务是否选中；
- 是否会被外发；
- 跨项目引用关系。

素材与上下文在项目中长期存在，但只有用户明确选择的内容才能进入当前任务。

## 7. 创作过程界面归属

以下界面不进入一级导航，也不作为独立孤立页面：

### 7.1 提示词增强与最终确认

属于图片或视频工作台内的提交前过程。

必须同时展示：

1. 用户原始输入；
2. 系统补充内容；
3. 最终提交提示词。

该界面可以使用工作台内的大型审查面板或步骤界面，具体布局在第三阶段确定。

### 7.2 外发与费用确认

属于最终提交前的阻断式确认界面。

必须展示：

- 服务商、接入渠道和模型；
- 验证状态；
- 原始输入、系统补充和最终提示词；
- 发送的上下文和素材；
- 参数和批量数量；
- 费用状态；
- 数据离开本机；
- 跨境或处理地区未知；
- 重试预授权范围。

确认完成后才创建真实提交任务。

### 7.3 任务详情

任务详情属于任务中心的详情层。

桌面端优先采用：

- 任务列表；
- 详情检查区；
- 必要时进入更完整详情或错误证据界面。

不为每种任务状态创建独立页面。

### 7.4 作品详情

作品详情属于作品库的详情层。

桌面端优先采用：

- 作品网格或列表；
- 详情检查区；
- 全屏预览；
- 版本关系视图。

不把作品详情拆成大量层级页面。

## 8. 全局任务连续性

### 8.1 全局任务活动入口

应用外壳应保留一个轻量、可折叠的任务活动入口，用于持续展示：

- 当前运行任务数量；
- 需要用户处理数量；
- 最近完成或失败状态；
- 点击后进入任务快速视图或任务中心。

该入口不是第二套任务中心，不展示虚假进度。

### 8.2 页面切换规则

用户在项目、作品或模型页面之间切换时：

- 已提交任务继续由任务中心跟踪；
- 当前项目草稿保留；
- 页面切换不得触发重新提交；
- 返回工作台时恢复最近本地草稿和界面上下文；
- 需要用户确认的步骤必须明确保持“尚未提交”。

### 8.3 应用重启规则

重新启动应用后：

1. 先恢复本地项目、草稿与任务记录；
2. 再恢复未结束任务的状态查询；
3. 不因恢复创建新任务；
4. 无法确认上游状态时进入需要用户处理路径；
5. 已保存作品继续由作品库管理。

## 9. 页面关系图

```text
应用启动
└─ 项目中心
   ├─ 新建项目
   ├─ 打开项目
   └─ 继续最近项目
      └─ 项目概览
         ├─ 图片工作区
         │  ├─ 生成
         │  ├─ 识别
         │  ├─ 编辑
         │  ├─ 转提示词
         │  ├─ 多图参考
         │  └─ 批量
         ├─ 视频工作区
         │  ├─ 文生视频
         │  ├─ 图生视频
         │  ├─ 批量
         │  └─ 基础编辑
         └─ 素材与上下文

图片/视频草稿
→ 提示词增强与最终确认
→ 外发与费用确认
→ 任务中心
→ 结果处理与本地保存
→ 作品库
→ 返回项目继续创作

全局入口：
任务中心 ↔ 来源项目 ↔ 已保存作品
作品库 ↔ 来源任务 ↔ 当前项目
模型管理 → 为创作提供动态能力
设置 → 为所有功能域提供本地偏好
```

## 10. 页面命名规则

采用面向创作者的直接名称：

- 项目；
- 图片；
- 视频；
- 素材与上下文；
- 任务；
- 作品；
- 模型；
- 设置；
- 提示词确认；
- 发送确认；
- 任务详情；
- 作品详情。

禁止使用以下名称作为正式主导航：

- 控制台；
- Dashboard；
- Playground；
- Workspace Manager；
- API 管理；
- AI 助手；
- 聊天；
- 数据中心；
- 资产后台。

必要技术词只在解释层出现，不进入核心导航。

## 11. Windows 与 macOS 导航一致性

两个平台保持一致：

- 一级入口名称；
- 项目内结构；
- 图片和视频模式；
- 任务状态；
- 作品关系；
- 提示词与外发确认结构。

允许平台差异：

- 窗口控制区域；
- 系统菜单和快捷键符号；
- 文件选择器；
- 系统权限提示；
- 通知样式；
- 系统标题栏处理。

平台差异不得改变用户完成核心任务的步骤和信息透明度。

---

## 12. 明确禁止的架构方式

1. 以聊天记录作为项目容器；
2. 将全部功能塞入单页三栏；
3. 为每个小动作建立独立一级页面；
4. 把图片与视频拆成两个互不关联的应用；
5. 在左侧导航罗列全部模型或服务商；
6. 把任务中心设计成后台表格；
7. 把作品库设计成普通文件浏览器；
8. 用首页统计数据取代最近创作和继续工作；
9. 把提示词增强隐藏在生成按钮之后；
10. 把外发授权放进设置并永久默认同意；
11. 因当前模型不支持某项参数而永久删除该信息架构位置；
12. 以旧 UI、旧代码路由或现有组件约束新版本结构。

---

## 13. 信息架构验收标准

通过评审至少满足：

- 用户能理解项目、任务和作品的区别；
- 图片和视频在同一项目中连续工作；
- 项目中心能让用户直接继续最近创作；
- 图片与视频能力均有明确且不重复的归属；
- 提示词确认与外发确认不会被跳过；
- 任务可从任何页面持续追踪；
- 作品能返回来源任务和项目；
- 模型和设置不干扰日常创作；
- 没有聊天软件、传统后台或 API 工具的信息架构；
- 未实测能力没有写入固定导航或固定参数页面。

## 14. 本阶段建议冻结的设计决策

建议产品负责人一次性确认以下事项：

1. 一级导航固定为“项目、任务、作品、模型、设置”；
2. 不增加“首页”“聊天”“图片”“视频”全局一级入口；
3. 图片与视频作为项目内工作区；
4. 项目内固定为“概览、图片、视频、素材与上下文”；
5. 提示词确认与发送确认属于工作台提交过程；
6. 任务详情采用任务中心内的列表—详情结构；
7. 作品详情采用作品库内的网格/列表—详情结构；
8. 应用外壳保留轻量任务活动入口；
9. 项目任务和项目作品通过全局中心的项目筛选访问，不建立重复数据域。

确认后，本文升级为 V1.0.0“已冻结”，作为第三阶段桌面应用框架设计的唯一信息架构依据。
