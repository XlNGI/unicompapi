## 1. 文档目的

本文定义 UniComp AI 首批核心页面必须解决的用户任务，以及从创作输入到本地作品的完整流程。

本文只确定：

- 页面职责；
- 页面之间的流转；
- 关键步骤顺序；
- 阻断条件；
- 恢复路径；
- 用户在每一步必须看见的事实。

本文不定义最终视觉样式和像素布局。

---

## 2. 通用任务流原则

任何图片或视频在线创作都必须经过：

```text
项目
→ 本地草稿
→ 输入与素材
→ 提示词审查
→ 模型能力检查
→ 外发与费用确认
→ 创建任务
→ 跟踪真实状态
→ 结果下载和本地保存
→ 形成作品
→ 继续创作
```

### 2.1 不允许跳过的步骤

以下步骤不得被一个“生成”按钮完全隐藏：

- 用户选择当前任务使用的上下文；
- 用户确认将发送的素材；
- 用户看见提示词三层；
- 用户看见实际服务商和模型；
- 用户看见费用状态；
- 用户确认数据离开本机；
- 模型能力检查；
- 结果完成本地保存。

### 2.2 草稿与任务边界

- 点击“保存草稿”或离开工作台不创建外部任务；
- 提示词增强完成不等于生成任务已提交；
- 长文本拆分完成不等于视频任务已创建；
- 用户完成发送确认后，才进入等待提交或上传状态；
- 重试产生新的执行记录，不覆盖原任务事实。

### 2.3 本地与在线边界

默认本地行为：

- 项目整理；
- 草稿编辑；
- 素材分类；
- 作品预览；
- 重命名；
- 收藏；
- 本地筛选；
- 不调用在线模型的基础处理。

必须提示外发的行为：

- 在线提示词增强；
- 图片识别；
- 图片生成与编辑；
- 图片转提示词；
- 视频生成；
- 上传参考素材；
- 远端重试；
- 跨服务商切换；
- 自定义远程接口请求。

## 3. 首批核心页面职责

### 3.1 项目入口与最近创作

用户目标：

- 新建项目；
- 打开已有项目；
- 继续最近草稿；
- 看见正在处理和需要处理的任务；
- 打开最近作品。

成功标准：

用户无需登录，也无需先进入设置，即可理解自己最近在做什么和下一步做什么。

### 3.2 图片创作工作台

用户目标：

- 选择图片创作模式；
- 输入需求；
- 选择素材与上下文；
- 配置当前模型支持的参数；
- 审查提示词；
- 提交任务；
- 比较结果并继续创作。

### 3.3 图片识别与结果编辑

用户目标：

- 选择一张或多张图片；
- 选择识别目的；
- 看见可见事实、模型推断、不确定和无法识别内容；
- 修改识别结果；
- 将确认后的结果转入提示词、编辑或视频创作。

### 3.4 视频创作工作台

用户目标：

- 文生视频或图生视频；
- 输入短文本、长文本、故事、脚本或营销内容；
- 形成镜头草稿；
- 调整镜头、动作、场景、风格、节奏和限制；
- 选择动态能力参数；
- 提交异步任务；
- 预览、继续创作或进入基础编辑。

### 3.5 提示词增强与最终确认

用户目标：

- 对照原始输入；
- 查看系统补充；
- 查看最终提交提示词；
- 修改或移除补充；
- 恢复原文；
- 明确增强服务是否在线及其接收方。

### 3.6 外发与费用确认

用户目标：

- 看见实际接收方；
- 看见将发送的数据范围；
- 看见模型、能力状态和参数；
- 看见费用已估算、未知或以服务商账单为准；
- 看见跨境或处理地区未知；
- 确认本次发送和有限重试范围。

### 3.7 任务中心与任务详情

用户目标：

- 知道任务进行到哪一步；
- 知道是否仍在远端执行；
- 知道是否可能已收费；
- 取消、恢复、重试或处理异常；
- 找到来源项目和结果作品。

### 3.8 作品库与作品详情

用户目标：

- 找到已保存图片与视频；
- 查看版本、来源和实际文件状态；
- 导出、整理或继续创作；
- 处理文件丢失、损坏和外置盘断开。

## 4. 流程一：启动、项目创建与继续创作

```text
启动应用
→ 恢复本地项目索引与任务记录
→ 进入项目中心
├─ 有最近项目
│  ├─ 继续最近草稿
│  ├─ 打开需要处理的任务
│  └─ 打开最近作品
└─ 无项目
   ├─ 新建项目
   └─ 打开已有本地项目
```

### 4.1 新建项目

用户至少确认：

- 项目名称；
- 本地保存位置；
- 可选项目说明或目标。

完成后进入项目概览，不强制配置在线服务商。

### 4.2 打开项目异常

- 路径失效：允许重新定位；
- 外置盘断开：保留记录并提示连接设备；
- 权限不足：允许修复权限或只读查看可确认内容；
- 数据损坏：说明可恢复内容，不伪装正常打开。

---

## 5. 流程二：图片生成

```text
项目 → 图片 → 生成
→ 输入原始需求
→ 选择上下文和参考图
→ 为参考图标明用途
→ 选择模型或确认推荐
→ 按能力声明显示参数
→ 提示词增强与最终确认
→ 外发与费用确认
→ 创建图片任务
→ 上传/提交/生成/结果处理/下载
→ 成功保存本地
→ 形成一个或多个并列作品
→ 比较、继续编辑、再次生成或导出
```

### 5.1 提交前阻断条件

- 缺少必要输入；
- 素材不可读；
- 素材用途不明确；
- 模型明确不支持；
- 参数组合无效；
- Key 缺失或无效；
- 外发授权未完成；
- 费用或接收方变化导致原确认失效。

### 5.2 结果规则

- 同一次返回的多个结果是同批并列作品；
- 再次生成是新任务；
- 调整提示词、参数或模型后生成形成新版本或同源新分支；
- 未完成本地保存不得显示为作品完成。

---

## 6. 流程三：多图参考

```text
选择多张图片
→ 逐图确认来源和用途
→ 指定主图或主要参考
→ 系统检查数量、格式和模型限制
→ 用户确认实际发送范围
→ 提示词确认
→ 外发与费用确认
→ 创建任务
```

每张图片必须显示：

- 是否参与本次任务；
- 参考用途；
- 是否会发送；
- 是否存在仅本地或服务商限制；
- 当前模型是否支持该用途。

模型不支持全部参考图时：

- 不静默删除；
- 给出减少图片、调整用途或更换模型的明确选择；
- 更换服务商需要重新外发确认。

---

## 7. 流程四：图片识别与结果编辑

```text
项目 → 图片 → 识别
→ 选择图片
→ 选择识别目标或问题
→ 选择可用识别模型
→ 确认外发范围和费用
→ 创建识别任务
→ 返回结构化结果
→ 用户审查和修改
→ 选择后续动作
   ├─ 保存为项目上下文
   ├─ 转为提示词草稿
   ├─ 进入图片编辑
   ├─ 进入图片生成
   └─ 进入图生视频
```

识别结果必须区分：

- 可见事实；
- 模型推断；
- 不确定信息；
- 无法识别；
- 用户修改内容。

用户修改后的结果不能倒写成“模型原始结论”。

---

## 8. 流程五：图片编辑

```text
选择原图或图片作品
→ 输入修改要求
→ 输入需要保留的内容
→ 可选选择区域或蒙版
→ 选择模型并检查编辑能力
→ 提示词确认
→ 外发与费用确认
→ 创建编辑任务
→ 返回新结果
→ 新结果作为派生作品保存
```

固定规则：

- 不覆盖原图；
- 不把“效果不满意”当系统失败；
- 再次编辑形成新任务和新版本；
- 原图、父作品、编辑任务和新作品保持可追溯。

---

## 9. 流程六：图片转提示词

```text
选择图片
→ 选择目标用途和输出结构
→ 选择识别/转换模型
→ 确认图片外发
→ 创建转换任务
→ 返回结构化提示词草稿
→ 用户修改与确认
→ 选择后续动作
   ├─ 保存为项目上下文
   ├─ 进入图片生成
   ├─ 进入图片编辑
   └─ 进入视频创作
```

转换结果只是可编辑草稿，不自动提交新的生成任务。

---

## 10. 流程七：文生视频

```text
项目 → 视频 → 文生视频
→ 输入短文本、长文本、故事、脚本或营销内容
→ 选择原始模式/智能优化/上下文增强/长文本转换
→ 短文本：形成单个或少量镜头草稿
→ 长文本：拆分为多个可编辑镜头草稿
→ 用户调整镜头顺序、内容、合并和删除
→ 选择模型并检查能力
→ 设置可用视频参数
→ 提示词三层确认
→ 外发与费用确认
→ 创建一个或多个视频子任务
→ 异步跟踪
→ 下载和本地保存
→ 形成视频作品
→ 预览、继续生成、图生视频延伸或基础编辑
```

### 10.1 镜头草稿规则

每个镜头至少能够表达：

- 主体；
- 动作；
- 场景；
- 镜头；
- 风格；
- 光线与色彩；
- 节奏；
- 用途与限制。

拆分完成不自动创建任务。

### 10.2 任务状态表达

服务商没有百分比时只显示：

- 真实阶段；
- 已等待时间；
- 最近查询时间；
- 当前可执行动作。

---

## 11. 流程八：图生视频

```text
选择上传图片或图片作品
→ 指定起始画面、主体或其他用途
→ 生成可编辑图片理解结果
→ 用户确认或修改理解结果
→ 输入运动、动作、镜头与场景变化
→ 选择模型并检查图片和视频能力
→ 提示词确认
→ 外发与费用确认
→ 创建视频任务
→ 异步跟踪
→ 本地保存为视频作品
```

固定规则：

- 图片理解结果必须可编辑；
- 用户必须知道图片会被发送；
- 图像用途必须明确；
- 不支持的图片数量或格式不得静默忽略；
- 视频作品保留来源图片和来源项目关系。

---

## 12. 流程九：提示词增强

```text
原始输入
→ 选择增强模式
→ 判断增强在本地还是外部执行
├─ 本地增强
│  └─ 生成系统补充
└─ 外部增强
   ├─ 展示增强服务商、数据范围和费用
   ├─ 用户确认
   └─ 创建独立增强任务
→ 同屏展示三层提示词
→ 用户编辑、删除补充或恢复原文
→ 确认最终提交提示词
```

### 12.1 三层内容规则

1. 原始输入始终保留；
2. 系统补充逐项标明类别和来源；
3. 最终提交提示词可编辑；
4. 翻译和模型格式转换也属于系统补充；
5. 外部增强服务与生成服务不同，需要分别说明接收方和费用；
6. 增强失败时允许回到原始输入继续，而不是阻断全部创作。

## 13. 流程十：外发与费用确认

外发确认是在线任务提交前的最后阻断步骤。

```text
提交前检查
→ 接收方确认
→ 发送内容确认
→ 参数与数量确认
→ 费用状态确认
→ 跨境与处理位置确认
→ 重试范围确认
→ 用户确认提交
→ 创建任务
```

必须展示：

- 服务商；
- 官方、第三方、自建或自定义接入类别；
- 模型；
- 身份和能力验证状态；
- 任务用途；
- 原始输入、系统补充和最终提示词；
- 上下文；
- 图片、视频、蒙版、脚本及各自用途；
- 参数；
- 批量数量；
- 费用状态和计费方；
- 数据离开本机；
- 可能跨境或处理地区未知；
- 同服务商重试次数和费用范围；
- 返回修改入口。

以下变化使原确认失效：

- 服务商变化；
- 官方接口和第三方接口变化；
- 模型变化且能力、费用或数据范围变化；
- 新增素材或上下文；
- 批量数量增加；
- 参数升级导致费用变化；
- 跨境状态变化；
- 重试超出授权范围。

## 14. 流程十一：任务中心与任务详情

### 14.1 任务进入中心后的阶段

```text
草稿
→ 等待确认
→ 等待提交
→ 上传中
→ 提交中/排队中
→ 生成中
→ 结果处理中
→ 下载中
→ 已完成
```

可能终态或处理状态：

- 部分完成；
- 已失败；
- 已取消；
- 可重试；
- 已过期；
- 需要用户处理。

### 14.2 任务详情最低信息

- 任务类型；
- 所属项目；
- 创建和更新时间；
- 服务商、接入渠道和模型；
- 当前统一状态；
- 最近可信阶段；
- 已等待时间和最近查询时间；
- 输入与提示词快照；
- 素材范围；
- 费用信息状态；
- 收费结论及依据；
- 结果数量；
- 错误阶段；
- 当前可执行动作；
- 来源任务、重试和派生关系。

### 14.3 取消流程

```text
用户点击取消
→ 判断是否尚未提交
├─ 尚未提交：直接已取消
└─ 已提交
   ├─ 服务商支持且确认取消：已取消
   ├─ 已请求但未确认：保留最近可信状态
   ├─ 不支持取消：说明可能继续和可能收费
   └─ 最终仍生成：进入结果处理并说明取消未生效
```

不得把“停止本地等待”显示为“远端已取消”。

### 14.4 重试流程

```text
用户选择重试
→ 判断原任务是否仍在处理或状态未知
├─ 是：先恢复查询，不直接重提
└─ 否
   → 展示是否新请求、是否可能再次收费
   → 保持或修改模型、参数、素材
   → 接收方或费用变化时重新确认
   → 创建新执行记录
```

## 15. 流程十二：应用退出和任务恢复

```text
应用关闭或异常退出
→ 本地保留项目、草稿、任务和最近可信状态
→ 下次启动先恢复本地记录
→ 对未结束任务恢复查询
├─ 仍在运行：恢复真实状态
├─ 已完成：进入结果处理与下载
├─ 已失败/取消：映射真实终态
├─ 需要授权/空间/权限：需要用户处理
├─ 已过期：已过期
└─ 暂时无法查询：保留最后可信状态
```

禁止：

- 因重启重新提交；
- 因查询失败显示已失败；
- 因远端完成直接显示作品完成；
- 因恢复失败删除历史任务。

---

## 16. 流程十三：批量任务

```text
建立批次
→ 设置共享内容
→ 逐项编辑差异
→ 检查每个子任务模型能力
→ 展示任务数量、素材范围和总费用边界
→ 批量授权
→ 创建独立子任务
→ 汇总追踪
→ 单项处理
→ 批量保存或整理
```

批量任务必须支持：

- 批次总览；
- 子任务独立状态；
- 独立费用和错误；
- 单项取消；
- 只重试失败或可重试项；
- 部分完成；
- 部分上传、生成、下载和保存失败；
- 不重复提交已成功任务。

跨服务商批量提交必须按接收方分别确认。

---

## 17. 流程十四：作品库与继续创作

```text
任务结果成功保存本地
→ 创建作品记录
→ 进入作品库
→ 用户查看预览和追溯信息
→ 选择后续动作
   ├─ 导出
   ├─ 重命名或收藏
   ├─ 再次生成
   ├─ 图片编辑
   ├─ 图片转视频
   ├─ 基础视频编辑
   ├─ 移动项目
   └─ 删除
```

### 17.1 作品详情信息

- 所属项目；
- 来源任务；
- 创作类型；
- 本地文件状态；
- 提示词三层快照；
- 实际服务商和模型；
- 实际可确认参数；
- 参考素材和用途；
- 父子版本；
- 同批并列结果；
- 重试或继续创作关系。

### 17.2 文件异常流程

```text
打开/预览/导出/继续创作时发现文件异常
→ 保留作品记录
→ 区分文件丢失、损坏、无权限或外置盘断开
→ 用户选择
   ├─ 重新定位文件
   ├─ 恢复磁盘或权限
   ├─ 在结果未过期时重新下载
   └─ 移除失效记录
```

不得凭同名文件自动替换，也不得删除来源历史。

## 18. 页面跳转与返回规则

### 18.1 从项目进入任务

- 打开任务中心并自动应用当前项目筛选；
- 返回时恢复项目原位置和草稿；
- 任务详情中的“返回项目”定位到来源工作台。

### 18.2 从项目进入作品

- 打开作品库并应用当前项目筛选；
- 作品详情可返回来源任务；
- “继续创作”回到当前项目相应工作台并建立新草稿。

### 18.3 从任务进入作品

只有完成本地保存后才显示“打开作品”。

### 18.4 从作品继续创作

系统只带入用户确认的作品和必要来源信息，不自动携带全部项目上下文或历史素材。

### 18.5 返回修改

用户从提示词或发送确认返回工作台时：

- 保留草稿；
- 不创建任务；
- 清楚标记本次确认已失效或需要重新确认的部分。

## 19. 核心页面状态最低覆盖

每个首批页面必须至少覆盖：

1. 正常；
2. 空白；
3. 本地读取中；
4. 校验中；
5. 在线请求中；
6. 失败；
7. 需要授权；
8. 需要用户处理；
9. 断网；
10. 应用恢复；
11. 本地文件异常；
12. 批量部分完成；
13. 禁用和只读；
14. 无可用模型；
15. 费用未知；
16. 服务商身份或处理地区未知。

具体视觉状态在《组件与交互状态规范》中冻结。

## 20. 流程验收标准

核心流程通过评审至少满足：

- 从项目开始，以本地作品结束；
- 不把增强结果当生成任务；
- 不把远端成功当本地作品完成；
- 不隐藏服务商、模型、发送内容和费用状态；
- 长文本先形成可编辑镜头草稿；
- 图片识别结果体现不确定性；
- 图片编辑不覆盖原图；
- 批量任务能下钻到子任务；
- 取消不伪造远端成功取消；
- 上游状态未知时不盲目重提；
- 重试保留原任务事实；
- 跨服务商发送每次重新确认；
- 文件丢失后仍保留作品历史；
- 页面切换和应用重启不无故丢失草稿与任务。

## 21. 本阶段建议冻结的设计决策

建议产品负责人确认：

1. 本文十四条核心任务流作为低保真交互设计依据；
2. 提示词确认和外发确认是两个独立审查层，不能合并成一个简单弹窗；
3. 长文本视频创作必须先进入镜头草稿，不直接提交；
4. 任务详情必须同时展示状态事实、费用事实和恢复动作；
5. 任务中心和作品库分别承担过程与结果，不建立重复页面；
6. 作品详情保留完整来源和版本关系；
7. 批量任务以批次加独立子任务组织；
8. 所有跨服务商行为在实际发送前重新确认；
9. 应用重启只恢复原任务，不自动新建任务。

确认后，本文升级为 V1.0.0“已冻结”，进入第三阶段《桌面应用整体框架与页面布局》。
