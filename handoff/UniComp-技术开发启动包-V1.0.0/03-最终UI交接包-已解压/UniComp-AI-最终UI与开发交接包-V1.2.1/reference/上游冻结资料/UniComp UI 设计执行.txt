## 关于“已冻结方案可修改”的执行规则

你已经明确授权：

> 如果在高保真页面设计阶段发现业务流程不通、不合理，允许修改已冻结方案。

我会按以下规则执行，避免混乱：

### 允许修改的前提
只有在以下情况出现时，我才会动已冻结方案：

1. 页面业务链路走不通；
2. 交互顺序明显不合理；
3. 关键操作路径过长或冲突；
4. 已冻结结构无法承载真实页面任务；
5. 状态切换会导致用户误解、漏操作或高风险误操作；
6. 页面说明附图无法自洽，说明现有冻结方案存在结构性问题。

### 修改原则
如果需要改，我不会“悄悄改”，而会按下面方式执行：

- 明确指出发现的问题；
- 说明为什么原冻结方案不适合；
- 给出修正后的结构或交互；
- 标记为：**高保真阶段设计纠偏修订**
- 同步更新执行总表、对应页面文档和后续设计依据

也就是说：

> **冻结不是僵死不动，而是在你授权前提下允许“为保证产品可用性而纠偏”。**

这个规则我会严格遵守。
