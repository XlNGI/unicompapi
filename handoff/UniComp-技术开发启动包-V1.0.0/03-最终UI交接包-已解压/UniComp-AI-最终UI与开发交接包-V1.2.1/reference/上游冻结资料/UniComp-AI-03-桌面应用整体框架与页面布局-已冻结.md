## 1. 文档目的

本文确定 UniComp AI V1.0 的桌面应用整体框架和页面布局，用于回答：

- Windows 与 macOS 共用什么应用外壳；
- 一级导航、项目内导航和页面操作分别出现在哪里；
- 图片、视频、任务、作品、模型和设置如何共享同一布局语言；
- 哪些页面使用左侧上下文面板、中央内容舞台和右侧检查器；
- 提示词审查和外发确认如何在不丢失草稿的情况下完成；
- 运行中任务如何在所有页面持续可见；
- 窗口变窄、系统缩放提高或面板折叠时，主操作如何保持可用；
- 全屏预览、版本对比和错误详情如何进入和退出。

本文冻结的是**桌面结构与布局规则**，不冻结最终品牌色、字体、圆角、阴影、图标风格和高保真视觉细节。上述视觉内容在第四、第五阶段确定。

本文不改变已冻结产品功能，不增加账号、会员、云端工作区或聊天主线，也不让 Codex 开始正式业务页面开发。

## 2. 桌面框架设计原则

### 2.1 内容舞台优先

图片、视频、识别画面、任务证据和作品预览必须占据页面最大视觉区域。

辅助面板只能承担：

- 素材和上下文选择；
- 输入和参数配置；
- 状态、来源和元数据检查；
- 当前任务相关操作。

不得用大面积装饰卡片、统计模块或技术日志挤压内容舞台。

### 2.2 一个应用外壳，多种工作区组合

全应用采用统一外壳，但不强制每个页面同时出现三栏。

页面根据任务选择以下区域组合：

- 仅中央内容区；
- 左侧上下文面板 + 中央内容区；
- 中央内容区 + 右侧检查器；
- 左侧上下文面板 + 中央内容区 + 右侧检查器；
- 列表 + 详情检查区；
- 聚焦审查层；
- 全屏预览层。

### 2.3 中央区域优先于两侧面板

窗口宽度不足时，收缩顺序固定为：

1. 缩减页面级留白；
2. 收窄左侧上下文面板；
3. 将左侧上下文面板折叠为抽屉；
4. 将右侧检查器折叠为抽屉；
5. 将全局导航收为紧凑形态；
6. 将次要操作收入“更多”；
7. 保留中央内容、当前状态和唯一主操作。

不得先缩小内容预览到不可用，也不得隐藏生成前确认、保存状态或需要用户处理的任务。

### 2.4 主操作跟随当前任务

每个页面只保留一个最明确的主操作。

例如：

- 项目中心：新建项目；
- 图片工作台：审查并提交；
- 提示词审查：继续检查发送内容；
- 外发确认：确认并创建任务；
- 任务详情：处理当前阻断问题；
- 作品详情：继续创作。

主操作固定在当前工作区或检查器底部，不放在远离当前内容的全局区域。

### 2.5 本地事实和远端事实同时可见

桌面框架必须为以下事实保留稳定位置：

- 当前项目；
- 草稿是否已本地保存；
- 当前服务商和模型；
- 数据是否将离开本机；
- 当前任务状态；
- 结果是否完成本地保存；
- 是否需要用户处理。

### 2.6 渐进披露

默认展示高频内容：

- 输入；
- 选中素材；
- 模型；
- 基础参数；
- 当前状态；
- 主操作。

高级参数、技术证据、完整请求摘要、错误码、文件路径和能力来源按需展开，不常驻占据主界面。

## 3. 应用外壳总体结构

### 3.1 标准结构

UniComp AI 采用以下统一桌面外壳：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ A. 系统窗口栏 / 应用标题栏                                               │
├──────────────────────────────────────────────────────────────────────────┤
│ B. 工作区上下文栏                                                        │
├────────┬──────────────┬──────────────────────────┬──────────────────────┤
│        │              │                          │                      │
│ C.     │ D.           │ E.                       │ F.                   │
│ 全局   │ 上下文面板   │ 中央内容舞台             │ 检查器               │
│ 导航   │ 可选         │ 页面最高优先级           │ 可选                 │
│        │              │                          │                      │
├────────┴──────────────┴──────────────────────────┴──────────────────────┤
│ G. 全局任务活动条：折叠 / 展开                                           │
└──────────────────────────────────────────────────────────────────────────┘

覆盖层：H. 抽屉、聚焦审查层、全屏预览、确认与错误详情
```

### 3.2 区域职责

| 区域 | 固定性 | 核心职责 | 不承担 |
| --- | --- | --- | --- |
| A. 系统窗口栏 | 常驻 | 平台窗口控制、安全拖拽区、应用名称、全局命令入口 | 项目内复杂操作 |
| B. 工作区上下文栏 | 常驻 | 当前项目、页面标题、项目内模式、面包屑、页面级操作 | 长参数表单 |
| C. 全局导航 | 常驻 | 项目、任务、作品、模型、设置 | 项目内图片/视频模式 |
| D. 上下文面板 | 按页出现 | 素材、上下文、筛选、任务列表、模型分类等 | 主要结果预览 |
| E. 中央内容舞台 | 常驻 | 画布、预览、项目内容、任务详情、作品网格 | 大量全局设置 |
| F. 检查器 | 按页出现 | 输入、参数、结果结构、状态详情、元数据和操作 | 全局导航 |
| G. 任务活动条 | 常驻折叠 | 运行数量、需处理数量、最近状态和快速进入任务 | 完整任务管理 |
| H. 覆盖层 | 临时 | 抽屉、审查、全屏、危险确认和证据详情 | 长期页面导航 |

## 4. 系统窗口栏与工作区上下文栏

### 4.1 系统窗口栏

建议结构高度基准为 **40—44 逻辑像素**，最终像素在 Design System 阶段校准。

必须包含：

- Windows/macOS 窗口控制安全区；
- 可拖动窗口区域；
- 应用名称或简化品牌标识；
- 全局命令入口预留；
- 诊断、更新等低频全局操作的“更多”入口预留。

不得包含：

- 完整项目导航；
- 提示词编辑器；
- 模型参数；
- 账号头像或强制登录入口；
- 大量状态徽标。

### 4.2 工作区上下文栏

建议结构高度基准为 **48—52 逻辑像素**。

根据页面显示：

- 当前页面名称；
- 当前项目切换器；
- 项目内“概览 / 图片 / 视频 / 素材与上下文”；
- 图片或视频的二级模式；
- 返回来源页；
- 页面级搜索、筛选、视图切换和次要操作；
- 当前草稿本地保存状态。

### 4.3 项目切换器位置

项目切换器固定放在**工作区上下文栏左侧**，仅在进入项目后出现。

显示最低信息：

- 项目名称；
- 本地可用状态；
- 未保存或恢复状态；
- 展开入口。

展开后可：

- 切换最近项目；
- 返回项目中心；
- 新建项目；
- 打开本地项目。

项目切换器不放在全局导航内，也不使用账号工作区样式。

### 4.4 项目内导航位置

项目内四个稳定区域：

- 概览；
- 图片；
- 视频；
- 素材与上下文；

固定放在工作区上下文栏中，使用清晰的平级切换，不再增加永久第二导航栏。

进入“图片”或“视频”后，其二级模式优先使用同栏中的分段切换或紧邻内容区的模式栏：

- 图片：生成、识别、编辑、转提示词、多图参考、批量；
- 视频：文生视频、图生视频、批量、基础编辑。

窗口较窄时，低频模式进入展开菜单，但当前模式必须持续可见。

## 5. 全局导航

### 5.1 导航形态

采用左侧垂直导航轨道，标准宽度基准为 **72 逻辑像素**，紧凑状态为 **56 逻辑像素**。

固定顺序：

1. 项目；
2. 任务；
3. 作品；
4. 模型；
5. 设置。

标准状态显示图标与两字中文标签；紧凑状态显示图标并通过工具提示和焦点说明补足名称。

### 5.2 导航状态

每项至少需要：

- 默认；
- 悬停；
- 键盘焦点；
- 当前选中；
- 需要处理徽标；
- 暂不可用；
- 高对比模式。

“任务”可显示需要用户处理的数量；不得显示没有真实依据的百分比。

### 5.3 全局导航保持规则

- 进入项目、任务、作品、模型和设置时全局导航保持；
- 提示词审查和外发确认时保持全局导航，但弱化非当前操作；
- 全屏预览时可以临时隐藏；
- 危险确认打开时导航不可触发，避免丢失上下文；
- 当前草稿未提交时切换全局页面，只保存本地草稿，不自动提交。

## 6. 面板系统

### 6.1 面板类型

UniComp 使用三类可复用面板：

1. **上下文面板：** 素材、上下文、筛选、任务列表、模型分类；
2. **检查器：** 输入、参数、识别结果、状态、元数据、文件信息；
3. **活动面板：** 全局任务快速列表和需要处理项。

### 6.2 结构尺寸基准

以下为第三阶段布局基准，不是最终视觉令牌：

| 区域 | 默认宽度/高度 | 最小值 | 最大值 | 行为 |
| --- | ---: | ---: | ---: | --- |
| 全局导航 | 72px 宽 | 56px | 72px | 紧凑时只显示图标 |
| 上下文面板 | 264px 宽 | 220px | 360px | 可拖动、折叠或转抽屉 |
| 检查器 | 344px 宽 | 300px | 440px | 可拖动、折叠或转抽屉 |
| 中央内容舞台 | 自适应 | 560px | 不限 | 优先获得剩余空间 |
| 任务活动条 | 36px 高 | 36px | 展开约 260px | 展开不覆盖关键主操作 |
| 系统窗口栏 | 40—44px 高 | 待校准 | 待校准 | 受平台控制区影响 |
| 工作区上下文栏 | 48—52px 高 | 待校准 | 待校准 | 页面和项目上下文 |

### 6.3 拖动与折叠

- 上下文面板和检查器支持拖动调整宽度；
- 调整时显示中央内容剩余空间；
- 达到最小宽度后继续拖动可折叠；
- 折叠后保留明确恢复按钮；
- 双击分隔线恢复默认宽度；
- 宽度偏好按“页面类型”保存，不在所有页面强制共用；
- 不同项目可共享布局偏好，但草稿内容不共享。

### 6.4 自动折叠优先级

当中央内容宽度不足 560px 时：

1. 先将上下文面板折叠；
2. 再将检查器转为覆盖式抽屉；
3. 两个抽屉不能同时占据中央区域；
4. 当前打开抽屉关闭后，焦点返回原触发控件。

### 6.5 检查器底部操作区

需要提交、保存或处理异常的页面，在检查器底部使用固定操作区。

固定操作区必须：

- 显示唯一主操作；
- 显示阻断原因；
- 防止连续点击重复提交；
- 在内容滚动时保持可见；
- 不遮挡错误提示和费用状态。

## 7. 窗口尺寸、缩放与响应规则

### 7.1 尺寸基线

- 推荐设计验收窗口：**1440 × 900 逻辑像素**；
- 常规生产窗口：**1200 × 720 及以上**；
- 最小完整工作窗口：**1024 × 680 逻辑像素**；
- 允许的保护性最小窗口：**960 × 640 逻辑像素**。

“保护性最小窗口”仍能完成核心操作，但上下文和检查器会改为抽屉，不作为长时间创作的推荐尺寸。

### 7.2 宽度级别

| 逻辑宽度 | 布局模式 | 面板规则 |
| --- | --- | --- |
| ≥ 1440 | 宽布局 | 全局导航、上下文面板、中央舞台、检查器可同时显示 |
| 1200—1439 | 标准布局 | 两侧面板可同时显示；优先收窄面板，保证中央舞台 |
| 1024—1199 | 紧凑布局 | 上下文面板默认折叠；检查器保持或转抽屉 |
| 960—1023 | 保护布局 | 全局导航紧凑；两侧均为互斥抽屉；次要操作收入更多 |

### 7.3 高度级别

高度不足时：

- 顶部两层结构不合并成无法识别的单层；
- 检查器和列表内部滚动；
- 主操作固定在底部；
- 任务活动条保持折叠；
- 中央预览允许缩放适配；
- 不能通过缩小正文和控件字体换取空间。

### 7.4 系统缩放

在 125%、150%、175% 和 200% 系统缩放下：

- 布局按有效逻辑尺寸进入对应级别；
- 文本不截断关键状态；
- 标签可换行或进入工具提示；
- 面板可转抽屉；
- 主操作和返回入口持续可见；
- 不依赖鼠标悬停才能理解关键事实。

### 7.5 超窄保护

应用不鼓励低于 960 × 640 的工作区。

若平台允许继续缩小：

- 保留中央当前任务和主操作；
- 显示“窗口较窄，部分面板已收起”的非阻断提示；
- 通过抽屉访问素材、参数和详情；
- 不清空草稿，不强制退出当前任务。

## 8. 项目中心布局

### 8.1 页面目标

用户打开应用后立即知道：

- 最近在做什么；
- 哪个草稿可以继续；
- 哪个任务需要处理；
- 哪个作品刚刚完成；
- 如何新建或打开本地项目。

### 8.2 标准布局

```text
┌ 全局导航 ┬────────────────────────────────────────────────────────────┐
│          │ 项目                                           新建项目   │
│          ├────────────────────────────────────────────────────────────┤
│          │ 继续创作                                                   │
│          │ [最近草稿] [需要处理任务] [最近完成作品]                   │
│          ├────────────────────────────────────────────────────────────┤
│          │ 本地项目                         搜索  筛选  网格/列表      │
│          │ [项目卡] [项目卡] [项目卡] ...                              │
│          │                                                            │
└──────────┴────────────────────────────────────────────────────────────┘
```

### 8.3 布局规则

- 项目中心默认不显示右侧检查器；
- 不使用 KPI、趋势图和经营看板；
- “继续创作”展示真实内容卡，不显示抽象数字；
- 项目卡以最近作品或用户封面作为视觉主体；
- 项目路径异常直接在项目卡上显示并提供修复入口；
- 选中项目后可在轻量预览层查看详情，不强制进入管理页面；
- 无项目时使用单一明确的新建/打开路径。

## 9. 项目概览布局

### 9.1 标准布局

项目概览采用中央内容区，不默认显示两侧面板：

```text
项目切换器 | 概览 | 图片 | 视频 | 素材与上下文
──────────────────────────────────────────────
项目目标与本地状态
继续创作：最近草稿 / 需要处理任务
最近作品
最近素材
```

### 9.2 规则

- 页面重点是“继续做什么”，不是汇总数据；
- 任务与作品只显示摘要，完整事实分别进入任务中心和作品库；
- 需要用户处理的任务优先于最近完成作品；
- 项目路径、外置盘和恢复状态在页面顶部持续可见；
- 快速进入图片或视频创作时创建本地草稿，不创建远端任务。

## 10. 图片创作工作台布局

### 10.1 通用框架

```text
项目切换器 | 图片 | 生成 / 识别 / 编辑 / 转提示词 / 多图参考 / 批量
──────────────────────────────────────────────────────────────────────
┌──────────────┬──────────────────────────────┬──────────────────────┐
│ 素材与上下文 │ 中央图片舞台                 │ 创作检查器           │
│              │                              │ 输入 / 模型 / 参数   │
│ 选中素材     │ 空画布 / 结果 / 对比 / 版本  │ 能力与费用状态       │
│ 发送范围     │                              │                      │
│              │                              │ [审查并提交]         │
└──────────────┴──────────────────────────────┴──────────────────────┘
```

### 10.2 左侧上下文面板

包含：

- 当前项目素材；
- 项目作品复用；
- 人物、品牌、商品、场景和风格上下文；
- 当前已选内容；
- 每张图片用途；
- 是否会外发；
- 素材校验状态。

不在左侧面板堆放模型参数。

### 10.3 中央图片舞台

根据阶段显示：

- 空白引导；
- 原图；
- 参考图关系；
- 生成结果网格；
- 单张大图预览；
- 原图与新版本对比；
- 多结果并列比较；
- 本地保存中和文件异常；
- 全屏预览入口。

中央舞台顶部可有轻量工具栏：

- 缩放；
- 适应窗口；
- 对比方式；
- 版本切换；
- 预览背景；
- 全屏。

### 10.4 右侧创作检查器

按顺序组织：

1. 原始输入；
2. 提示词模式和增强状态；
3. 当前模型与能力状态；
4. 基础参数；
5. 高级参数折叠区；
6. 费用状态和发送前提示；
7. 阻断问题；
8. 主操作“审查并提交”。

模型名称、参数枚举、限制和费用全部来自动态能力声明。

### 10.5 图片识别布局差异

图片识别采用：

- 左侧：待识别图片与识别目的；
- 中央：当前图片大图、区域选择和多图切换；
- 右侧：结构化识别结果编辑器。

结果编辑器固定区分：

- 可见事实；
- 模型推断；
- 不确定；
- 无法识别；
- 用户修改。

### 10.6 图片编辑布局差异

- 中央舞台显示原图、新版本和蒙版；
- 左侧面板管理源图、参考图和保留要求；
- 右侧检查器管理修改要求和模型参数；
- “保存”永远创建新版本，不覆盖原图；
- 对比和回退不进入独立页面。

### 10.7 图片转提示词布局差异

- 中央展示图片和当前识别区域；
- 右侧展示结构化提示词草稿；
- 草稿可编辑后转入图片或视频工作台；
- “转入创作”只建立新草稿，不自动提交任务。

### 10.8 多图参考布局差异

左侧面板必须为每张图片显示：

- 缩略图；
- 用途；
- 顺序或权重；
- 是否发送；
- 校验和限制状态。

中央舞台显示多图关系概览，不将多图简单堆叠为附件列表。

### 10.9 批量图片布局差异

采用：

- 左侧批次列表；
- 中央子任务表格或卡片编辑区；
- 右侧共享设置和批次检查器。

共享设置与逐条差异必须分开。批量数量不是普通单任务参数。

## 11. 视频创作工作台布局

### 11.1 通用框架

```text
项目切换器 | 视频 | 文生视频 / 图生视频 / 批量 / 基础编辑
──────────────────────────────────────────────────────────────────────
┌──────────────┬──────────────────────────────┬──────────────────────┐
│ 镜头/素材区  │ 视频舞台 / 故事板            │ 创作检查器           │
│              │                              │ 输入 / 运动 / 模型   │
│ 镜头草稿     │ 当前镜头预览                 │ 参数 / 费用状态      │
│ 参考图用途   │ 结果播放与版本               │                      │
│              │                              │ [审查并提交]         │
└──────────────┴──────────────────────────────┴──────────────────────┘
```

### 11.2 文生视频

短文本模式：

- 左侧可折叠，仅显示结构和素材；
- 中央以视频预览和结果为主；
- 右侧完成输入、镜头、动作和参数。

长文本、故事、脚本和营销文案模式：

- 左侧固定为镜头草稿列表；
- 中央显示当前镜头详细编辑和故事板；
- 右侧显示当前镜头提示词、模型和参数；
- 支持合并、删除、排序和逐条确认；
- 未确认镜头不得自动创建任务。

### 11.3 图生视频

- 左侧显示参考图、图片用途和图片理解结果；
- 中央显示源图、运动预览区域和生成结果；
- 右侧显示主体动作、镜头运动、节奏、约束和动态参数；
- 图片理解结果可编辑，不能隐藏在后台。

### 11.4 视频任务状态

视频生成后，工作台不显示虚假百分比。

中央舞台显示：

- 上传中；
- 排队中；
- 生成中；
- 结果处理中；
- 下载中；
- 已等待时间；
- 最近查询时间；
- 可执行动作。

完整状态事实仍由任务中心管理。

### 11.5 基础视频编辑

基础编辑采用中央时间线和预览结构，但必须保持轻量：

- 中央上部：视频预览；
- 中央下部：单层或有限轨道时间线；
- 左侧：来源片段和素材；
- 右侧：裁剪、顺序、简单转场、画面和导出设置；
- 不模拟专业非线性剪辑软件的复杂轨道、节点和效果面板。

## 12. 提示词增强与最终确认布局

### 12.1 界面形态

提示词确认采用**工作区内聚焦审查层**，不是小弹窗，也不是独立一级页面。

进入后：

- 保留全局导航和当前项目上下文；
- 暂时隐藏素材面板和普通参数检查器；
- 中央区域用于三层内容审查；
- 返回后恢复原工作台位置和面板状态。

### 12.2 标准布局

```text
提示词审查                                             草稿已本地保存
──────────────────────────────────────────────────────────────────────
┌────────────────────┬────────────────────┬──────────────────────────┐
│ 用户原始输入       │ 系统补充内容       │ 最终提交提示词           │
│ 只读基线/可复制    │ 来源、类别、开关   │ 可编辑、可复制、可恢复   │
│                    │ 可修改、可移除     │                          │
└────────────────────┴────────────────────┴──────────────────────────┘
返回修改                         恢复原始输入      继续检查发送内容
```

### 12.3 结构规则

- 三层必须在同一审查上下文中可见；
- 系统补充逐项显示来源和类别；
- 翻译和模型格式转换属于系统补充；
- 用户修改最终提示词后标记为“用户已修改”；
- 支持查看变更摘要，不要求用户阅读技术 Diff；
- 在线增强若由独立服务商完成，清楚显示接收方和费用状态；
- 增强完成不显示为“任务已创建”。

### 12.4 紧凑布局

窗口较窄时：

- 三栏转为分段查看；
- 顶部持续显示“原始 / 补充 / 最终”状态；
- 最终提示词和继续按钮保持可达；
- 不将系统补充隐藏为不可查看的摘要。

## 13. 外发与费用确认布局

### 13.1 界面形态

外发确认采用第二个独立的**阻断式聚焦审查层**。

不得与提示词审查合并成一个普通弹窗。

### 13.2 标准布局

```text
发送与费用确认
──────────────────────────────────────────────────────────────────────
┌────────────────────────────────┬────────────────────────────────────┐
│ 将发送的内容                   │ 接收方与授权                       │
│ 原始输入                       │ 服务商 / 接入渠道 / 模型          │
│ 系统补充                       │ 验证状态                           │
│ 最终提示词                     │ 数据离开本机                       │
│ 图片 / 视频 / 蒙版 / 上下文    │ 跨境或处理地区未知                 │
│ 参数 / 批量子任务              │ 费用状态 / 账单说明                │
│                                │ 自动重试范围                       │
└────────────────────────────────┴────────────────────────────────────┘
返回修改                                              确认并创建任务
```

### 13.3 规则

- 左侧回答“发送什么”；
- 右侧回答“发送给谁、可能花多少钱、授权到什么范围”；
- 服务商、素材范围、参数、费用或处理地区变化后，原确认失效；
- 跨服务商切换必须重新进入本层；
- 费用未知时不得弱化或隐藏；
- 批量任务需要显示批次和子任务范围；
- 主按钮文案使用“确认并创建任务”，不使用模糊的“继续”；
- 返回修改不丢失草稿，也不创建任务。

### 14.1 宽布局

│          │ 筛选       │ 任务列表         │ 任务详情               │

### 14.2 标准与紧凑布局

- 标准布局保留筛选和任务列表，详情在右侧抽屉；
- 紧凑布局先显示任务列表，选择任务后进入详情层；
- 返回列表时保留筛选、滚动位置和选中任务；
- 批次展开后可进入单个子任务。

### 14.3 任务列表最低信息

- 任务类型；
- 来源项目；
- 创建时间；
- 服务商和模型；
- 当前真实阶段；
- 结果数量；
- 费用状态；
- 需要用户处理标记。

### 14.4 任务详情结构

1. 当前结论；
2. 状态时间线；
3. 服务商与模型；
4. 费用和授权事实；
5. 上传、生成、下载和本地保存阶段；
6. 已完成内容；
7. 未完成或无法确认内容；
8. 当前可执行动作；
9. 技术证据折叠区；
10. 来源项目与结果作品。

取消状态必须区分本地停止等待、远端取消请求、远端确认和无法确认。

### 15.2 页面规则

- 图片与视频统一浏览，类型筛选清楚；
- 作品卡以真实缩略图为主体；
- 文件丢失、损坏和外置盘断开直接覆盖在对应作品上；

作品详情支持：

- 父版本；
- 子版本；
- 同源并列版本；
- 来源任务；
- 原始素材。

版本关系优先使用可理解的缩略图链路，不使用复杂工程图。

## 16. 模型与服务商页面布局

### 16.1 结构

```text
┌ 全局导航 ┬────────────────┬────────────────────────┬───────────────┐
│          │ 服务商分类     │ 服务商与模型列表       │ 配置检查器    │
│          │ 在线 / 本机    │ 能力状态、验证时间     │ Key / 地址    │
│          │ 局域网 / 自定义│ 限制和可用状态         │ 测试与风险    │
└──────────┴────────────────┴────────────────────────┴───────────────┘
```

### 16.2 规则

- 服务商、模型和能力三层清楚区分；
- 国内在线、海外在线、本机、局域网和自定义接口使用同一页面结构，但风险提示不同；
- Key 常态只显示掩码和状态；
- 连接测试成功不得显示为“所有能力已验证”；
- 自定义接口显示真实地址类别和身份核验状态；
- 模型能力详情采用结构化列表，不以营销名称替代事实；
- 页面不模拟 API 调试工具，不展示原始 JSON 作为主界面。

## 17. 设置页面布局

设置采用：

- 左侧设置分类；
- 中央设置内容；
- 不默认显示右侧检查器。

分类至少预留：

- 存储；
- 备份与迁移；
- 代理与网络；
- 安全与隐私；
- 外观；
- 通知；
- 诊断；
- 关于。

规则：

- 危险操作放在对应设置项内，不集中制造“危险区”；
- 本地目录变化提供影响说明和恢复路径；
- 迁移项目时明确 API Key 默认不迁移；
- 系统原生权限和文件选择器遵循平台习惯；
- 未验证的系统目录、最低系统版本和沙盒行为不写死。

## 18. 全局任务活动条

### 18.1 定位

全局任务活动条是所有页面共享的轻量状态入口，不是第二个任务中心。

折叠状态显示：

- 运行中任务数量；
- 需要用户处理数量；
- 最近完成或失败摘要；
- 打开任务快速视图的入口。

示例结构：

```text
3 个任务运行中 · 1 个需要处理                         查看任务
```

### 18.2 展开状态

展开后显示最近任务快速列表：

- 任务名称和类型；
- 真实阶段；
- 已等待时间；
- 最近查询时间；
- 当前可执行动作；
- 进入完整任务中心。

不得显示虚假百分比，也不得在快速面板内复制完整任务详情。

### 18.3 页面关系

- 展开活动条不覆盖检查器固定主操作；
- 在保护布局中改为底部覆盖抽屉；
- 打开完整任务中心时保留来源页面和草稿；
- 任务完成本地保存后，活动条可以显示“打开作品”。

## 19. 全屏预览与聚焦模式

### 19.1 全屏预览

用于：

- 图片大图；
- 多版本比较；
- 视频播放；
- 图片识别区域检查；
- 作品预览。

进入后：

- 临时隐藏全局导航、上下文面板和检查器；
- 保留退出、版本切换、缩放和必要播放控制；
- 不改变当前选中内容和草稿；
- 退出后恢复原页面滚动和焦点位置。

### 19.2 创作聚焦模式

创作聚焦模式与全屏预览不同：

- 保留工作区上下文栏；
- 隐藏全局导航和非必要面板；
- 中央舞台和当前检查器扩大；
- 适合长时间编辑当前提示词、镜头或结果；
- 不隐去服务商、费用状态和本地保存状态。

### 19.3 模态框使用边界

模态框只用于：

- 短小、明确的危险确认；
- 文件删除边界；
- 覆盖风险；
- 无法继续前必须处理的单一问题。

提示词审查、外发确认、复杂任务恢复和模型配置不得塞进小模态框。

## 20. 页面状态在框架中的位置

### 20.1 页面级状态

适用于：

- 无项目；
- 无任务；
- 无作品；
- 项目数据损坏；
- 当前页面无法读取。

显示在中央内容舞台，不覆盖全局导航。

### 20.2 面板级状态

适用于：

- 素材校验中；
- 无上下文；
- 参数同步失败；
- 模型不可用；
- 识别结果为空。

显示在对应面板内部，不阻断其他区域。

### 20.3 内联字段状态

适用于：

- 参数不支持；
- 文件格式错误；
- Key 无效；
- 费用未知；
- 上限未知；
- 当前授权失效。

错误靠近触发字段，并在主操作区汇总阻断原因。

### 20.4 全局状态

适用于：

- 应用离线；
- 项目恢复中；
- 存储目录不可用；
- 代理或证书异常；
- 多个任务需要处理。

使用工作区上下文栏下方的非遮挡状态条，必要时联动任务活动条。

## 21. Windows 与 macOS 统一和差异

### 21.1 必须统一

- 一级导航顺序；
- 项目内导航；
- 页面命名；
- 面板职责；
- 任务状态；
- 提示词三层；
- 外发与费用确认；
- 作品和文件边界；
- 主操作位置；
- 响应与折叠规则。

### 21.2 允许差异

- macOS 窗口控制位于左侧，Windows 位于右侧；
- 系统窗口栏为两侧控制区预留不同安全范围；
- 快捷键显示使用 Command 或 Ctrl；
- 系统文件选择器、权限提示、通知和菜单遵循平台习惯；
- 标题栏拖拽和全屏行为遵循平台规范。

### 21.3 不得提前写死

- 最低系统版本；
- 固定沙盒目录；
- 精确系统权限弹窗；
- Windows/macOS 特定安全存储名称作为用户文案；
- 未通过原型验证的系统交互。

### 21.4 顶部安全区

- macOS 左侧窗口控制区域不可放项目切换和返回按钮；
- Windows 右侧窗口控制区域不可放全局操作；
- 两个平台的工作区上下文栏从安全区后开始对齐；
- 不为了像素完全一致破坏平台窗口习惯。

## 22. 键盘、焦点与无障碍布局要求

- 全局导航、项目切换、模式切换、上下文面板、中央舞台、检查器和任务活动条具有清晰焦点顺序；
- 抽屉打开后焦点进入抽屉，关闭后返回触发位置；
- 聚焦审查层打开后，背景工作台不接受误操作；
- 全屏预览退出后返回原选中作品或画布；
- 列表和网格支持键盘移动和选择；
- 拖动分隔线同时提供键盘调整方式；
- 颜色不是面板开关、状态和选中的唯一表达；
- 高缩放下保持控件命中区域，不缩小到只适合鼠标精确点击；
- 快捷键具体组合在实现说明阶段冻结，当前只保留能力和显示位置。

## 24. 明确禁止的布局方式

不得采用：

1. 以中央聊天消息流作为所有创作入口；
2. 一级导航同时出现首页、项目、图片、视频和创作等重叠概念；
3. 全应用永久五栏并排，导致内容区过窄；
4. 在项目中心使用 KPI 卡片、趋势图和后台数据看板；
5. 将提示词三层隐藏在“高级设置”中；
6. 将外发确认压缩成只有“同意”按钮的小弹窗；
7. 将模型管理设计成 JSON、HTTP 和状态码主导的调试器；
8. 在视频生成中使用无真实依据的进度百分比；
9. 在右侧面板塞入所有功能，形成无限滚动参数墙；
10. 页面切换时清空草稿或静默重新提交；
11. 用全屏模态层长期取代正常页面导航；
12. 复制某一现有图片软件、视频软件或模型服务商的整体布局。

## 26. 已确认并冻结的产品结论

产品负责人已确认并冻结以下第三阶段方案：

1. 采用“系统窗口栏 + 工作区上下文栏”的双层顶部结构；
2. 采用左侧垂直全局导航，固定为项目、任务、作品、模型、设置；
3. 项目切换器和项目内导航放在工作区上下文栏，不建立永久第二导航栏；
4. 页面采用可组合的“上下文面板 + 中央内容舞台 + 检查器”；
5. 图片和视频工作台默认使用左右辅助面板，中央内容拥有最高空间优先级；
6. 提示词审查与外发确认使用两个独立的工作区内聚焦审查层，不使用普通小弹窗；
7. 全应用保留底部可折叠任务活动条；
8. 宽度不足时两侧面板依次转为互斥抽屉，不缩小主内容和主操作；
9. 推荐验收尺寸为 1440 × 900，最小完整窗口为 1024 × 680，保护性最小窗口为 960 × 640；
10. Windows 与 macOS 共享结构，仅在窗口控制、安全区、快捷键和系统交互上遵循平台差异；
11. 本文已升级为 V1.0.0“已冻结”，下一阶段进入视觉方向探索。
