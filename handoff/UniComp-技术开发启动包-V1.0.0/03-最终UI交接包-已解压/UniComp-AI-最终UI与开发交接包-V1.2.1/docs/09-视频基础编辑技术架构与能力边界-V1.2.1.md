## 1. 文档目的

本文用于约束 Codex、桌面端、媒体处理、任务中心和测试团队对“视频基础编辑”的实现方式。

目标不是开发一个专业剪辑软件，而是交付一套：

- 本地优先；
- 非破坏式；
- 轻量单轨；
- Windows 与 macOS 可稳定运行；
- 可保存草稿、可恢复、可导出、可追溯；
- 不覆盖原始视频；

的视频基础编辑能力。

本文优先级低于产品负责人最新决策，高于通用技术习惯和 Codex 自主判断。

## 2. V1.0 产品能力边界

### 2.1 必须实现

#### 视频片段

- 导入一个或多个本地视频；
- 按顺序加入视频主轨；
- 裁剪片段首尾；
- 在播放头位置分割；
- 删除、恢复、复制和排序片段；
- 显示每个片段来源；
- 替换丢失源文件；
- 多片段顺序拼接；
- 不覆盖源文件。

#### 画面处理

- 画布比例；
- 适应画布；
- 填满画布；
- 缩放与位置；
- 裁切；
- 旋转；
- 水平或垂直翻转；
- 纯色或模糊原画背景；
- 当前处理引擎真实支持的其他基础变换。

#### 速度

- 整段统一变速；
- 单片段变速；
- 恢复原速度；
- 只展示本地引擎真实支持的范围。

#### 文字

- 添加多个基础文字层；
- 设置内容、开始时间、结束时间；
- 字体、字号、对齐、位置、透明度；
- 无动画、淡入、淡出、淡入并淡出；
- 字体不可用时明确提示并允许替换。

#### 声音

- 保留或静音原声；
- 调整原声音量；
- 添加一条背景音乐；
- 裁剪背景音乐；
- 背景音乐音量；
- 简单淡入和淡出；
- 不实现复杂多轨混音。

#### 封面

- 从视频选帧；
- 选择本地图片；
- 选择项目图片；
- 封面默认只影响作品展示；
- 只有用户主动选择时才把封面加入视频开场。

#### 草稿与导出

- 非破坏式编辑草稿；
- 自动保存编辑配置；
- 撤销与重做；
- 另存为、复制草稿；
- 本地导出任务；
- 导出进度、取消、失败和重试；
- 编码、文件写入和校验全部成功后才标记完成；
- 每次导出产生独立新文件和版本记录。

### 2.2 首版明确不实现

- 专业多轨视频；
- 画中画与多层视频合成；
- 复杂关键帧；
- 曲线变速与光流补帧；
- 自动字幕识别；
- 卡拉 OK 逐字字幕；
- AI 配音；
- 数字人；
- 自动剪辑成片；
- 高级调色；
- 遮罩动画；
- 插件系统；
- 专业特效合成；
- 复杂音频混音；
- 在本页调用图片或视频生成模型。

Codex 不得因为底层组件“可以做到”而擅自扩大范围。

## 3. 推荐技术分层

```text
视频基础编辑页面
    ↓
编辑领域层
    ↓
预览与时间线层
    ↓
本地媒体编排层
    ↓
媒体处理引擎
    ↓
任务中心与文件存储层
```

### 3.1 编辑页面层

负责：

- 素材列表；
- 预览舞台；
- 单轨时间线；
- 文字轨；
- 背景音乐轨；
- 动态属性面板；
- 撤销、重做、保存和导出入口。

页面不得直接拼接媒体命令，不得直接写入正式输出文件。

### 3.2 编辑领域层

负责维护可序列化的编辑草稿，建议模块：

- `EditProjectService`
- `TimelineService`
- `ClipEditingService`
- `TextOverlayService`
- `AudioTrackService`
- `CoverService`
- `UndoRedoService`
- `DraftAutosaveService`
- `SourceRelinkService`
- `ExportPlanService`

页面所有操作必须转换为领域命令，再修改草稿状态。

### 3.3 预览与时间线层

负责：

- 视频播放和定位；
- 播放头同步；
- 缩略图；
- 音频波形；
- 代理文件；
- 文字与画面变换预览；
- 低成本实时反馈。

预览层不生成正式作品。预览允许降低分辨率或使用代理文件，但最终导出必须读取原始素材。

### 3.4 本地媒体编排层

负责把编辑草稿转换为可执行媒体处理计划：

- 输入探测；
- 时间范围计算；
- 时间戳归一化；
- 变速；
- 比例和画布；
- 片段拼接；
- 文字渲染；
- 音量和背景音乐；
- 编码参数；
- 输出临时文件；
- 最终校验与原子保存。

建议通过适配器隐藏具体媒体引擎：

```ts
interface MediaEngineAdapter {
  probe(input: MediaSource): Promise<MediaProbe>;
  buildPreview(input: PreviewRequest): Promise<PreviewArtifact>;
  export(plan: ExportPlan, events: ExportEventSink): Promise<ExportResult>;
  cancel(jobId: string): Promise<CancelResult>;
  verifyOutput(path: string): Promise<OutputVerification>;
}
```

首选实现可以是 FFmpeg 或经过验证的等效本地媒体引擎，但业务层不得依赖具体命令格式。

### 3.5 任务中心与存储层

本地导出必须创建任务中心记录，不在页面线程中直接执行。

任务阶段建议：

```text
queued
→ validating_sources
→ preparing_media
→ encoding
→ writing_file
→ verifying_file
→ completed
```

异常状态：

```text
needs_user_action
failed
cancel_requested
cancelled
interrupted
recovery_required
```

只有以下条件全部成立，任务才能标记为 `completed`：

1. 媒体引擎正常结束；
2. 临时输出文件存在；
3. 文件大小和容器信息有效；
4. 文件可读取；
5. 最终路径写入成功；
6. 校验通过；
7. 版本和作品记录写入成功。

## 5. 源文件管理

### 5.1 不复制为默认策略

导入素材默认记录本地引用，不强制复制整个视频到项目目录。

用户可选择：

- 仅引用原文件；
- 复制到项目素材目录；
- 使用作品库中的受管文件。

### 5.2 文件身份

不能只依赖绝对路径。建议记录：

- 原始路径；
- 文件大小；
- 修改时间；
- 媒体时长；
- 容器信息；
- 可选内容哈希；
- 平台允许时的文件身份信息。

### 5.3 丢失文件

发现源文件不可用时：

- 草稿继续保留；
- 对应片段标记不可用；
- 禁止静默替换成同名文件；
- 允许重新定位；
- 重新定位后校验文件身份；
- 不匹配时要求用户确认。

## 6. 预览架构

### 6.1 双路径原则

```text
快速预览路径
低清代理 / 播放器 / UI 叠加层
```

```text
正式导出路径
原始素材 / 完整处理计划 / 正式编码
```

两者必须使用同一套编辑领域数据，避免维护两套业务状态。

### 6.2 代理文件

代理文件建议用于：

- 高分辨率视频；
- 高码率视频；
- 长视频；
- 解码压力过高；
- 用户主动生成。

代理必须：

- 可删除、可重建；
- 与原文件建立映射；
- 不进入作品库；
- 不替代正式导出源；
- 缓存清理后不破坏草稿。

### 6.3 预览一致性

以下内容必须重点对齐：

- 裁切范围；
- 画布比例；
- 缩放和位置；
- 文字位置和时间；
- 片段顺序；
- 变速后时长；
- 音量和背景音乐时间；
- 转场持续时间。

字体渲染、颜色转换和硬件解码可能造成轻微差异，测试中必须明确允许误差范围。

## 7. 媒体处理引擎

### 7.1 集成方式

媒体引擎必须作为受控本地进程或库运行：

- 不暴露任意命令输入；
- 参数由结构化导出计划生成；
- 标准输出与错误输出必须被捕获；
- 支持进度事件；
- 支持取消；
- 退出码和输出文件都必须验证。

### 7.2 临时文件与原子保存

正式导出流程：

```text
创建任务目录
→ 写入导出计划快照
→ 输出到临时文件
→ 媒体完整性校验
→ 处理文件名冲突
→ 原子移动到最终位置
→ 写入作品和版本记录
→ 清理临时文件
```

任何一步失败：

- 不覆盖已有正式文件；
- 保留草稿；
- 保留错误阶段；
- 临时文件按清理规则处理；
- 允许从安全阶段重试。

### 7.3 硬件加速

支持模式：

- 自动选择；
- 优先硬件；
- 仅软件；
- 禁用某种硬件能力。

必须实现：

```text
硬件路径失败
→ 记录失败原因
→ 根据策略回退软件处理
→ 重新创建新的执行记录或子尝试
```

硬件加速不能成为导出成功的必要条件。

## 8. 导出计划

`ExportPlan` 必须在任务创建时冻结快照，避免用户继续编辑草稿后影响已提交任务。

建议包含：

- 草稿版本；
- 输入文件快照；
- 片段和时间线；
- 文字和字体；
- 音频；
- 画布；
- 编码参数；
- 保存路径；
- 文件冲突策略；
- 硬件加速策略；
- 预估空间；
- 任务创建时间。

用户修改草稿后再次导出，必须创建新任务和新计划。

## 9. 撤销、重做和自动保存

### 9.1 命令模型

建议可撤销编辑均表示为命令：

```ts
interface EditCommand {
  apply(state: EditDraft): EditDraft;
  revert(state: EditDraft): EditDraft;
  describe(): string;
}
```

必须支持撤销：

- 裁剪；
- 分割；
- 删除；
- 复制；
- 排序；
- 变速；
- 画面变换；
- 文字；
- 音量；
- 背景音乐；
- 转场；
- 封面。

### 9.2 自动保存

- 使用防抖保存；
- 保存到临时文件后原子替换；
- 失败时保留内存状态并明确提示；
- 不能因自动保存失败而清空编辑内容；
- 应用关闭前检查未落盘修改。

## 10. 取消、失败与恢复

### 10.1 取消

取消请求不等于已经取消。

状态流程：

```text
running
→ cancel_requested
→ cancelled
```

如果引擎不支持安全取消：

- 显示“正在停止”；
- 不提前标记取消完成；
- 处理残留临时文件；
- 保留任务事实。

### 10.2 应用重启恢复

启动时扫描本地任务目录：

- 找到任务计划；
- 找到临时文件；
- 判断引擎进程是否仍存在；
- 判断输出是否已写完；
- 判断是否可以继续；
- 无法继续时标记 `recovery_required`。

不得把中断任务自动标记失败或完成。

### 10.3 重试

- 重试创建新的执行记录；
- 保留原失败记录；
- 可以复用同一导出计划；
- 修改参数后必须创建新计划；
- 更换硬件或软件编码方式要记录差异。

## 11. 跨平台规则

Windows 与 macOS 使用同一：

- 编辑草稿结构；
- 页面业务逻辑；
- 任务状态；
- 导出计划；
- 错误语义；
- 作品版本关系。

允许平台差异：

- 文件选择器；
- 路径表达；
- 系统字体；
- 硬件编码能力；
- 进程管理；
- 系统休眠控制；
- 沙箱与目录权限；
- 窗口控制区。

任何平台不支持的能力必须动态隐藏或明确禁用原因。

## 12. 性能边界

V1.0 不写死统一硬件指标。实现必须：

- 对输入素材执行探测；
- 根据分辨率、时长、码率和设备能力决定是否建议代理；
- 在本地设置中提供节能、平衡、高性能和自定义；
- 控制本地视频导出并发；
- 避免在 UI 主线程执行媒体探测和编码；
- 对缩略图、波形和代理任务设置低优先级；
- 磁盘不足时阻断正式导出；
- 内存或温度风险只能提示，不伪造精确预测。

---

## 13. 安全与合规

- 媒体命令参数必须结构化生成；
- 禁止直接拼接用户输入到 shell；
- 临时目录必须受控；
- 不将完整本地路径写入普通日志；
- 诊断包默认脱敏；
- 第三方媒体引擎及编解码器的许可和分发方式必须在发布前审查；
- 不声称支持当前构建中未验证的格式或编码器。

## 15. 最低验收清单

### 草稿

- [ ] 所有编辑不覆盖源文件；
- [ ] 自动保存失败不会丢失当前编辑；
- [ ] 撤销和重做覆盖核心操作；
- [ ] 草稿重开后时间线和属性一致；
- [ ] 源文件丢失可重新定位。

### 时间线与预览

- [ ] 裁剪、分割、排序结果正确；
- [ ] 播放头和时间线同步；
- [ ] 代理删除后草稿仍可恢复；
- [ ] 变速后片段时长正确；
- [ ] 文字和背景音乐时间范围正确。

### 导出

- [ ] 导出在后台任务中执行；
- [ ] UI 主线程不被编码阻塞；
- [ ] 取消状态真实；
- [ ] 硬件失败可回退软件；
- [ ] 不覆盖已有文件；
- [ ] 输出校验通过后才完成；
- [ ] 每次导出形成独立版本。

### 恢复与失败

- [ ] 应用崩溃后草稿可恢复；
- [ ] 中断任务不会错误显示完成；
- [ ] 失败阶段和原因可见；
- [ ] 重试不覆盖原失败记录；
- [ ] 临时文件可安全清理。

### 跨平台

- [ ] Windows 与 macOS 使用同一业务状态；
- [ ] 平台差异由适配层处理；
- [ ] 不支持的能力动态隐藏；
- [ ] 路径、权限和休眠行为经过真实测试。

## 16. Codex 禁止事项

Codex 不得：

- 把基础编辑扩展成专业剪辑器；
- 在编辑页调用生成模型；
- 每次操作都重新编码完整视频；
- 直接修改原始文件；
- 用 UI 预览结果代替正式导出；
- 编码进程退出就直接标记完成；
- 写死所有设备的格式、分辨率、帧率和并发；
- 因硬件加速失败阻止软件导出；
- 省略任务中心和恢复状态；
- 使用未审查的第三方二进制直接发布。

## 17. 实现准入

正式开发“视频基础编辑”前，Codex 必须先输出：

1. 编辑草稿 Schema；
2. 领域模块与依赖图；
3. 媒体引擎适配层接口；
4. 预览与正式导出分层方案；
5. 导出任务状态机；
6. 临时文件和原子保存方案；
7. 硬件加速回退方案；
8. Windows / macOS 文件权限和进程差异；
9. 测试计划；
10. 不在 V1.0 范围内的能力清单。

上述内容经项目负责人确认后，才能进入正式实现。
