## 播放修复方案与界面交互

在既有播放逻辑中分别维护用户是否希望继续播放，以及当前媒体处于暂停、准备、播放、缓冲、失败或结束状态。当前请求与当前媒体元素的事件共同决定界面，不能仅凭点击就标记为正在播放。

| 实际状态 | 按钮及可见提示 | 用户操作与恢复 |
| --- | --- | --- |
| 已暂停/可播放 | 播放图标 | 一次点击从当前播放头开始 |
| 正在准备或定位 | 加载提示“正在准备片段 2”，提供取消播放 | 准备完成且用户仍希望播放才继续；取消后晚到事件不得自动启动 |
| 正常播放 | 暂停图标，时间推进 | 一次点击立即暂停视频与配乐 |
| 缓冲/切换中 | 明确显示“缓冲中”或“切换片段中”，保留取消能力 | 保留上一帧；准备好自动续播，用户中途暂停则保持暂停 |
| 意外暂停 | 播放图标与简短“播放已暂停”提示 | 一次点击续播；不需要先做一次无效暂停 |
| 准备超时/解码失败 | 停止假播放状态，显示“片段 2 预览未就绪”及“重试播放” | 保留当前位置；重试只针对当前失败路径，源文件缺失时提供重新定位入口 |
| 全部播完 | 重播图标/文案 | 一次点击从开头播放 |

具体行为约束：

- 主媒体处理 playing/pause/waiting/stalled/error/ended；正常换源产生的 pause 和结束前 pause 不能清掉继续播放意图，也不能跳过后续片段。事件、seek、play promise、超时均绑定当前草稿/片段/媒体元素/请求代际，旧结果失效。
- seek 和换源完整闭环为“保留旧帧 → 获取有效预览 → 定位并解码目标帧 → 交回主画面 → 按最新意图播放”。主画面恢复后必须撤下保持帧，不能只验证媒体时间在走。
- 准备/seek/缓冲采用可取消的有界等待，初拟单次 15 秒收口，作为验收参数验证，不当作媒体行业标准。健康播放不轮询 IPC、不反复调用 play；必要的停滞检查只在活跃播放期间采样本地媒体进度，离页/暂停即取消，并排除页面隐藏造成的绘制节流。失败后由用户触发一次重试，不无限自动重试或擅自跳过坏片段。
- 自动跨片段保持播放意图；手动选片段保持原来的播放/暂停意图。拖动时间线沿用当前“进入拖动即暂停、松手定位后仍暂停”的行为，避免未经要求改变交互。
- 配乐服从实际播放阶段：主视频暂停、准备或缓冲时配乐暂停，恢复后按时间线位置对齐，避免画面停住而声音继续跑。
- 将错误归到具体片段和用途：主预览、拖动预览、时间轴缩略图分别反馈；例如“片段 3 拖动预览准备失败”。非当前片段准备失败不误停当前播放；恢复成功或离开对应上下文后清理旧提示。
- 播放、放大、Esc、切换属性页签不写入草稿；失败重试不改变剪辑时长、选定输出或正式作品状态。

## 推荐布局

属性面板贯通右侧上下两排；素材与舞台位于左上；时间轴只横跨素材和舞台下方。保留现有一级导航、顶部草稿操作、完整等比画布和底部任务栏。素材区默认280px，属性宽度按可用编辑区约三分之一、下限400上限560px，舞台取其余空间。截图尺寸的示例为280 / 816 / 560px（另计两道16px间距），不是按视频比例改变栏宽。属性可用高度由原来的上排扩展至两排，画面不会因扩大属性区而被裁切。

时间轴默认约240px高，保证三条轨可见；继续提供现有收起功能。低高度窗口优先保证播放工具栏和属性操作可见，各列表/表单内部垂直滚动。第一版不新增任意拖动面板或工作区持久化。
