# 制作过程联网提示与资料依据优化

日期：2026-09-11。依据负责人“制作的时候怎么没有感觉到联网搜索功能”及后续确认，在 `feature/provider-chat-availability-fix` 进行独立维护。遵循 `AGENTS.md` 顶部维护决策、`PLANS.md` 当前记录和现有原生搜索门禁；保留前一批模型配置/旧记录兼容改动，不恢复历史阶段或交接资料。范围为意图判定、响应准备、已有 Kimi/GLM 协议、对话提示及测试。

## 实际原因

只读检查发现最近一次实际 PPT 工作流的资料策略是 `none`，当前项目没有原生搜索执行账本；当前网关文本配置中原生搜索声明为 0。因此该次制作没有执行搜索。原逻辑主要依赖“联网/搜索”等显式词，普通制作又没有说明资料依据，用户无法辨认是否检索过网络。

## 变更

- 要求最新政策、近期数据、行业现状等公开时效事实时主动建议检索，并进入现有逐次授权。最新上传附件、修改最新版本及网络技术概念不据此触发。资料策略仅是建议，不提供联网权限；拒绝联网在后续补充要求中持续生效，只有明确重新要求联网才恢复建议。
- 制作前持久化助手资料说明，明确本次不联网搜索及最新信息未核实。本地检索命中的混合资料任务说明优先使用本地资料。该说明在绑定响应版本前写入，避免造成会话版本冲突；本地提示不进入模型历史。
- 缺搜索能力时说明未发起检索，并指向“模型与服务商→文本模型→联网搜索设置”。配置声明不等同于服务商实际支持，没有自动给网关模型设置协议。
- 区分请求已提交、收到搜索工具调用/来源、完成、无可确认记录、失败和取消。等待提示仅在真实传输会话打开后发出；GLM 收到首个完整且校验通过的结构化来源事件即显示来源数量，结束时列出累计来源和费用未报告事实。正文中的 URL 不作搜索证据。
- 显式拒绝在会话授权复用前处理；取消、失败、完成或撤销后的迟到事件不会恢复任务或追加成功提示。流读取及 Kimi 下一轮请求前复核取消；轮数、来源数量、字节和校验边界保持有界。
- 修复消息容器网格高度导致底部预留空间失效、提示被输入框遮挡的问题。自动跟随立即到达底部，避免平滑滚动中间事件被误判为用户离开底部；用户主动向上滚动的退出跟随行为保留。
