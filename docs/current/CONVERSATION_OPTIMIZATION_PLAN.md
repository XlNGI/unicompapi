更新时间：2026-09-09

## 1. 目标与当前范围

让用户在会话中用自然语言表达需求，由系统理解目标、利用授权资料、调用已支持的能力、验证结果并交付；用户可以继续补充、修改或取消。

本计划属于独立维护任务，不恢复历史阶段。事实源为负责人最新决策、根目录 `AGENTS.md`、`PLANS.md` 顶部维护记录、当前源码和本次实际验证。既定功能已完成与本次发现的会话接线、稳定性和体验问题并不矛盾。

本次允许修改：会话页面、应用层意图/工作流、受控 IPC、Provider 接线、附件引用、对应测试及工程文档。实施保留工作区中其他维护任务的已有改动。

本轮实施计划覆盖问答、附件理解、Office 生成与修订，以及这些能力之间的多交付物顺序编排。图片/视频创作的会话接入、全部功能统一调度、新增搜索供应商及额外 OCR/视觉能力留作后续独立任务。本轮包含对未配置能力的准确提示和既有研究引用链路修复。

成功的产品行为：

1. 问答直接给答案；生成、修订请求进入对应的受控执行流程。
2. 资料和必要参数足够时继续执行；只追问真正影响结果的缺项，不让用户反复选择已经明确的内容。
3. 附件是资料，不能单独成为创建文档的依据。对已生成作品的后续提问与修改请求分别处理。
4. 任务保留已确认需求、来源、目标和进度。补充信息合并，纠正信息替换，取消立即停止后续执行。
5. 结果必须经实际校验；说明已完成、未完成以及需要用户处理的事项，支持对已交付作品继续修订。
6. 不支持的需求说明具体能力边界和可用路径，不能停留在无意义追问或声称已经完成。

## 4. 执行行为设计

统一入口按以下顺序处理：

1. 读取本轮原文、当前任务、明确引用的作品和授权资料。
2. 判断本轮属于取消、纠正、补充、新需求还是普通问答；取消不得被字段提取覆盖。
3. 生成或更新严格的语义计划，包含目标、交付物、约束、资料需求和必要工具参数。
4. 由应用层解析真实对象、校验能力与参数、检查授权和执行预算；缺项才进入追问。
5. 资料、能力和既有授权满足时直接执行；仅对必要缺项或尚未满足的授权/门禁进行简短询问，展示真实进度并允许取消。
6. 调用白名单能力，完成内容、布局、文件和发布校验，再交付结果与可追溯的引用。

### 4.1 理解与追问

- 可靠的本地规则负责快速判断和取消保护；复杂表述交给受控语义分类/规划。不能只不断追加关键词，也不能将当前规则产生的高置信度错误无条件视为终局。
- 模型只建议语义字段与工具参数，应用层决定权限、路径、服务商路由、费用和作品登记。分类器应复用现有受控 Provider 机制，不新增私有凭证或直连通道。
- 先检查既有外发授权，再调用语义服务；采用最小必要上下文，优先使用附件元数据，避免为分类无差别发送完整企业资料。
- 追问项使用稳定字段标识与解决状态，展示文字不作为状态判断键。新回答可消除歧义，否定的类型不能参加普通关键词优先级。
- 缺少美化偏好等非必要信息时使用合理默认值；无依据的数据、需要修改的具体文件、必要执行授权等不能猜测。
- 计划变化导致交付物、目标、资料外发或费用范围变化时重新评估授权；不对已有授权范围内同一动作重复确认。

### 4.2 上下文、资料与结果

- 保留任务原始需求和历次补充/纠正，生成统一的有效约束；“上一份”“改第二页”等指代只能解析到当前项目允许访问的真实作品。
- 按会话/任务保存受控附件引用：文件标识、版本或内容 Hash、来源定位与可用状态。预览文本仅用于展示，生成和问答使用受预算控制的正文或检索片段。
- 用户明确选择的附件优先；不默认扩大到其他会话、其他项目或整个附件库。删除、失效、跨项目和版本变化必须被检测。
- 对长文件支持按问题检索和按章节读取。全文总结或全表统计不能用少量 top-k 片段冒充完整处理；超预算时说明处理范围并分段执行。
- 图片、扫描 PDF、加密文档等分别检测能力；当前无解析能力时明确告知，不能把已导入文件卡片当成已理解内容。
- 本地资料和获授权的研究片段统一进入带来源标识的上下文；引用视为不可信数据，不覆盖系统规则。
- 仅在本地文件、内容、布局、Hash、原子发布和 Work 登记均通过后显示正式作品；失败只重试受影响步骤，避免重复生成或登记。外部请求区分未发送、已有确定结果和已发送但结果未知；未知结果先核对服务商可恢复状态，不能自动重发付费请求或宣称未收费。

### 4.3 执行控制

- 输入按钮、Enter、附件拖入后的发送共用意图入口；显式输出偏好作为计划提示，不能覆盖本轮明确的问答或取消语义。
- 待澄清、待确认和就绪状态均接受自然语言取消；执行中取消停止后续工具步骤，处理迟到结果，并准确报告已经发生的调用和交付。
- 每个任务具备工具白名单、总超时、单步超时、费用/用量预算、最大步骤、最大重试/修正次数和可取消状态。实现前明确应用层配置及默认值，禁止无限循环和静默扩容。
- 能力选择读取当前能力注册、参数 schema 和授权；不写死服务商、模型、价格、分辨率、时长或数量。
- 多个 Office 交付物自动拆成关联任务，保存各子任务依赖、状态与结果，按依赖顺序逐项执行和交付；同一资料分析结果在适用时复用。已成功交付的部分不因后续失败重复运行。
- “先做 PPT”只调整未开始任务的顺序，原先要求的 Word 保留为待执行；若“只做 PPT，Word 不做了”，则取消 Word 子任务。开始后续步骤前重新检查当前授权与剩余预算，任务取消时停止尚未开始的交付物。

## 5. 分批任务与可审查提交

本轮实现最初保留在原工作区的 `feature/conversation-natural-language`。交付时从 `origin/develop` 的 `df6905e` 创建独立分支 `feature/conversation-natural-language-integration`，按本轮范围转入改动，保留远程已合入的底栏行为；原工作区其他维护改动和既有删除状态不变。按下表边界审查；隔离集成的验收、提交、合并及同步状态以实施记录为准。

| 任务 | 批次与依赖 | 实现范围 | 完成标准 |
| --- | --- | --- | --- |
| CO-001 取消与纠正保护 | 第一批，最高优先级 | 意图解析、工作流状态、执行前复核 | 取消不产生新执行；否定风格不误取消；纠正类型不沿用被否定类型 |
| CO-002 意图与追问修复 | 第一批，依赖 CO-001 | 创建/问答判定、稳定追问字段、澄清合并 | 明确创建请求不因主题疑问词误判；已回答问题清除；Word 内表格识别为单文档 |
| CO-003 统一输入与附件问答 | 第一批，与 CO-002 对齐接口 | ChatPage 发送入口、文档偏好、单轮受控附件读取及回答上下文注入 | 拖入文件后可按已授权资料问答；按钮与 Enter 一致；超读取范围说明限制；失败、切换会话和新会话不误继承执行意图 |

| CO-005 任务上下文与附件引用 | 第二批，依赖 CO-003 | 工作流与引用持久化、多轮恢复、长文件正文与检索、研究引用 | 多轮保留约束；尾部资料与版本可追溯；不会跨会话泄露引用；资料失败可见 |
| CO-006 执行与交付闭环 | 第二批，依赖 CO-004/005 | 状态反馈、取消/恢复、工具参数校验、结果门禁 | 重复点击不新增同一执行/登记；未知外部结果不自动重发付费请求，费用事实准确；Office 生成/修订可继续操作 |
| CO-007 Office 关联任务与多交付物 | 第三批，依赖第二批，遵循 D-01/D-03 | 受控资料读取/分析、Word/Excel/PPT 生成与修订桥接；关联任务计划、顺序执行及部分成功恢复 | 多个交付物自动拆分并逐项登记；顺序调整/取消作用于正确子任务；失败恢复不重做已成功部分 |
| CO-008 场景评测与收口 | 贯穿各批，最终依赖本轮全部任务 | 用户场景、执行集成、恢复、平台和门禁记录 | 达到本计划验收标准，保留实际失败与未验项，不以单元测试替代完整任务验收 |

CO-007 按三个部分审查：Office 子任务/依赖合同和计划持久化、受控资料处理及文档执行器、逐项交付与顺序调整及取消恢复。优先验收“分析销售资料 → Excel 报表 → PPT 汇报”和“同一资料分别生成 Word 与 PPT”。后续依赖未满足时停止对应任务，不执行空数据占位流程。

新增联网供应商、图片/视频会话入口、额外 OCR/视觉及通用任意工具 Agent 不在本轮实施范围。既有 Office 内配图保持现有流程与门禁，不能借多交付物编排扩展成独立图片创作。

## 6. 用户场景与验收标准

每条场景同时检查语义计划、工作流状态、实际调用和最终结果。取消/误执行类必须断言工具与作品登记调用次数，不能只检查界面文案。

| 场景 | 用户输入或操作 | 预期结果 |
| --- | --- | --- |
| AC-01 | “帮我做一份季度经营汇报 PPT” | 资料、模型和既有授权满足时直接进入受控 PPT 执行，不多一次常规确认；无真实数据时明确资料缺项或生成标注清楚的模板 |
| AC-02 | “帮我做一份关于如何提高销售额的 PPT” | “如何”作为主题，不分为普通聊天 |
| AC-03 | “可不可以帮我做一份 PPT，介绍公司的产品” | 识别为礼貌创建请求，不只回答“可以” |
| AC-04 | 已选销售附件；“分析附件里的销售数据，然后做一份 Excel 报表” | 读取指定资料并生成报表；统计结果与固定数据夹具一致，资料不可用时不编造 |
| AC-05 | “帮我做一份 PPT，不要太花哨” | 保留简洁风格约束，不误判取消 |
| AC-06 | “帮我做个总结 PPT” | 类型已明确，不再追问 Word、Excel 或 PPT |
| AC-07 | “帮我做个总结”后回答“不用做 PPT 了，取消” | 当前任务取消，新执行调用数为 0；可立即发送新需求 |
| AC-08 | 修订任务正在追问目标；回答“PPT，不要修改了” | 停止修订，原文件和作品登记不变 |
| AC-09 | 追问格式时回答“不要 PPT，要 Word，重点讲第三季度销售” | 选择 Word，保留主题，清除已解决问题，不调用 PPT 执行器 |
| AC-10 | “做 Word 和 PPT”，开始前补充“先做 PPT”；变体“只做 PPT，Word 不做了” | 自动建立两个关联任务，不要求二选一；前者优先执行 PPT，Word 保留待执行并在授权满足时继续；后者取消 Word，已解决问题不重复询问 |
| AC-11 | “做一份 Word 报告，并插入一个数据表格” | 单份 Word 内含表格，不误创建 Excel 子任务 |
| AC-12 | 拖入 PDF 后说“总结主要观点，在这里回复就行” | 读取资料后在会话回答，不创建 Office 文件；读取失败清楚说明原因 |
| AC-13 | PPT 交付后说“谢谢”；分别用 Enter 与按钮发送 | 普通聊天，不因上轮类型新建文件 |
| AC-14 | 长附件关键事实放在末节；先生成摘要，再问“最后一节列出了哪些风险？” | 能定位并引用末节；不能仅靠前 2000 字符或旧回答猜测 |
