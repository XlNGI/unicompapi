# R-04 / R-05 父任务续接与恢复验收

开始日期：2026-10-04；本地主链路验收完成：2026-10-05。分支 `feature/chat-send-input-runtime-fix`，属于阶段 9 基线收口后的维护。依据负责人“可以，直接做”及后续“继续”，保留此前已经授权的全部工作树改动。以下结果以最终稳定源码门禁为准。

## 实际实现

稳定的 ConversationAgentSession 保存原始任务、受控消息版本/Hash、等待版本、一次性续接令牌摘要、固定 deadline/预算、租约 owner/epoch 与已登记 Work。规划容器不绑定 Response；后续每次回复追加独立 child AgentRun/Response，旧 Response 和调用身份不可重绑。既有 Provider Loop 继续承担真实执行，没有第二个执行循环。

补信息、确认授权和安全继续都携带原 Session、版本和令牌，Host 再核对项目、会话、原始输入及候选/授权。主 metadata CAS 消费令牌、追加 child 并取得租约。等待、重启和继续保持原始开始时间、截止时间及既有消耗；过期须明确发起新任务。重复命令只能返回已经绑定的执行，不再调用模型或工具。续接仍保留原始 PPT 交付目标，单纯文本回复不能替代文件交付。

生产等待区支持补充、确认、继续、停止和过期后发起新任务。新等待任务优先于旧过期记录。未知结果保持冻结；用户明确关闭只解除新任务阻拦，保留旧未知事实和已保存文件，不恢复旧调用权限。没有 Response 的规划请求也能明确关闭；有 Response 的未知结果继续使用原核对/确认关闭入口。

默认执行租约 30 秒、有界续租并有独立失效计时器。模型与工具的实际准入前后核对 owner/epoch，租约失效信号传到真实 Provider 请求，包含没有文档工具 session 的调用。项目 metadata 用跨进程独占锁保护读改写 CAS；存活进程的锁不能因年龄被抢走，仅可恢复已证明进程死亡的遗留锁。

显式核对、确认关闭和完成 WAL 的各次写入也重新检查执行权，不能在另一个 owner 活跃时先写其子任务日志。主 WAL 证明只是已知本地投影失败时，可单独收口 Root；真正未知请求不能沿用这个通道冒充完成。普通页数目标和已保存文件的门禁沿用此前实现。

两处绑定之间崩溃时，只从主 AgentRun、Response 与原消息版本/Hash 核验并补齐不可变关系；该收据不改变状态、期限、预算或租约。过期且可证未提交的响应先本地收尾；原授权 claim 仅在核验尚未开始请求后释放，已开始或无法核验的请求不退回调用额度。首次恢复因旧租约仍有效而跳过后，同一 Host 后续按相关会话/执行范围重新核对已过期的失主任务；不要求再次启动，不刷新其他任务或正常等待的令牌。

已正常收口的历史任务不再占用恢复候选名额或重复校验文件。取消、过期任务里的未决调用、缺失绑定和待投影 WAL 仍纳入调查；扫描沿用主仓库的 4096 条有界上限，不截断未决记录。热路径只索引经过核验的不可变归属，权限、当前 lease/epoch、active child 和预算仍以每次主记录读回为准。无 mutation 渲染能力时，已有 PPT 的会话也不误用更大的组合执行预算。

## 恢复边界

统一恢复器先取得执行权或只读观察权，再核对主记录中的 Session、Run、canonical 调用、Response/流事件、提交 acceptance、完成 WAL、文档任务、修改日志和真实 Work/文件 Hash。旧局部扫描按该所有权过滤，另一个活跃 owner 的任务不会被中断或修复。

| 已持久事实 | 恢复行为 |
| --- | --- |
| 已进入等待，输入与主记录有效 | 保留原任务，重启时更新一次续接令牌 |
| 可证明尚未提交 HTTP/工具且无副作用 | 提供显式继续；旧准备响应仅本地收尾 |
| 已知本地发布/完成投影尚未收口 | 复用既有本地幂等修复，不生成第二份文件 |
| 请求已发但结果未知、未决工具、记录/文件证据不一致 | 冻结，不自动重发；保留可验证的文件 |
| 缺 canonical WAL，但已有开始/流输出证据 | 不能认定零调用，转待核对 |
| 时限已过且结果已知 | 过期，不重置预算 |
| 仅备份记录、损坏主记录或输入已改变 | 不授予执行权 |

恢复只使用已有受控消息/工作流引用。原工具参数只保存 Hash 的步骤不能从摘要重建，未实现任意步骤自动续跑。已拥有 Session 的 Agent/受控文档主链路纳入此协议；无 Session 的旧独立工作流保留兼容恢复，未强制迁移。真实付费调用、真实凭证、用户项目数据和用户开发应用均不用于本轮验证；macOS 实机继续延期。模板/Design IR、逐页预览和审美 QA 不在本轮范围。

会话文档闭环验证以当前受控 PPT 首版/修改为主；未把这些结果扩大为所有格式、所有服务商或所有旧入口均支持任意续跑。跨进程恢复 guard 本身留下不确定锁时继续保守停止，不按年龄抢锁。

## 失败记录与性能

接入过程中曾发现审计/执行时钟不一致、Root 未同步子终态、明确信息关闭后的父状态未收口、读取已完成回复早于真实结算、规划失租后过期错误放行等问题，均有相应回归。测试增补时首轮 full worker 仍加载旧 Service，出现两条新方法不存在错误；该轮没有宣称通过，日志 `r04-r05-vitest-full-first.log` 保留。后续稳定全量的重复归属查询让一次生成恢复超原 5 秒，身份索引改为不缓存权限/状态并保留每次 primary fence 核查后，最终该闭环约 4374ms；无 mutation renderer 的预算 profile 也保持当前实际能力上界。

原 Office 三方向检查在独立和全量运行中均超 10 秒。真实探针得到三份顺序转换约 12—14 秒，全部 9 页的渲染/QA 通过；profile 初始化或新增启动参数没有足够收益，因此没有加入生产 profile 缓存。只将三个无顺序依赖、各自随机文件/独立 profile/临时目录的 fixture 改为 `Promise.allSettled(3)`，仍等待全部自有任务结束后清理，所有检查和原 10000ms 保留。并行探针 6691ms，独立用例 5688ms，最终全量该文件 7/7。证据为 `r04-r05-office-isolated.log`、`r04-r05-office-parallel-probe.log`、`r04-r05-office-parallel-isolated.log`；未把门禁组织优化称为新的生产批量创作功能。

当前范围内无已知阻断。旧独立入口、任意参数自动重建、设计一致性、预览与审美 QA 仍维持前述边界。本轮改动尚未提交、推送、合并、部署或重启用户应用。
