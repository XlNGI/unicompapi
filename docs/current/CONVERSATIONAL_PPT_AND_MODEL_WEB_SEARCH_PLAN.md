## 1. 任务定位与决策依据

本任务属于既定功能收口后的独立维护与体验扩展，不重启历史阶段计划。依据负责人本次会话决策、根目录 `AGENTS.md`、`PLANS.md` 顶部维护事实及当前源码实施。

负责人已经明确：

1. 所有实际支持联网搜索的已接入模型都应能够使用联网能力，重点是模型在回答过程中主动选择搜索。
2. PPT 先规划整体，再一页一页制作，能够逐页看到结果并单独修改。
3. “我想做一个 PPT”之类不完整需求必须先追问或引导，不能直接编造主题开始制作。
4. 所有相关提示都以助手回答的形式出现在会话中，包括追问、计划、授权、生产进度、失败、恢复和交付。
5. 连续生产进度更新同一条助手消息，等待用户回应时新增消息；页面预览、引用与文件附在对应回复中。本文早期记录中的“制作过程”均按总体方案 V2.3 统一称为“生产进度”。

本文件只新增工程侧说明，不覆盖权威 UI 交接原件。最新负责人确认的对话交互覆盖此前讨论中的独立制作卡片、提示条与强制按钮确认方案。

### 1.1 与总体架构的对齐规则

本文件不再把 Chat、Research、Document 解释为互斥路由，也不把 PPT 描述为拥有独立权限的 Agent。PPT 是共享 Conversation Agent/Task Runtime 下的一种格式交付，由 `Document Planner` 产出版本化 `Document IR`，再由 PPT 格式适配器和 Platform Renderer 执行。联网搜索是受授权的 Context/Research Tool；搜索 Observation 必须回到同一个任务计划，允许 Agent 决定继续检索、直接回答、制作文档或追问。

PPT 页面状态、逐页预览、页面修订和搜索授权仍由本文件定义；任务取消、预算、版本、幂等、结果未知、修正次数、确定性 QA、Visual QA、原子发布和 Artifact Registry 顺序遵循总体方案。页面修正后必须重新渲染并通过完整 QA，不能直接登记为正式作品。

2026-09-22 最新 UI 决策与实施：根据负责人要求，生产进度默认展开本地与模型交互时间线，流式展示请求、响应、计划决策、本地工具及校验发布过程，并在正文模型响应节点下同步显示可读的生成正文。独立 Trace 已接真实生产调用点并支持历史恢复，跨正文流终态继续显示本地生成事件；旧 `task_progress` 保留兼容。正文预览来自模型内容流和已验证消息内容，页面预览 IPC 尚未接通，因此本计划 P5 的真实逐页预览仍未完成。验证与后续接线边界见总体方案 12.14—12.15 和 `PLANS.md` 顶部维护记录。

## 2. 目标与边界

### 2.1 本次目标

- 基于实际服务商连接、模型及协议能力，统一启用模型原生联网搜索。
- 建立可恢复、可取消、可单页修订的 PPT 制作任务。
- 使用真实执行事件驱动自然语言回复，保证用户知道当前完成了什么、正在做什么及需要补充什么。
- 保留本地资料优先、范围授权、凭证隔离、费用事实、正式作品校验和登记门禁。

### 2.2 范围边界

- 不新增业务一级页面；复用会话及现有文档工作区。
- 不加入登录、会员、充值或云同步。
- 不默认联网；开启自动搜索必须有有效授权。
- 不把普通函数调用能力等同于模型原生搜索能力。
- 不承诺未知网关、未知未来模型无需适配即可使用；新模型复用已支持协议，新增协议需要新增适配。
- 本轮不强制接入独立第三方搜索服务。应用执行搜索工具是兼容扩展路径，保留现有接口，单独验收后开放。
- 不以 PPT 生成为理由自动启用付费图片生成；素材优先采用用户授权资料、已有资源及本地图表。
- 本次提示形式改造覆盖会话制作及搜索闭环，不顺带重写无关业务页面。Windows/macOS 原生文件选择等系统界面仍使用系统机制，触发原因及结果在会话中说明。

## 4. 产品交互闭环

### 4.1 信息不足时先对话

最低启动条件是：输出类型明确，主题或实际内容范围明确，存在足够资料或允许使用通用知识的边界。企业名称、产品功能、业绩等事实不能用默认值编造。

示例：

> 用户：我想做一个 PPT。
>
> 助手：你想做什么主题的 PPT？可以告诉我用途，比如工作汇报、产品介绍或教学，也可以先添加参考资料。
>
> 用户：介绍我们公司的产品。
>
> 助手：是什么产品，主要给谁看？你可以简单介绍，也可以添加产品资料。
>
> 用户：给客户介绍我们的仓储管理软件，这是资料。
>
> 助手：我会根据这份资料整理客户介绍大纲，重点说明使用场景、核心功能和产品价值。页数先按内容建议，你可以随时调整。

规则：只有缺少会显著影响结果的关键事实、授权或目标时才追问；已有信息不重复问，资料足够时直接读取并执行。每次最多提出 1—2 个关键问题，不把追问作为固定分类步骤。页数、风格等次要参数可采用默认建议，不形成长表单。

“随便做”“其他你安排”只允许采用明确表达的自主范围；仅说“你安排”不能自动授权联网、收费配图或编造企业事实。没有主题时可提出一个具体主题建议并询问是否采用。

### 4.2 所有提示都是助手回答

| 场景 | 会话表达示例 |
| --- | --- |
| 大纲 | “我整理了 10 页大纲，含封面和结尾：……” |
| 搜索授权 | “这部分需要查询最新公开资料。将由当前模型服务商根据本次已选内容生成搜索查询，搜索可能另行计费。是否允许本次联网？” |
| 逐页进度 | “第 3 页已完成。正在制作第 4 页的产品对比图。” |
| 自动调整 | “第 5 页内容过密，我正在压缩文字并调整布局。” |
| 阻断 | “第 7 页缺少销售数据。其他页面已保留，你可以补充数据，或让我改成定性说明。” |
| 失败 | “第 5 页的配图制作失败了，其他页面已保留。可以重试这一页，或改用无图版式。” |
| 交付 | “10 页 PPT 已完成并通过检查，文件在下面。” |

- 不以弹窗、toast、独立提示条或独立进度卡作为本流程的信息载体。
- 预览缩略图、文件、来源链接作为助手消息附件；查看大图可打开现有文档工作区。
- 用户可直接回复“继续”“不要联网”“重做第 3 页”“暂停”“取消”。按钮不是完成流程的必要条件。
- 当前进度消息原位更新，阶段结束时保存最终摘要；完整真实事件留在内部审计中，不把技术日志整段显示给用户。
- 授权问题、缺失信息问题、最终交付使用新的助手消息；已经提出的问题不被进度覆盖。
- 不伪造等待动画所对应的工作，不输出内部 Prompt、思维链、凭证、绝对路径或附件全文。

### 4.3 自然语言操作必须绑定目标

Conversation Agent 负责理解用户语义并决定回答、追问或工具行动。Application 只对已经绑定的待回应问题、授权和目标执行确定性解析与校验，不使用业务正则替代 Agent 路由。每个待回应问题保存 questionId、taskId、workflowRevision、问题类型和允许动作；只有一个明确匹配的有效问题时，“同意”“继续”才可解析为对应动作。

- 搜索授权、内容确认与付费配图是不同授权类型，不得用一次“继续”跨类型放行。
- 同时存在多个任务或待确认项时，先用对话澄清目标。
- 否定、转述、引用及材料中的“同意”不作为用户授权。
- 新增附件、切换服务商连接、扩大外发范围、修改预算或计划版本后，重新评估授权是否失效；旧回复不能授权新任务。
- 复杂意图可由模型建议解析，但 Application 根据真实用户消息及有效问题执行确定性校验。
- 制作期间输入普通问题不会被自动当作修改指令；明确另起任务时通过对话说明当前任务处理方式。

## 5. 模型原生联网搜索

### 5.1 能力身份与覆盖矩阵

有效能力键为连接、模型、协议绑定及相应版本的组合。同名模型在官方接口和网关中分别登记；模型名称、营销描述或普通模型列表不能证明搜索能力。

实施时盘点当前 ProviderPackage、实际协议族及配置入口，形成逐项矩阵：模型/连接/协议、文档证据、适配器版本、能力状态、测试状态、已知限制。使用现有能力状态体系区分声明支持、验证支持、未知、不支持、受限及验证失败。

建议的搜索能力字段：

| 字段组 | 内容 |
| --- | --- |
| 执行方式 | provider_native / application_tool |
| 控制能力 | 能否关闭、自动选择、强制搜索 |
| 返回能力 | 搜索过程事件、来源引用、搜索用量 |
| 约束能力 | 域名限制、次数限制、费用限制、上下文范围控制 |
| 证据 | 来源、记录时间、有效范围、协议/模型版本 |
| 约束强度 | 可强制执行 / 仅提示 / 不可观测 |

不能可靠禁止搜索的连接，不得在“关闭联网”请求中被当作满足离线要求的候选。未知能力以助手说明并提供可行选择，不自动试探收费接口。

### 5.2 用户控制

- 默认关闭；用户通过对话允许本次或本会话联网后，可进入自动模式，由模型判断是否搜索。
- “必须联网查询”要求实际搜索证据；只有协议支持强制搜索或能通过可控路径保证时才接受，否则说明限制。
- 会话授权记录时效、项目、连接、内容范围和预算；仅在授权仍有效时复用，支持随时撤销。
- 能力状态可以在模型信息中展示，但开启失败、授权和限制说明全部通过助手回复表达。

### 5.3 协议适配

Application 输出受控的搜索意图、授权引用和限制；Provider Adapter 决定真实请求格式。

原生工具、专用搜索参数、专用端点均由对应协议族负责序列化和解析。保留文档 function 白名单；新增独立的原生工具判别结构，不接受模型或 Renderer 任意注入 tools、端点、请求头或凭证。

兼容网关需要验证请求参数透传、模型路由权限、响应事件和费用信息。原生搜索失败不自动切换模型、网关或独立搜索服务。

### 5.4 搜索事实、来源与费用

统一区分 enabled、started、completed、failed、unobserved；启用不等于执行，模型自述或普通正文链接不能证明真实搜索。

有协议事件时可回复“正在检索”；无事件时只说“已允许联网”。强制搜索缺少证据时说明“未能确认本次搜索已执行”，不能将答案标为联网核实结果。

来源记录标题、URL、提供方、协议引用位置、接收时间及可用证据。网页发布日期只有真实返回时才记录。链接校验、去重并通过受控外链入口打开；没有抓取正文就不能声称应用验证了网页内容。来源作为不可信资料隔离传入后续模型。

模型 token、搜索次数及搜索费用分别登记。未返回的指标标为未报告，不能记成 0；有确定定价及数量才能计算费用。

原生搜索的查询词和次数可能由服务商内部决定。授权必须说明实际外发内容及不可观测限制。硬性域名/预算要求无法执行时阻断，不以客户端提示冒充服务端约束。客户端取消后，上游可能仍执行或计费，保存结果未知状态。

## 6. PPT 逐页制作

### 6.1 整体计划与稳定页面身份

确定主题、受众、目标、资料边界、视觉规则及页面顺序后形成 DocumentPlan/DeckPlan。每页保存稳定 pageId、显示页码、标题、核心结论、来源需求和版式意图，并映射到版本化 Document IR/Scene IR。Agent 可以根据 Observation 动态调整页面顺序和工具调用；逐页串行只是默认并发策略，不是强制固定流水线。

页码包含封面与结尾，不允许生成器静默新增页面。已有 section 自动续页逻辑需改为先反馈页数变化：明确要求固定页数时优先调整内容和布局；无法满足时通过对话说明，不无限缩小字体。

新增 deckRevision、pageRevision、内容 Hash、主题版本及依赖版本。旧作品没有 pageId 时，在受控导入/修订准备阶段建立映射，不能让模型提供的路径或页码直接决定文件操作。

### 6.2 页面状态与产物

```text
pending → drafting → layout → rendering → checking → ready
                     ↑                       ↓
                     └──── bounded repair ───┘

分支状态：waiting_input / failed / paused / cancelled / stale
```

单页检查点保存内容、布局、素材引用、预览、结构/视觉检查报告及失败码。内容生成、图表制作、排版和修复由实际 Observation 决定，不强制每页调用一次模型。PPT 页面执行器共享父任务的预算、授权、取消和 revision，修正后必须重新渲染并通过完整 QA。

默认按页串行调度，降低跨页依赖和费用复杂度；后续并行只能使用显式并发上限。每页完成校验后立即可预览，整套任务尚未完成时标为“草稿页已完成”。

### 6.3 预览与导出一致性

优先渲染实际页面 PPTX 产物；若使用中间场景描述预览，必须与 PPTX 输出共享布局模型并通过一致性验收。不得把独立 HTML 美化预览当作导出效果。

首先验证现有渲染适配器能否提供真实逐页图像、字体回退和可取消能力。渲染器缺失或失败时，在对话中明确说明预览不可用，不能伪造缩略图，也不能宣称视觉检查完成。正式交付是否满足视觉门禁必须按实际证据判定。

### 6.4 单页编辑与全局依赖

- 单页改写、换版式、重做、锁定、恢复上一版均定位 pageId + expectedRevision。
- 插入、删除、重排更新显示页码、目录和交叉引用；用户所说“第 3 页”基于其已看到的当前版本解析。
- 锁定页不自动重写。全局主题变更涉及锁定页时通过对话说明影响并取得明确指令。
- 正在生成的页面收到修改请求时取消或作废旧执行；过期返回不得覆盖新版本。
- 修改局部只重做目标及明确依赖页；素材或主题变化按依赖标记 stale，不无条件重做整套。
- 每次接受的修订保留可回退版本，局部失败不破坏已完成页面或父作品。

### 6.5 暂停、恢复与最终交付

暂停停止调度新页面，取消可取消的活动请求，并保存最近有效检查点。已提交上游但结果未知的请求单独登记，不把暂停等同于服务端终止。

重启后恢复页面状态，在对话中说明完成页数和中断点；不自动重新发起收费调用。重试只覆盖明确失败或待继续步骤，已保存结果优先对账，避免重复扣费。

最终组装使用同一个 deckRevision 的页面快照，核对页面数、顺序、字体/素材引用、链接、结构、布局及 Hash，原子发布后登记 Work。任一步失败保留草稿并说明原因；作品已经登记但会话同步失败时走 reconcile，不重新生成整套。

## 7. 分层结构与事件持久化

| 层 | 职责 |
| --- | --- |
| Domain | 搜索能力、授权范围、Deck/Page 版本、状态转移、事件 Schema |
| Application | 完整性检查、自然语言动作绑定、权限和预算、调度、失效传播、交付门禁 |
| Platform | 服务商协议、凭证回调、受控本地文件、PPTX 生成、渲染、仓储 |
| Renderer | 助手回复、预览附件、文件与来源显示；只提交受控 ID 与用户动作 |

内部事件至少包含 eventId、taskId、executionId、sequence、stage、status、occurredAt、revision，以及必要的 pageId、failureCode 和安全计数；不包含凭证、绝对路径、原始请求体或思维链。

状态变更与待发布事件需采用原子事务/持久 outbox 或现有等价机制。采用至少一次投递加幂等消费，不依赖脆弱的“只发一次”。Renderer 按事件序号和 revision 去重、拒绝旧状态覆盖，并支持读取快照后续订阅补齐事件。

助手进度消息是事件的确定性投影，不通过额外模型调用编造。持久化区分任务系统生成的助手说明与模型正文；组装后续模型上下文时避免重复塞入进度记录，同时保留用户指令、确认事实和已选内容。

正式消息终态应先落盘再通知 UI，复用已修复的会话版本同步机制。不得由进度高频写入反复制造用户输入的 revision 冲突。

## 8. 有界执行合同

以下为本搜索/PPT 子计划的阶段策略建议，不是写死的服务商能力。最终以总体方案 V2.3 的统一资源策略和任务快照为唯一来源；集中配置并校验，实际协议更严格时采用更严格限制。单任务总调用、费用和总耗时上限由统一资源策略决定，分阶段预算不能绕过全局上限。

| 阶段 | 输入 → 输出 | 建议最大耗时 | 修正/调用边界 | 失败与取消 |
| --- | --- | --- | --- | --- |
| 意图/完整性 | 用户消息与授权上下文 → 需求或问题 | 本地 5 秒；模型 90 秒 | 每条新消息最多一次模型判断；最多一次结构修正 | intent_invalid；取消后不进入生成 |
| 等待用户 | 有效问题 → 回答绑定 | 不计主动执行时长；授权另有有效期 | 不自动轮询追问；用户新消息驱动 | question_expired / ambiguous_reply |
| 搜索 | 授权快照 → 来源与用量事实 | 单次 90 秒 | 应用工具回合建议最多 3；原生内部次数必须声明控制能力 | search_failed / search_unobserved / budget_exceeded |
| 整套规划 | 已完整需求与资料 → DeckPlan | 120 秒 | 最多一次结构修正 | plan_invalid / page_count_mismatch |
| 单页内容 | PagePlan 与必要资料 → 页面内容 | 120 秒 | 初次生成加最多一次内容修正 | page_content_invalid / source_missing |
| 单页排版渲染 | 页面内容与主题 → 页面文件和预览 | 每次 60 秒 | 最多两次布局修复，受全局预算约束 | render_unavailable / layout_overflow |
| 整套检查交付 | ready 页面版本快照 → 正式 Work | 180 秒 | 不自动重发生成请求；登记同步幂等对账 | revision_conflict / verification_failed / registration_failed |

取消需贯穿模型请求、搜索工具、渲染子进程和文件写入；每个检查点校验取消及版本。无论服务商是否支持取消，客户端不得继续发布被取消版本。

模型不能自行决定执行上限、权限、路径、服务商、费用或正式作品登记。费用未知不能被解释为满足硬预算；在无法硬控制的原生搜索上，须使用明确接受该限制的授权或阻断执行。

## 9. 实施批次与修改范围

本节 P0—P7 是搜索/PPT 子计划映射，不是独立于总体方案的第二套产品阶段。总体方案 V2.3 的 P0—P5、Task Runtime、原子工具和发布门禁优先；本节只描述搜索与 PPT 格式特定工作的依赖顺序。P1 原子工具桥接基础已部分完成，但实体绑定、Observation 持久化、真实逐页渲染和完整闭环仍未完成。

每批从最新已集成的 `develop` 建立独立 `feature/*` 分支；依赖前一批合入后再起分支。保留本地和远程功能分支，避免一个大 PR 重写全链路。

| 批次 | 交付内容 | 主要范围 | 进入下一批的条件 |
| --- | --- | --- | --- |
| P0 能力与渲染核实 | 搜索覆盖矩阵、协议证据、页面渲染验证、Schema 迁移方案 | `docs/current/`、Provider/渲染相关定向验证 | 每个接入协议有明确依据；预览方案有实际渲染证据 |
| P1 对话事件与追问 | 真实事件投影、自然语言动作绑定、所有提示进入助手回复 | `src/domain/entities/conversation*`、`src/application/conversation*`、仓储/IPC、`src/pages/chat/` | 模糊需求不生成；授权不误触发；刷新不丢消息 |
| P2 搜索能力与授权 | 模型搜索能力 Schema、路由快照、会话/本次授权、费用 DTO | Provider model/profile、runtime authorization、shared/IPC、chat | 不支持/未知能力正确处理；旧授权不能扩大外发 |
| P3 原生搜索协议 | 按实际协议族拆多个小 PR，逐一接入请求/事件/引用/用量 | `src/platform/providers/`、transport、解析测试、能力矩阵 | 当前已接入的声明支持模型全部映射到适配器，并标明真实验收结果 |
| P4 PPT 页面任务 | Deck/Page 稳定 ID、版本、检查点、页数合同和顺序调度 | `src/domain/entities/presentation-plan.ts`、Application、文档仓储 | 可独立保存页；失败后保留已完成页；无陈旧写入 |
| P5 逐页预览与回复 | 真正逐页渲染、缩略图附件、进度回复、最终组装 | `src/platform/documents/`、document IPC、chat/workspace | 用户能在整套完成前看到真实页面；导出与预览一致 |
| P6 修订与恢复 | 单页修改/重做/锁定/回退、重排依赖、暂停重启、搜索与 PPT 联动 | revision map、文档修订、调度、会话恢复 | 单页变更不误改其他页；恢复无重复生成/计费 |
| P7 集成验收 | 全量回归、Windows 实机、受授权真实服务商验收、交付记录 | 测试、验证脚本、`PLANS.md`、本计划验收附件 | 无阻断失败；未验证项明确登记，不能以模拟结果关闭真实验收 |

P3 可按协议分别上线，展示范围以矩阵为准；不能把“已有公共框架”宣称为全部模型已支持。PPT 路径无需等待所有搜索适配完成即可用本地资料验收，最终按依赖合流。

## 10. 验收清单

### 10.1 对话与需求

- “我想做一个 PPT”触发主题追问，未调用文档生成或收费接口。
- 连续补充主题、受众、资料后正确恢复同一任务，不重复问已知信息。
- 所有追问、授权、失败、进度和交付均在助手消息中；完整流程不依赖提示弹窗或独立表单。
- “继续”只作用于明确待回应项；引用、否定、旧问题回复和多个任务歧义不会误授权。
- 消息更新不刷屏、不抢输入焦点；键盘、读屏与滚动跟随符合现有约束。

### 10.2 搜索

- 同名模型不同连接分别识别能力；开关关闭时请求不启用搜索。
- 自动模式允许模型不搜索；实际搜索状态必须有协议证据。
- 必须搜索时，不支持、缺证据或失败均明确说明，不能伪装为联网完成。
- 覆盖授权撤销、资料范围扩大、模型/协议变更、超时、限流、鉴权失败、引用缺失、事件重复及乱序。
- 覆盖只有最终响应、没有搜索过程的服务商；不伪造中间状态。
- 引用安全处理且不过度背书；费用未知不显示免费，累计与增量用量不重复计费。
- 不自动切换搜索服务或重新执行结果未知的收费请求。

### 10.3 PPT

- 明确要求 12 页时最终恰为 12 页，含封面/结尾；内容过密按合同处理。
- 每页生成、预览和检查可观察；全部页面生成完成不等于正式文件交付完成。
- 第 N 页失败不丢失此前已完成页面；只重试失败页。
- 第 3 页重做只影响指定页及必要依赖；重排后仍依据稳定 ID 修改正确页面。
- 已锁定页面不能被全局调整静默覆盖；旧执行晚到不覆盖新版本。
- 实际 PPTX 与预览逐页核对文字、图表、图片、字体和分页；不能以内容结构检查替代视觉检查。
- 中断/重启可从检查点恢复；保存/登记/会话同步各故障点重试无重复作品。
- 正式 Work 经过本地文件、内容、布局、Hash、原子发布及登记门禁。

### 10.4 工程验证

每批运行相关定向测试、类型检查、lint、真实生产构建及差异检查；涉及流式协议、权限、仓储或导出时运行相关故障与恢复套件。集成时运行完整 Node/UI 和 Vitest 门禁、平台审计及已有恢复/关闭校验。

真实请求验证必须先取得针对连接、合成输入、外发范围及预算的明确授权，记录时间、费用和脱敏结果，不使用企业资料作默认测试输入。计划编写及离线实现不等于已授权联网检索或收费验收。

Windows 为当前必需实机目标；macOS 保留跨平台设计及静态/合同约束，实机未执行时记录 deferred，不宣称已验收。

## 11. 已知风险与实施前核实项

| 项目 | 处理方式 |
| --- | --- |
| 网关宣称支持但不透传原生工具 | 按连接验证，失败后保留限制事实，不靠模型名称放行 |
| 服务商无法限制内部查询、次数或费用 | 在能力矩阵明示；硬约束任务阻断，不能用软提示替代 |
| 缺少可用 PPTX 页面渲染器 | P0 优先验证；未解决前不关闭逐页视觉验收 |
| 章节与物理页面不是一一对应 | 使用稳定 pageId 与实际文件映射；显式处理续页和固定页数 |
| 进度频繁写入导致会话冲突 | 单独事件序列与节流投影，终态落盘后通知，保留乐观并发校验 |
| 局部编辑时全局布局变化 | 版本快照与依赖失效控制，避免不必要整套重做 |
| 当前工作区 handoff 文件缺失 | 保留现状，不删除校验绕过失败；集成验收使用含权威资料的干净工作树并单独登记工作区差异 |
