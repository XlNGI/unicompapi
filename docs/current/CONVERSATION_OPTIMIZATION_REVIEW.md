## 已复现的问题与修复目标

1. **已登记作品后完成状态写入失败**：在 `Work` 保存成功后注入 execution 的 `completed` 写入失败，原实现把执行改为失败；相同请求重试导致作品数量由 1 变为 2。应保留待结算状态，复核任务、执行、作品、文件、父版本及本地 Hash 后补写完成，不重复渲染或登记。
2. **正文已完成但本地文件生成中断**：启动恢复把所有未结算文档标为外部结果待核对，导致已持久化正文和本地生成参数无法继续。应识别真实完成的模型响应及已开始的本地文件步骤，保留正文、原参数和已交付部分，仅恢复本地生成；未知响应仍不得自动重发。
3. **追问后的资料要求没有传入资料处理**：从“帮我做个总结”补充为“Excel，统计全表总计金额”后，仍按原摘要需求准备和接受事实摘要。另一个方向，从报告需求补充“总结附件全文”会漏做分段摘要。应将 Application 校验后的有效需求贯通摘要准备、响应预校验和最终上下文构造，并持久化主进程内的查询快照；原消息身份继续用于追溯。

## 后续反馈：生成 PPT 问第 5 页却回答第 7 页

负责人确认对象是当前对话里刚生成的 PPT。源码确认普通响应只读取会话历史正文、附件和项目资料，没有根据 `documentResult.workId` 读取已交付 PPT 的实际页面。生成器会插入封面，并可能为长章节生成续页，因此大纲序号不能等同于物理页码；局部修订后的历史正文也不能充当成品页面。本轮没有读取负责人这份原始 PPT，不能把“固定偏移两页”认定为其个案结论。

修复后，单页问答默认定位当前消息之前最近交付的 PPT，亦可用完整文件名选定版本；从已登记 Work/File 校验项目、执行来源、文件位置、状态、大小及同一读取缓冲区的 SHA-256。页面按 `presentation.xml` 及关系表的实际顺序读取，从封面计数，保留隐藏页与空白页，不以 `slideN.xml` 文件名或大纲节号代替页码。页码越界、来源不明、版本冲突、文件变更、多页/范围请求和超限读取在发送前返回安全提示。

当前问答入口与旧 `createDraft` 入口均做本地预检，并保存仅主进程使用的页面查询。旧版普通问答草稿可从可信原始用户消息重新定位页面；内部文档生成 Prompt 不用作页码读取指令。兼容旧消息将内部 Prompt 保存在 `content`、用户原句保存在 `displayContent` 的结构，避免把生成/修订误路由为页问答。授权范围包含目标页 Hash，发送前重新读取并核对；页码问答排除历史大纲、旧附件和其他项目资料，仅发送目标页引用与当前问题。若上下文预算删掉或截断目标页，则停止请求，不用残缺页面回答。
