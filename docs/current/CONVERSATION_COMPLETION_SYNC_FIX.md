# 回复完成后的会话版本同步修复

日期：2026-09-10。按负责人“发现新的问题”截图继续维护现有对话链路，依据 AGENTS.md 顶部维护决策及 PLANS.md，不恢复历史阶段计划。修改范围为 ChatPage、会话流式结果保存和相应回归测试。

## 问题与根因

图片分析已经成功，但继续发送“生成提示词”时提示“内容已在其他位置更新，请刷新后重试”。会话关联生命周期原先先调用 `lifecycle.complete()`，发布完成事件，再保存助手消息终态。界面在收到事件后读取会话，可能取得保存前的版本；下一条 workflow 直接使用该旧 revision，触发真实的乐观锁冲突。旧异步会话快照也可能覆盖较新版本。

## 实际实现

- 先排空回复增量、保存助手消息完成状态，再记录及发布执行完成事件；本地保存失败不提前通知成功。这样实时订阅和完成事件重放均只能在终态保存后看到完成。
- 普通新消息和澄清回答在提交前读取最新会话版本，并继续保留后台乐观锁校验。同步失败保留输入；同步期间取消则不提交，已归档/只读状态不继续发送。
- 单会话更新和窗口聚焦刷新均不允许较低版本覆盖已加载的较高版本。
- 不自动重放可能已经受理的写请求；真正的并发修改仍显示冲突并保留输入，避免重复消息或重复执行。

实现提交：`b008d31`；分支 `feature/conversation-completion-sync`，从本地 develop 创建并保留。
