# 项目删除与失效记录清理（2026-10-19）

本轮响应负责人“项目删除的功能没有，失效的项目也不能删除”的截图反馈。属于维护优化，依据最新负责人要求、AGENTS.md、PLANS.md 顶部维护记录和当前源码；继续现有 feature/www-model-binding-repair-20261019 分支，保留此前启动、合同绑定和视频接收修复，不覆盖交接原件。

## 实际问题与修改

底层 ProjectCatalogService 已有 remove，但 Storage API、preload、Host IPC 和产品界面未接通。实际“项目”一级入口显示 ChatPage，ProjectsPage 位于其“管理项目”弹窗，因此同时补齐以下入口：

- 项目侧栏每行的“…”菜单，失效项目的菜单独立于禁用的打开按钮。
- “管理项目”中的项目卡片，拆开打开按钮和删除按钮，避免按钮嵌套。
- 作品库“部分项目无法读取”中每条问题旁的“移除记录”。问题较多时限制列表高度并支持滚动。

共用确认框默认选择“仅从列表移除”，保留本地项目内容；有效项目还可选择“同时移到系统回收站”。失效或损坏提示仅提供记录清理，不要求原目录存在、挂载或可读。移除可通过“打开项目”重新加入。目录权限等 stat 失败现在使单条项目显示不可用，不再让整个最近项目列表失败。

Host 仅接受项目 ID 与 forget/trash 枚举，不接受 Renderer 路径。移除与打开、创建、关闭共用会话队列；清理当前项目先等待既有会话变更门禁，目录清单写入成功才清空会话。清理其他项目不会切换当前项目。删除后主动使读模型失效、同步监听器并通知项目列表、标题栏和存储监控刷新。

回收站操作要求项目已关闭，拒绝路径别名、符号链接、项目身份不符、受保护目录、包含其他登记/当前项目的目录，以及未结束或未知结果的执行/调用和活动对话响应。只调用系统 shell.trashItem，不使用永久递归删除。回收站不可用或失败时保留清单，允许改选仅移除记录；文件已经进入回收站但清单保存失败时，仍可清理残留记录。重复移除不会再次猜测路径或执行文件删除。

允许修改范围为项目管理、共用确认框、Storage IPC/preload、目录清单/会话控制、受控回收站校验、刷新事件和样式，以及对应测试、验证脚本和维护证据。没有改模型配置或继续调用模型。
