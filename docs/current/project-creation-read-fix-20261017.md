# 新建项目后的本地保存失败误报

日期：2026-10-17。当前为既有功能维护，依据负责人本次截图反馈、AGENTS.md、PLANS.md 顶部维护事实及当前源码；没有恢复历史阶段。范围为项目会话列表读取适配器、相关回归、隔离 Electron 脚本和维护记录。权威 UI 原件未修改；本轮不涉及视觉改版，也不声明缺失交接包的一致性验收。

## 原因

只读检查截图所示项目，project.json 与本机项目目录清单的项目 ID 一致，manifest 已成功落盘。原 ThreadFileReadAdapter.listThreadSummaries 在没有当前项目时也调用 requireRepository，抛出 thread_file_read_disabled 并映射成 storage_error。ChatPage 初次载入、window focus 及项目切换都会刷新列表，并将此错误统一显示为“本地保存失败，请检查存储状态后重试。”成功的后续列表读取不会移除此旧提示。

创建项目会打开原生目录选择器。返回焦点与项目会话登记之间允许一次无项目列表刷新，因此保存成功仍可能留下错误提示。对 Git HEAD 原始适配器在内存中编译复现，同样的无项目输入得到 storage_error；本轮构建得到成功的空列表，详见 reproduction.json。没有将该现象归因于磁盘不足或认定整个存储链路损坏。

## 修改

- src/platform/ipc/thread-file-read-adapter.ts：没有项目、没有仓储且没有分页游标时返回成功的空列表；有项目的真实读取错误仍保留。
- tests/platform/thread-file-read-adapter.test.ts：补充启动空态、目录选择返回焦点、新建项目 manifest、首条消息持久化、重建 Runtime 读回及关闭项目后的空态；另验证损坏的项目索引仍失败。
- scripts/verify-project-creation-electron.cjs：加载实际生产 main/preload/renderer，使用独立临时配置、受控目录选择和焦点事件操作真实新建项目界面；本地 IPC 保存首条消息，关闭再打开项目后读回。隐藏测试窗口，阻断并计数 HTTP(S) 外发；覆盖默认 Thread 及显式 Legacy 模式。
- PLANS.md：保留已有内容，新增本轮维护结果。

未覆盖原有会话/文档修改，没有切换分支或提交/合并/推送。用户目录和目录清单仅按故障范围只读检查，未修复性写入或删除用户资料。

## 验证

类型检查、全仓 lint、生产构建、Node/UI 合同 401/401 通过。定向 Vitest 两组为 42/42 和 99/99，重复的 Thread 读取适配器 7 项只计算一次，共 9 文件 134 项通过；零最终失败或跳过。不是本轮全量 Vitest 验收。

默认 Thread、显式 Legacy 的隔离真实 Electron 流程均通过：无项目读取、目录返回焦点、新建项目界面和当前项目显示、manifest/catalog 校验、首条消息保存、关闭项目后读取空列表、重开后读回原消息，无“本地保存失败”提示。消息验证通过本地 IPC，不调用真实生成服务。两个模式外部请求均为 0；临时项目不登记到用户配置。

初次回归的损坏索引夹具漏写 entities 子目录，首条消息请求夹具又带入合同不接受的 attachments 字段；纠正夹具后重新通过。Electron 脚本首次异步准备导致主进程加载晚于 ready，改为同步 bootstrap；新增 DOM 检查时的错误选择器亦已修正并重验。这些中间失败均未被描述为通过，可用日志保留在机器证据压缩包，其余失败说明保留于本段及工具执行记录。隐藏窗口的中间截图存在合成帧滞后，最终脚本不再产出或使用这些截图作为验收证据；采用实际 DOM、IPC 和物理文件断言。

## 生效及边界

本轮没有主动关闭或重启用户窗口。主进程修复需在本目录下次启动 pnpm dev 后生效；已经保存的项目可直接打开，无需重建或重复创建。本轮没有真实 Provider、收费、联网搜索、全量 Vitest 或 macOS 实机验收。后续仅需加载修复后核对原操作；若仍有提示，应按实际错误重新定位，不将真实存储失败掩盖成空列表。

测试 Electron 进程已退出。Windows 缓存句柄使脚本退出前的临时配置清理未能完成；退出后的宽范围清理及缩小到已核对固定目录的清理均被自动审批以 blocked by policy 拒绝。8 个本轮隔离测试临时目录暂保留，不是用户项目；未改用其他删除方式绕过拒绝，不影响功能验收。
