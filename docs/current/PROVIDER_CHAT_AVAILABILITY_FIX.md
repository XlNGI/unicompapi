# 模型配置遮挡与对话不可用维护记录

日期：2026-09-11。依据负责人两张截图及“分析业务逻辑，需要优化就优化”，按当前维护规则在 `feature/provider-chat-availability-fix` 分支实施。范围为模型管理布局、对话候选读取、旧文档任务兼容、相关回归与本记录。

## 已确认原因

1. 模型概要原为 `position: fixed; bottom: 0` 的紧凑底栏，加入完整搜索表单后高度增加，覆盖模型目录并与全局任务栏重叠。搜索表单对图片模型同样显示，默认选中 Kimi，切换模型还保留上一个模型的未保存值。
2. 当前项目 59 条历史 workflow 中有一条旧 CRUD `documentCommand` 残留，主文件与备份均有该字段。当前严格解析器拒绝旧字段，导致项目启动恢复 Promise 拒绝；候选列表又等待该恢复，随后把异常显示为“本地保存失败”，同时显示“0 个可用”。会话 66 条和响应执行 96 条本身可解析，不能将此归因于磁盘空间不足。
3. 只读现有 registry 和运行授权台账，以真实候选代码核对得到普通对话 17/17、深度推理 14/14 可用。目录“已启用”只代表模型开关，候选仍依赖精确功能配置、协议绑定和授权；图片/视频模型不会作为文本候选。

旧字段与 `docs/current/CHAT_PROVIDER_REJECTION_FIX.md` 已登记的 CRUD 残留一致；当前 Git refs 中没有对应引入实现，无法确认具体引入提交。未读取历史归档或真实凭证，也未发起真实模型/搜索调用。

## 实际变更

- 模型概要回到目录正常内容流；文本模型的联网设置默认折叠，图片/视频模型不再显示。协议无声明时不预选；切换模型按该模型已保存值回填或清空草稿。明确设置仅适用于当前连接下当前模型，保存不等于授权联网。窄窗口模型列允许名称收缩，避免功能文字与启用标记重叠。
- 仅兼容实际观察到的旧 `recreate / choose_target / 空候选` 元数据，要求 `chat`、`ready/cancelled` 且没有目标、执行、交付、确认或授权状态。保留原始请求和字段，将当前读取状态投影为 `cancelled`，防止重放旧命令；未知结构和带执行状态的旧记录仍拒绝。读取不改文件，后续正常仓储写入保留旧请求元数据。
- 纯模型目录查询不再等待项目历史任务恢复；响应写入和执行仍须通过原恢复门禁。恢复 Promise 创建时立即观察异常，保留原始拒绝状态，避免未处理的拒绝。
- 普通/推理候选分别处理成功和失败；一类失败不会吞掉另一类成功结果。读取失败显示明确提示和“重新加载模型”，不再误报为保存失败或真实空目录；重试保留输入。
