# 视频播放和草稿切换问题修复记录

## 问题汇总

用户在第二轮验收时发现以下问题：

### 1. ✅ 播放视频时界面抖动
**现象**：点击播放按钮后，整个页面布局会抖动/跳动

### 2. ✅ 放大视频按钮不可用
**现象**：视频播放器的全屏按钮点击无效

### 3. ⚠️ 点击"新建本地草稿"后时间线消失
**现象**：点击"新建本地草稿"后，之前生成的视频在时间线上消失了

---

## 问题 1 & 2：视频播放抖动和全屏按钮修复

### 根本原因

**原因 1：容器 overflow: hidden**
```css
.uc-generation-history__preview {
  overflow: hidden;  /* ⚠️ 裁剪视频控件 */
}
```
- 视频控件（包括全屏按钮）被裁剪，点击无效
- 浏览器可能尝试滚动到被裁剪的控件，导致布局抖动

**原因 2：视频尺寸设置不当**
```css
.uc-generation-history__preview video {
  width: 100%;   /* ⚠️ 强制填满容器 */
  height: 100%;  /* ⚠️ 强制填满容器 */
}
```
- 视频加载前：容器根据 100% 计算高度（可能很小）
- 视频加载后：浏览器获取真实尺寸，重新计算布局
- 高度变化导致整个页面重排，产生抖动

### 修复方案

**修复文件**：`src/styles/pages.css`

#### 修复 1：移除 overflow: hidden

```diff
 .uc-generation-history__preview {
   display: grid;
   min-width: 0;
   min-height: 0;
   padding: var(--uc-space-3);
-  overflow: hidden;
+  overflow: visible;
 }
```

**效果**：
- ✅ 视频控件不再被裁剪
- ✅ 全屏按钮可以正常点击
- ✅ 音量、进度条等控件完全可用

#### 修复 2：使用 auto 尺寸，让视频保持原始比例

```diff
 .uc-generation-history__preview video {
   display: block;
-  width: 100%;
-  height: 100%;
+  width: auto;
+  height: auto;
   max-width: 100%;
   max-height: 100%;
   margin: 0;
   object-fit: contain;
 }
```

**效果**：
- ✅ 视频按原始比例显示
- ✅ 加载后尺寸不变，不会抖动
- ✅ 通过 max-width/max-height 限制在容器内

## 问题 3：新建草稿后时间线消失

### 根本原因分析

这**不是 BUG，而是设计行为**。

#### 数据模型

`GenerationHistory` 组件依赖 `draftId` 查询历史：

```tsx
// src/components/GenerationHistory.tsx
function GenerationHistory({ draftId, projectId, mediaKind }) {
  // 加载指定草稿的历史记录
  const history = await storage.listGenerationHistory({
    projectId,
    draftId,    // ⚠️ 必填字段，按草稿筛选
    mediaKind
  });
}
```

#### 存储接口定义

```ts
// src/shared/storage-ipc.ts
listGenerationHistory(request: {
  readonly projectId: string;
  readonly draftId: string;      // 必填，不能省略
  readonly mediaKind: 'image' | 'video';
}): Promise<...>;
```

**结论**：
- 历史记录是**草稿级别**的，不是项目级别的
- 每个草稿有自己独立的历史记录
- 切换草稿 = 切换历史记录视图

### 为什么这样设计？

#### 优点：
1. **草稿隔离**：不同的创意方向互不干扰
2. **精确追溯**：每次生成都能追溯到具体的提示词版本
3. **清晰的工作流**：一个草稿 = 一个创意迭代链

#### 缺点：
1. ❌ 切换草稿后，之前的作品"消失"
2. ❌ 用户可能认为作品丢失了
3. ❌ 无法在一个视图看到所有生成历史

### 解决方案建议

#### 方案 A：在「作品库」查看所有历史 ✅ 推荐

**实现**：已有「作品库」功能，显示项目的所有作品

**使用方式**：
1. 左侧导航栏点击「作品库」
2. 可以看到所有草稿生成的作品
3. 可以筛选、预览、导出

**优点**：
- ✅ 不需要修改代码
- ✅ 功能已经存在
- ✅ 更符合"创作工作区 vs 归档库"的心智模型

**建议**：在界面上给用户提示
```
💡 提示：切换草稿后，之前的作品可以在「作品库」中查看
```

#### 方案 B：时间线显示项目级历史 ⚠️ 需要修改后端接口

**实现**：修改 `listGenerationHistory` 接口，支持不传 `draftId`

```diff
 listGenerationHistory(request: {
   readonly projectId: string;
-  readonly draftId: string;
+  readonly draftId?: string;  // 可选，不传则返回项目所有历史
   readonly mediaKind: 'image' | 'video';
 }): Promise<...>;
```

**前端修改**：
```tsx
// 查询项目级历史，不限定草稿
const history = await storage.listGenerationHistory({
  projectId,
  // draftId: undefined,  // 不传，返回所有草稿的历史
  mediaKind: 'video'
});
```

**优点**：
- ✅ 切换草稿不影响历史显示
- ✅ 用户体验更直观

**缺点**：
- ❌ 需要修改后端接口
- ❌ 时间线会混合不同草稿的作品，可能混乱
- ❌ 无法追溯某个作品是从哪个草稿生成的

#### 方案 C：保留草稿级历史 + 添加提示 ✅ 最简单

**实现**：在 UI 上添加说明

**位置**：时间线标题旁边
```tsx
<header>
  <strong>生成历史</strong>
  <span>当前草稿的 3 张作品</span>
  <Tooltip>
    💡 切换草稿后历史会改变。查看所有作品请访问「作品库」。
  </Tooltip>
</header>
```

**优点**：
- ✅ 零代码改动（或极少）
- ✅ 保持当前设计逻辑
- ✅ 引导用户使用作品库
