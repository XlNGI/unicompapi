# 统一视频与生图右侧工作台布局及生成交互规范方案 (V2.0)

> 文件路径: `docs/fixes/统一视频生成布局修复方案.md`  
> 适用模块: 图生视频 (`VideoImageWorkspace`)、文生视频 (`VideoTextWorkspace`)、专业生图 (`ImageProfessionalWorkspace`)、生成历史组件 (`GenerationHistory`)

---

## 一、问题现状与截图深度对比

根据用户最新提供的 3 张运行实测截图排查，发现以下核心痛点：

### 痛点 1：生成中主舞台仍残留旧视频，导致感知上“没有在生成视频”
- **截图 1 现象**：左侧已经处于“2 提交中 / 处理中”，右侧下方时间线最新出现了一个“生成中”转圈卡片，但右侧上方主播放器**依然在全屏播放今天 09:44 生成的历史旧视频**！
- **截图 2 现象**：在另一种情况下点击生成，右侧上方却又变成了大 Spinner 提示“正在生成视频 / 完成后自动登记到本地”。
- **根本原因排查**：
  在 `src/components/GenerationHistory.tsx` 中：
  ```tsx
  const selectedWork = works.find((work) => work.workId === selectedWorkId);
  const previewWorkId = selectedWorkId ?? completedWorkId;
  const generationInFlight = livePendingPhases.has(submissionProgress.phase) || ...;
  // 缺陷代码：只要先前选过某个历史作品，previewWorkId 就存在，导致 showLoadingPreview 为 false！
  const showLoadingPreview = generationInFlight && !previewWorkId;
  ```
  **逻辑冲突**：用户在点击生成前，时间线上默认选中了上一件历史作品（或者用户刚刚预览过某张历史作品）。触发新生成后，`previewWorkId` 仍然存在，导致上方主舞台依然播放老作品，只有下方时间线出现转圈。用户第一眼看过去上方毫无生成反馈，误以为“根本没在生成视频”，状态极度混乱割裂！

---

### 痛点 2：DOM 结构与外层容器类名不统一
- **文生视频 (`VideoTextWorkspace.tsx`)**：
  ```tsx
  <Card
    aria-label="生成过程与作品区域"
    className="uc-generation-two-pane__result uc-image-professional__after-pane"
  >
    <GenerationHistory ... />
  </Card>
  ```
- **专业生图 (`ImageProfessionalWorkspace.tsx`)**：
  ```tsx
  <Card
    aria-label="生成过程与作品区域"
    className="uc-image-professional__after-pane"
  >
    <GenerationHistory ... />
  </Card>
  ```
- **图生视频 (`VideoImageWorkspace.tsx`)**：
  ```tsx
  <Card
    aria-label="生成过程与作品区域"
    className="uc-generation-two-pane__result uc-generation-two-pane__output uc-image-professional__after-pane"
  >
    <header className="uc-image-professional__pane-heading">
      <span aria-hidden="true">2</span>
      <div>
        <h2>第二步 · 生成过程与作品</h2>
        <p>提交状态与通过本地校验的作品会保留在这里。</p>
      </div>
    </header>
    <div className="uc-video-image__canvas">
      <GenerationHistory ... />
    </div>
  </Card>
  ```
- **冲突根源**：
  1. 多了 `uc-generation-two-pane__output` 类（该类在 CSS 中自带 `grid-template-rows: auto minmax(0, 1fr)`，破坏了内部网格）；
  2. 多了 `<header>` 标题头（虽然可能隐藏或折叠，但在 DOM 树中占位）；
  3. 多套了一层 `<div className="uc-video-image__canvas">`，而在 `src/styles/pages.css` 中 `.uc-video-image__canvas` 定义了 `align-content: start;`，这导致内部 `GenerationHistory`（原本为 100% 弹性高度的 grid）无法撑满父级 Card，右侧布局与文生视频彻底不一致。

## 二、全面对齐改造方案

### 1. 结构与容器 100% 对齐（图生视频 → 文生视频/专业生图标准）
修改 `src/pages/creation/video/VideoImageWorkspace.tsx`：
- 彻底移除多余的 `<header>` 和 `<div className="uc-video-image__canvas">`；
- Card 样式类统一定义为 `uc-generation-two-pane__result uc-image-professional__after-pane`；
- 直接挂载 `<GenerationHistory />`，内部网格自主管理高度撑满与自适应，实现图生视频、文生视频、专业生图三端完全一致的 DOM 体系。

### 2. 生成中（In-flight）交互与主舞台反馈统一
修改 `src/components/GenerationHistory.tsx`：
- **生成态优先与焦点调度**：
  当处于 `generationInFlight`（即提交中、请求中、等待生成）时：
  1. 若用户在**本次生成期间尚未主动点击其他历史作品**（即 `!userTookOverRef.current`），主舞台必须**强制优先展示当前生成的 Loading 进度态**（“正在生成视频 / 完成后将校验并登记到本地”），且标题头显示“正在生成”，绝不继续播放旧历史作品！
  2. 下方时间线上的当前生成中卡片（`node.kind === 'pending'`）自动获得激活指示，形成“上方加载动效 + 下方时间线生成中”的强一致视觉关联。
  3. 若用户在生成过程中**主动点击了某张历史作品**（查看过往成果），则切换到该历史作品预览（尊重用户的浏览意图）；一旦再次发起新生成，状态重新聚焦到当前进行中的任务。
  4. 生成完成并通过本地落库校验后，通过已有的 `expectedWorkId` 与自动选中逻辑，将主舞台无缝切换到刚生成好的本地全新作品！

## 四、验证标准

1. **静态契约与编译校验**：
   - 执行 `npm run typecheck` 零错误；
   - 执行 `npm run lint` 零错误；
   - 执行 UI 契约测试零回归。
2. **交互行为验收**：
   - 图生视频、文生视频在未生成时，默认选中最新作品并全高展示；
   - 点击“生成”瞬间，无论此前是否选中过旧作品，右侧上方立即统一进入“正在生成”主舞台态，下方时间线同步高亮“生成中”节点；
   - 生成完成落库后，主舞台平滑自动切换为最新生成的视频播放器；
   - 图生视频与文生视频右侧外框边距、背景、时间线尺寸与网格高度像素级一致。
