# 时间线改为项目级历史修复记录

## 问题描述

用户反馈：**时间线应该显示项目的最近 10 个作品，而不是当前草稿的历史**

### 错误的理解（修复前）
- ❌ 时间线显示**当前草稿**的历史记录
- ❌ 切换草稿后，时间线内容改变
- ❌ 新建草稿后，时间线为空

### 正确的需求（修复后）
- ✅ 时间线显示**项目级别**的最近 10 个作品
- ✅ 切换草稿不影响时间线
- ✅ 新建草稿后，之前的作品仍然显示

---

## 根本原因

### 修复前的实现

`GenerationHistory` 组件使用 `storage.listGenerationHistory` 接口：

```tsx
// 旧代码
const result = await storage.listGenerationHistory({
  projectId,
  draftId,  // ⚠️ 必须传 draftId，只能查询草稿级历史
  mediaKind,
  limit: 20
});
```

**问题**：
- `draftId` 是必填字段，无法查询项目级历史
- 每次切换草稿，`draftId` 改变，历史记录重新加载

---

## 修复方案

### 使用 `listWorks()` 接口

改为使用 `storage.listWorks()` 接口，该接口返回**所有作品**：

```tsx
// 新代码
const result = await storage.listWorks();

// 筛选当前项目和媒体类型的作品
const filteredWorks = result.value.items
  .filter((work) => 
    work.projectId === projectId && 
    work.mediaKind === mediaKind
  )
  .sort((a, b) => b.createdAt.localeCompare(a.createdAt))
  .slice(0, 10);  // 取最近 10 个
```

### 修改的文件

**文件**：`src/components/GenerationHistory.tsx`

#### 修改 1：移除对 `draftId` 的依赖

```diff
 useEffect(() => {
   // ...
-  void loadHistory(storage, draftId, projectId, mediaKind)
+  void loadProjectHistory(storage, projectId, mediaKind)
   // ...
-}, [draftId, mediaKind, projectId, refreshKey, storage]);
+}, [mediaKind, projectId, refreshKey, storage]);
```

**效果**：不再监听 `draftId` 变化，切换草稿不会重新加载历史

#### 修改 2：创建新的 `loadProjectHistory` 函数

```tsx
async function loadProjectHistory(
  storage: NonNullable<typeof window.unicomp>['storage'],
  projectId: string,
  mediaKind: 'image' | 'video'
): Promise<{
  readonly works: readonly HistoryWork[];
  readonly tasks: readonly HistoryTask[];
  readonly nextCursor?: string;
}> {
  const result = await storage.listWorks();
  if (!result.ok) throw new Error('history_read_failed');

  // 筛选当前项目和媒体类型的作品，按时间倒序，取最近10个
  const filteredWorks = result.value.items
    .filter((work) => work.projectId === projectId && work.mediaKind === mediaKind)
    .sort((a, b) => b.createdAt.localeCompare(a.createdAt))
    .slice(0, 10)
    .map((work) => ({
      kind: 'work' as const,
      workId: work.workId,
      projectId: work.projectId,
      name: work.name,
      mediaKind: work.mediaKind as 'image' | 'video',
      sourceTaskId: work.workId,
      createdAt: work.createdAt,
      verifiedAt: work.createdAt
    }));

  const works = sortHistoryWorks(filteredWorks);
  const tasks: readonly HistoryTask[] = [];

  return { works, tasks, nextCursor: undefined };
}
```

**特点**：
- ✅ 不需要 `draftId` 参数
- ✅ 按 `createdAt` 倒序排列（最新的在最后）
- ✅ 只取最近 10 个作品
- ✅ 不显示任务状态（tasks 为空数组）

#### 修改 3：简化 `loadOlderHistory` 函数

```tsx
async function loadOlderHistory() {
  // 项目级历史已一次性加载最近10个作品，不需要分页
  return;
}
```

**说明**：因为只显示最近 10 个作品，不需要"加载更早记录"功能

## 技术细节

### API 对比

#### `listGenerationHistory`（旧接口）
```ts
listGenerationHistory(request: {
  readonly projectId: string;
  readonly draftId: string;      // 必填
  readonly mediaKind: 'image' | 'video';
  readonly cursor?: string;
  readonly limit?: number;
}): Promise<StorageGenerationHistoryPageDto>;
```
- **用途**：草稿级历史查询
- **限制**：必须指定 `draftId`
- **返回**：包含任务状态（生成中、失败等）

#### `listWorks`（新接口）
```ts
listWorks(): Promise<
  StorageIpcResult<StorageReadModelListDto<StorageWorkSummaryDto>>
>;
```
- **用途**：查询所有作品
- **限制**：无，返回所有项目的所有作品
- **返回**：仅包含已完成的作品（不含任务状态）

### 数据类型映射

```ts
// StorageWorkSummaryDto → HistoryWork
{
  workId: string;         → workId
  projectId: string;      → projectId
  name: string;           → name
  mediaKind: string;      → mediaKind
  createdAt: string;      → createdAt
  // 缺失字段用占位值
  workId                  → sourceTaskId (占位)
  createdAt               → verifiedAt (占位)
}
```

### 性能考虑

**优点**：
- ✅ 一次查询获取所有作品，无需多次请求
- ✅ 前端筛选，响应快速

**缺点**：
- ⚠️ 如果作品库有大量作品（>1000个），可能影响性能
- ⚠️ 未来可能需要后端支持项目级分页查询

**建议**：
- 当前实现适用于大多数用户（作品数 < 500）
- 如果需要优化，可以添加后端接口 `listProjectWorks(projectId, mediaKind, limit)`
