## 一、批准边界

本支只实现 ProviderInvocationAttempt/Event、UsageSchema、ProviderUsageObservation/Summary、LocalResultObservation、项目级原子仓储和媒体/文本统一安全读投影。未修改 React、preload、Electron 页面、RouteSnapshot、提交编排、协议适配器、历史数据、阶段 10 或 macOS 实机目标。

本支禁止真实服务商 HTTP、真实凭证读取/验证和收费调用。Vidu 两项已用尽预算继续封存，Image V1 未验证事实不变。

## 二、实际实现

- 新增媒体与文本统一的 `ProviderInvocationAttemptV1`，分别关联 `taskId + executionId` 或 `conversationId + userMessageId + responseExecutionId`，并固定 RouteSnapshot 引用、显式重试来源和八类调用状态。
- 新增单调、连续、可重建的 `ProviderInvocationEventV1` 时间线；首事件必须为 `submission_started`，重复 event ID/sequence 内容相同保持幂等，冲突或非法状态转换拒绝。
- attempt 在提交前建立；请求字节写出前失败进入 `failed_before_submission`，未知提交结果进入 `unknown_outcome`，终态不可继续追加普通事件；显式重试必须引用同一 subject 的终态 attempt。
- 新增版本化 `UsageSchemaV1`、metric 白名单、单位/数字种类/允许阶段、四类聚合策略和完整性规则；未知 metric、单位、阶段、非法十进制或额外响应字段均拒绝。
- `final_authoritative` 取最高权威阶段的最终值，`cumulative_latest` 取最大 sequence，`delta_sum` 只累加不同本地 sourceEventKey，`first_reported` 后续冲突标记异常。
- 同一 sourceEventKey 内容相同保持幂等，内容冲突保留旧观察并追加 `invalid_response` 标记；ProviderUsageSummary 由 Schema 统一计算完整、部分、未返回、未知、不适用和历史未采集状态。
- 新增独立 `LocalResultObservationV1` 和项目级原子仓储，只记录本地输出数量、媒体属性与校验状态，不把请求规格、价格推导、路径、Hash 或远端响应混入用量。
- 新增媒体/文本统一只读调用投影，只公开 subject、脱敏时间线、用量汇总和本地结果属性；不公开 RouteSnapshot、endpoint、Prompt、远端 operation ID、签名 URL、绝对路径、Hash 或原始响应。
