### 1. Chat Completions（`POST /v1/chat/completions`）

官方请求字段：`model`、`messages`、`temperature`、`top_p`、`n`、`stream`、`stream_options`、`stop`、`max_tokens`、`max_completion_tokens`、`presence_penalty`、`frequency_penalty`、`logit_bias`、`user`、`tools`、`tool_choice`、`response_format`、`seed`、`reasoning_effort`、`modalities`、`audio`。

核对结论：

- 已覆盖：model/messages/stream/stream_options/temperature/top_p/n/stop/max_tokens/max_completion_tokens/presence_penalty/frequency_penalty/seed/user/tool_choice/response_format/reasoning_effort。
- 本轮新增：`logit_bias`（object）进入 UniCompAPI 专用文本 Schema 并被序列化。
- 有意不暴露：`tools`（当前参数 Schema 类型不支持 array-of-object，且产品无工具调用入口）、`modalities`/`audio`（多模态，超出项目边界）、`stream`（产品对话固定流式，适配器控制）。
- 有意移除暴露/发送：`thinking`、`chat_template_kwargs`、`enable_thinking`、`top_k`、`metadata`、`parallel_tool_calls`——这些不在 UniCompAPI 公开合同内；DeepSeek 事故（`thinking` 被网关以 `newapi.invalid_response` 拒收）证明网关对未公开字段失败关闭，不再猜测发送。

### 2. 图像生成（`POST /v1/images/generations`）

- 原生 OpenAI 格式官方字段：`model`、`prompt`、`n`、`size`；已覆盖，另按模型 Schema 开放 quality/style/response_format/output_format/watermark 等服务商扩展。
- 通义千问格式（qwen-image 族）官方示例字段：`model`、`input.messages`、`parameters.negative_prompt`、`parameters.prompt_extend`、`parameters.watermark`、`parameters.size`；当前 qwen-image Schema 的字段集合（size/negative_prompt/prompt_extend/watermark/seed）与官方一致，但外层仍按 OpenAI 兼容 JSON 发送（`prompt` + 顶层字段）。该信封形态属冻结的新api.image 适配器行为，真实网关接收形态尚未验证，本轮不重写适配器，保留为后续真实合同验证项。
- `POST /v1/images/edits` 对 UniCompAPI 已按负责人决策迁移为 reference_to_image / generations，历史 image_edit 不再挂载。

### 3. 视频创建（`POST /v1/videos`）

- 官方 Sora 格式为 `multipart/form-data`：`model`、`prompt`、`seconds`、`input_reference`（文件）。
- 当前 newapi.video 使用 JSON 信封，已覆盖 model/prompt/duration/seconds；图生视频使用 `image`（受控 Base64 data URL）而非 `input_reference`。真实 Vidu/HappyHorse 经 newapi.video 成功记录证明 JSON 信封对当前目录模型有效，本轮不改为 multipart；差异作为已知边界登记。
- 参数白名单（duration/seconds/resolution/size/ratio/audio/watermark/seed/fps 等）继续由 Profile Schema 控制；`n`/`response_format`/`user`/任意 extensions 不在当前目录模型 Schema 内，不暴露。

## 二、实施修改

1. UniCompAPI 封闭世界路由（`unicompapi-model-capabilities.ts`、`openai-compatible-video-routing.ts`、`provider-registry-feature-candidates.ts`、`provider-management-framework.ts`）：未知模型 key 不再自动挂载 text_chat/text_reasoning/text_to_image/text_to_video/image_to_video，也不进入功能候选；必须显式补充能力表、Schema、路由测试后启用。
2. UniCompAPI 专用文本 Schema（`unicompapi-model-capabilities.ts`）：`parameters.unicompapi.text_chat.official`、`parameters.unicompapi.text_reasoning.official`（revision 1），只含官方字段并新增 `logit_bias`。
3. 接线：`project-text-feature.ts`（对话文本 Schema 解析器）、`provider-management-framework.ts`（文本 Profile 定义挂载）、`prompt-once-text-adapter.ts`（提示词增强路由校验与解析）改为使用 UniCompAPI 专用 Schema。
4. DeepSeek V4 `reasoning_effort` 特判收敛：新增 `isUniCompApiDeepSeekV4Model()` 能力表助手，`newapi-chat-adapter.ts` 不再写死模型名列表；行为不变。
5. 常量与清理：`newapi-video-adapter.ts`、`provider-management-framework.ts` 的字面量 `'provider-package-unicompapi'` 改为常量；删除未使用的 `isUniCompApiViduModel`。
6. 测试：未知 UniCompAPI 模型零 Profile（capabilities/视频路由/管理框架）；UniCompAPI 文本请求只序列化官方字段且 `logit_bias` 透传、`thinking` 等非官方字段在 HTTP 前被拒。
