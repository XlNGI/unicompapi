## 一、允许范围

本流程只修改 Execution/Task 生命周期、图片与视频操作提交端口、提交控制器、Provider 操作收据仓储、异步查询/取消/恢复端口、对应测试和工程记录。未实现 Vidu HTTP、共享运行时、协议适配器、真实 Token、真实联网或收费生成。

## 二、实际修改

1. 建立 `accepted_async`、`completed_sync`、`submission_outcome_unknown` 与 `failed_before_submission` 严格判别联合，并把提交结果冻结到不可变 `ProviderOperationRecord`。
2. 新增项目范围 `provider-operations.json` 仓储，包含显式 Schema v1→v2 迁移、严格运行时校验、串行写入和既有原子 JSON 写入边界；一个 Execution 只能关联一份不可变收据。
3. 同步结果只在主进程私有收据中保存 URL、base64 或 file URI；Execution 只关联受控收据 ID，不向 renderer 返回结果正文、远端 operation ID 或仓储位置。
4. 收据先于 Execution 状态更新落盘。若进程在两次写入之间退出，恢复服务可以依据不可变收据幂等补齐 `remote_completed`、异步排队或失败状态。
5. 异步端口支持 provider operation 查询、完成、失败、过期、取消、取消仍处理中和取消结果未知，不包含任何 HTTP 实现。
6. 请求可能已经送达但响应事实不确定时进入 `submission_outcome_unknown`，收据固定 `automaticRetryCount: 0`；领域状态机及图片/视频提交控制器均拒绝在同一 Task 上普通重试。
7. 图片和视频控制器统一持久化 Provider 收据并依据模型协议绑定选择同步或异步生命周期；保留旧提交端口返回形状的兼容迁移，后续协议适配器可以直接返回新的判别联合。
8. renderer 错误契约只增加稳定 `submission_outcome_unknown`，页面仅显示真实阻断提示，不泄露路径、凭证、endpoint、结果引用或内部错误。
