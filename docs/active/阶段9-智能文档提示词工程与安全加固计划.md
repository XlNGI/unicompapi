# 阶段 9｜智能文档提示词工程与安全加固计划

日期：2026-09-03

状态：`in_progress/pr-a_implementation`

适用范围：阶段 9 收口基线之上的智能文档工作流扩展。本文是工程侧计划，不改写阶段 9 历史验收结论，不表示下列能力已经实现。

## 一、背景与目标

当前智能文档扩展已经具备部分本地意图规则、文档大纲 Schema、BM25 资料检索、受控工具合同、临时版本和原子发布合同。近期反馈与代码审查表明，提示词工程与安全边界仍存在跨层风险：资料通过 `user` 消息注入而非系统级规则，修订异常存在继续采用模型全量大纲的路径，否定句可能触发破坏性动作，章节与页面共用序号模型，未识别请求缺少 LLM 结构化兜底，必需资料检索失败仍会继续生成，结构化输出仍允许任意 Markdown 降级。

本计划目标：

1. 让模型只负责受控的语义理解、内容建议和结构化计划，不让资料改变任务、安全规则或工具权限。
2. 让局部修订在任何失败、歧义、冲突或越权情况下 fail-closed，禁止静默采用模型全量修改。
3. 让章节、页面、表格、单元格和块级目标具有清晰且可验证的语义，不再复用一个含义不明的 ordinal。
4. 让高置信度本地规则、低置信度 LLM 分类和用户追问形成明确三态闭环。
5. 让资料依赖、结构化输出、渲染验证和发布登记拥有可审计的状态与失败码。

## 二、基线与边界

### 已保留的架构原则

- 本地规则优先处理高置信度明确请求；复杂、复合或歧义请求才调用 LLM。
- LLM 输出封闭 Schema 的计划或大纲；Application 负责 Schema、实体、权限、项目范围、费用和状态校验；Platform 负责白名单工具执行。
- 高置信度编辑使用“本地规则 + 固定工作流”；开放式编辑使用“LLM 候选计划 + 受控工具调用”。当前 `runDocumentAgentLoop` 的本地修订路径属于后者中的固定状态机，不应描述为 LLM 自主调度。
- 企业资料优先本地 RAG，BM25 保持保底；联网搜索只在用户明确授权且满足外发边界时启用。
- 正式 Work 必须通过本地文件、内容、布局、Hash、原子发布和登记门禁。

### 本计划不包含

- 不新增业务一级页面，不恢复首页或已废止入口。
- 不绑定新的向量数据库、embedding 模型、联网搜索服务商或收费能力。
- 不改变阶段 9 Windows x64 收口结论，不启动阶段 10，不声明 macOS 已支持。
- 不让模型决定文件路径、凭证、Provider、权限、费用、Work 登记或任意代码。
- 不以扩大附件外发范围、默认联网或完整网页/附件文本展示来解决提示词质量问题。

## 三、问题分解与优先级

### P0｜修订 fail-closed

问题：`document-generation-service` 当前对旧文档兼容、修订代理、补丁应用和范围保护使用了过大的 `try/catch`。修订代理或补丁校验异常时，流程可能继续使用模型返回的全量 `outline`，从而修改用户未授权的范围。

目标行为：

- 只有旧文档无法按历史格式解析时，才允许进入明确标记的兼容恢复路径。
- 修订代理、目标解析、补丁解析、补丁应用、范围校验、保留条件校验任一失败，立即进入结构化失败状态。
- 只有修订计划完成、目标范围验证通过、非目标范围保留条件写入并校验后，才允许交给 Runner。
- 失败、取消、超时、冲突或预算耗尽不得登记新 Work，旧 Work 保持可打开。

必须新增负面测试：`applyPatch` 抛错、目标章节不存在、模型返回跨章节变化、revision 冲突和修订 Agent 超时，均不得发布模型全量大纲。

### P0｜破坏性操作的否定与确认

问题：`clear_section` 的规则只识别清空/删除词和目标范围，未建立否定关系与风险确认模型。

目标行为：

- 先做否定识别，再做动作识别，再做目标解析，最后做风险评估。
- “不要清空第二章”“第二章不要删除”“保留第二章，不要删掉内容”等请求不得生成 `clear_section`。
- `clear_section` 必须具有明确且唯一的目标；缺少目标、目标不唯一或目标跨版本时进入追问。
- 高风险清空、删除章节、移除页面和批量删除默认进入 `needs_confirmation`，确认必须绑定当前会话 revision、目标和幂等键。
- 用户确认前不得执行文件写入或产生新 Work。

### P0｜章节、页面和块级目标模型分离

问题：当前 `第 N 章/节/页/部分` 共用一个 ordinal，并在 PPT 中统一转换为 `sectionIndex = ordinal - 1`、`pageNumber = ordinal + 1`，封面、章节页和正文页存在错位风险。

目标数据模型：

```ts
type RevisionTarget =
  | { unit: 'section'; ordinal: number; heading?: string }
  | { unit: 'page'; pageNumber: number; pageKind?: string }
  | { unit: 'table'; name: string }
  | { unit: 'cell'; sheet: string; address: string }
  | { unit: 'block'; sectionOrdinal: number; blockIndex: number };
```

Application 负责把语义目标解析为当前文档的受控结构索引。PPT 必须显式记录封面、章节页、正文页、结束页映射；Word 的章节/段落、Excel 的工作表/单元格不得复用 PPT 页码规则。

### P1｜意图三态与 LLM 分类兜底

问题：本地规则返回 `chat` 时直接生成高置信度 `DocumentIntentPlan`，未识别但可能是 Office 操作的请求会静默落入普通会话；现有 `document-intent-planner` 尚未成为聊天主链的 LLM fallback。

目标状态：

```text
high-confidence document → 直接进入受控文档流程
high-confidence chat → 普通会话
unknown/low-confidence → LLM 结构化分类
LLM 仍有歧义 → needs_clarification
高风险操作 → needs_confirmation
```

LLM 分类输出采用封闭 Schema，至少包含：`task`、`documentKind`、`target.unit`、`target.number/name`、`operation`、`confidence`、`needsConfirmation`、`missing` 和 `ambiguities`。模型不得返回内部 message/work ID、路径、凭证、Provider、任意 URL 或代码；这些值由 Application 根据当前会话上下文解析。

分类失败、模型不可用或超时必须回退本地规则；回退仍无法确定时必须追问，不得自动生成或执行。

### P1｜系统规则与不可信资料边界

问题：项目上下文、附件和 RAG 结果当前以 `user` 消息或同一用户消息中的文本标记注入。`“不可信参考资料”` 只是文字约定，不能提供模型层面的权限边界。

目标消息结构：

```text
system/developer：稳定生成规则、安全规则、工具和输出 Schema
user：用户原始需求（显示文本与内部模型输入分离）
reference/tool：带元数据的资料片段和检索结果
assistant/tool：模型候选计划或受控工具观察
```

资料 DTO 必须携带 `sourceId`、来源类型、版本、位置、检索时间、内容 Hash 和引用关系。资料只允许支撑事实，不能改变任务、目标、工具、权限、费用或系统规则。资料内容中的“忽略规则”“调用某工具”等指令一律作为普通文本处理。

若 Provider 合同暂不支持独立 `system/developer` 角色，必须在 Application 层保留等价的结构化规则字段或受控适配器，不得把安全边界仅依赖自然语言前缀，并在验收记录中明确能力状态。

### P1｜资料策略与 RAG 失败语义

问题：RAG 无结果或失败时当前继续生成，未区分通用模板与明确要求依据企业资料的任务。

新增资料策略：

- `no_external_context`：只使用用户明确输入，不自动检索。
- `optional_context`：资料可选；检索失败可继续，但交付说明必须标记未使用资料。
- `required_context`：资料是任务前提；检索失败、空结果、版本冲突或引用不足时停止生成并要求补充或确认。

策略由 Application 根据用户请求和结构化计划决定，不能由资料内容或模型自行升级/降级。每个需要事实支撑的章节必须保留来源引用；来源不足时省略事实、标记待确认或进入追问。

### P1｜结构化输出协议

问题：文档提示词使用“优先 JSON，无法结构化时使用 Markdown”，这不是严格 JSON 协议；任意 Markdown 恢复会掩盖模型格式失败。

目标协议：

1. Provider 请求尽可能启用受支持的 JSON object/Schema 响应格式。
2. Application 对响应执行严格 JSON Schema 和文档类型校验。
3. 失败时只允许一次有界、无新增资料和无新增费用的本地恢复；恢复结果必须标记 `recovered_structured`。
4. 仍失败时终止为 `invalid_outline`/`invalid_plan`，不得自动降级为普通 Markdown 文档并继续发布。
5. 若历史兼容必须保留 Markdown 路径，结果必须显式标记 `recovered_unstructured`，只能进入需要用户确认的草稿状态，不能与正常结构化结果等同。

## 四、统一状态与失败码

Application 至少需要区分以下状态：

```text
intent_received
intent_classified
needs_clarification
needs_confirmation
source_retrieval
source_insufficient
plan_validated
revision_target_resolved
revision_scope_validated
tool_executing
temporary_version_written
rendered
diagnostics_collected
repaired
published
failed_closed
cancelled
```

建议失败码：

```text
intent_unknown
intent_ambiguous
confirmation_required
negated_destructive_request
target_missing
target_ambiguous
target_unit_mismatch
revision_scope_violation
revision_patch_failed
source_required_unavailable
source_citation_insufficient
invalid_plan
invalid_outline
unvalidated_output
revision_conflict
budget_exceeded
max_steps_exceeded
cancelled
```

内部审计只记录脱敏字段：计划版本、意图类型、目标单位、目标摘要、来源 ID/Hash、规则或模型路径、工具 ID/版本、revision、状态、失败码、耗时、预算消耗和幂等键。不得记录 Prompt 全文、思维链、凭证、绝对路径、原始网页或完整附件。

## 五、实施顺序与小 PR

所有实现从最新 `develop` 创建独立 `feature/*` 分支，按小 PR 推进。本文冻结顺序和验收要求；实施按负责人批准的计划推进。

### PR-A｜修订 fail-closed 与失败隔离

范围：收窄 `document-generation-service` 异常边界；拆分旧文档兼容恢复与修订执行错误；补齐 `revision_scope_violation`、`revision_patch_failed`、`unvalidated_output` 状态；禁止模型全量大纲在修订失败时继续发布。

验收：补丁异常、范围越权、目标缺失、revision 冲突、取消和超时均零 Work；上一版文件可重新打开；失败审计不含敏感字段。

### PR-B｜否定解析、风险确认与目标单位模型

范围：新增否定关系解析、破坏性操作风险策略、`RevisionTarget` 分层模型和 PPT 页码映射；更新清空/删除/移除操作的确认门禁。

验收：否定句零破坏性调用；“第二章”与“第二页”分别命中正确结构；封面、章节页、正文页、结束页的映射有固定测试；确认前不写临时文件。

### PR-C｜unknown 意图与 LLM 结构化分类兜底

范围：将聊天主链改为 `document/chat/unknown` 三态；接入受控 LLM 分类端口；模型输出只允许分类 Schema；Application 负责目标和内部实体解析；模型失败回退规则，仍不确定则追问。

验收：覆盖同义、口语、否定、复合、多目标和普通聊天黄金样本；unknown 不生成；低置信度不执行；模型输出路径、ID、URL、凭证或代码全部被拒绝。

### PR-D｜system/developer 规则与参考资料 DTO

范围：将稳定规则从用户资料消息中分离；附件和 RAG 结果改为带来源元数据的 reference/tool 输入；建立资料注入隔离和 Provider 能力投影。

验收：资料中包含提示词注入文本时，任务、工具和权限不改变；来源版本、位置、Hash 可追溯；普通聊天不因资料内容触发生成；不支持 system/developer 的 Provider 明确标记降级能力并通过安全测试。

### PR-E｜资料必需性与 RAG 失败策略

范围：增加 `no_external_context/optional_context/required_context`；Application 决定检索策略；required 资料缺失、空结果、过期或引用不足时停止并追问；交付说明记录实际来源。

验收：通用模板可在 optional 资料失败时继续；企业资料明确要求在 required 资料失败时零生成、零 Work；离线回退、索引重建和来源引用不回归。

### PR-F｜JSON Schema、有限恢复与终止协议

范围：统一 DocumentIntentPlan、RevisionPlan、DocumentOutline、PresentationPlan 和 RepairPlan 的严格输出状态；限制一次本地恢复；删除任意 Markdown 自动发布路径，或将其隔离为 `recovered_unstructured` 草稿。

验收：合法 JSON 直接通过；缺字段、未知字段、错误类型和越界结构稳定失败；一次恢复仍失败时不调用第二次 Provider、不发布、不登记 Work；状态和交付说明准确反映恢复类型。

## PR-A 实施进度（2026-09-03）

- 已收窄修订异常边界：旧文档兼容恢复、修订目标/补丁/范围校验和 Runner 执行错误相互隔离；修订失败不再回退到模型全量大纲。
- 已接受本地修订 Agent 的 `completed_unvalidated` 合同：结构校验通过后仍由 Runner 负责最终渲染，且必须同时满足修订变更、具体补丁、目标校验和未改动区域校验。
- 已修复运行时提示误报：Provider 鉴权安全码不再被通用 `unavailable` 状态覆盖为“超时/服务不可用”，UI 会显示“服务商鉴权失败”并提示检查凭据、权限或切换模型。
- 已修复文档完成轮询对单次本地瞬时读取异常的 fail-fast：Provider 执行可能已经 `completed`，但 UI 却进入“文档生成失败，请重试。”现允许最多 4 次瞬时失败并间隔 1 秒重试；成功读取后计数归零，连续 5 次仍失败时保持 fail-closed，不引入无限循环。
- 已修复 PPT 章节续页局部修订范围：当同一章节的标题在其连续页上重复或使用“（续 N）”形式时，执行器和 Runner 校验从授权页开始授权连续匹配范围；不连续的重复标题不进入范围，Word/Excel 细粒度行为不变。
- 新增修订 fail-closed、鉴权失败提示、轮询瞬时失败和真实 PPTX 续页范围回归；续页修复后 focused 回归 50/50 通过，完整 `pnpm test`、typecheck、lint、build 和 `git diff --check` 均通过。
- PR-A 仍待 Windows x64 真实 Office 人工验收和功能分支合并；PR-B 至 PR-F 未实施，本计划整体保持 `in_progress`。

## 六、评测与验收矩阵

### 语义黄金样本

至少覆盖：

- 清空、删除、擦掉、移除、清理、不要删除、保留不动等同义和否定表达；
- 第 N 章、第 N 节、第 N 页、工作表、单元格、段落和具体文件名；
- 单目标、多目标、目标缺失、目标冲突、上一版/前一版和新建请求；
- 普通问答、分析请求、格式比较和包含 Office 词汇但不要求生成的请求；
- “根据公司资料”“根据这份制度”“做通用模板”等不同资料策略；
- 资料注入文本、过期来源、无结果、检索失败、模型超时和结构化输出错误。

每个样本记录：期望 task、documentKind、target unit、operation、confidence、是否确认、资料策略、允许的下一状态和禁止的工具调用。

### 自动化门禁

- Application/domain：Schema、意图、否定、目标映射、范围保护、失败隔离、资料策略和状态机。
- Platform：Provider message role、reference DTO、工具白名单、临时文件、渲染、Hash、原子发布和审计脱敏。
- UI/IPC：只发送用户意图和版本化引用，不发送内部路径、凭证、Prompt、完整附件或 Provider 路由事实。
- 全量 `test`、`typecheck`、`lint`、`build`、平台审计、交接校验、敏感字段扫描和 `git diff --check`。

### Windows x64 验收

- 使用最新 Electron 构建验证普通聊天、创建文档、局部章节清空、局部页面修改、Excel 指定列和 Word 指定段落。
- 使用真实 Word/Excel/PowerPoint 打开、保存、重新打开；检查非目标范围内容、布局、字体、溢出、重叠、页码映射和新版 Work 登记。
- 记录失败、取消、确认、RAG 必需资料缺失、Provider 不支持 system/developer、结构化恢复和 revision 冲突证据。
- macOS 继续保持 `required=false/not_run/deferred`，不以 Windows 证据推导 macOS 支持。

## 七、完成条件与未完成项

本计划只有在 PR-A 至 PR-F 均有实现提交、自动化门禁、Windows x64 实机证据、失败矩阵和脱敏审计后，才能标记 `passed`。在此之前统一记录为 `planned`、`in_progress` 或对应失败状态。

当前未完成项：

- 修订 fail-closed 的 Windows x64 真实 Office 人工验收尚未完成；
- 否定和破坏性操作确认尚未接入；
- 章节/页面目标模型尚未拆分；
- unknown 意图尚未接入 LLM 结构化 fallback；
- 稳定规则尚未迁移到真正的 system/developer 层；
- required/optional 资料策略尚未接入主链；
- JSON 严格失败和恢复状态尚未统一；
- 本计划尚未执行 Windows x64 实机回归。
