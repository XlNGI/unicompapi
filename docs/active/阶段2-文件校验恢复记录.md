## 一、本次实现

- `NodeSha256FileVerifier` 使用流式读取计算 SHA-256，不一次加载整个文件。
- 校验结果包含字节数、Hash、是否匹配已有证据和校验时间。
- 支持 `AbortSignal` 取消和真实字节进度回调。
- 读取失败区分文件不存在、非普通文件、权限拒绝、取消、无效 expected checksum 和通用读取失败。
- `NodeFileStatusProbe` 探测项目文件和外部文件的存在性、外置存储连接、读取权限、项目目录可写性和 Hash 一致性。
- `recovery-planner` 只生成恢复动作建议：重新检查、重连存储、重新定位、选择可写目录、恢复备份和重新下载。
- 校验或探测不会自动覆盖、删除、上传、重新下载或修改文件引用。

## 二、状态映射

| 事实 | 建议状态 | 恢复建议 |
| --- | --- | --- |
| 文件可读且 Hash 一致 | `available` | 无 |
| 项目路径缺失 | `missing` | 重新定位、恢复备份 |
| 外部卷不可用 | `disconnected` | 重连存储、重新检查 |
| 项目目录不可写 | `read_only` | 选择可写目录、重新检查 |
| Hash 不一致 | `corrupted` | 恢复备份、重新下载 |
| 路径非法 | `missing` | 重新定位 |

外部源文件只要求可读取，不因源文件不可写而自动修改或覆盖原文件。

## 三、安全边界

- 项目内路径继续通过 `ProjectRelativePath` 校验并限制在项目根目录。
- 外部路径只能来自主进程已保存的 `FileReference`，不接受渲染进程任意绝对路径。
- Hash 计算不上传文件，不记录绝对路径或文件内容。
- 恢复动作是建议，不是自动执行；用户确认前不改变文件或索引。
