# 任务中心人民币消费摘要读模型

日期：2026-08-28

分支：`feature/task-consumption-summary-cny`

阶段：阶段 9 已收口后的独立 UI/读模型优化；阶段 10 未启动。

## 负责人决策

- 任务中心消费图表统一展示人民币。
- 主进程增加受控 `getConsumptionSummary` 读模型。

## 实际修改

- 新增 `storage:get-consumption-summary` 受控 IPC、共享 DTO、Electron 主进程注册和 preload 白名单方法。
- renderer 的消费图表由“查询最多 200 条调用记录，再逐条查询详情”改为一次 `getConsumptionSummary()`；项目文件变化后通过既有受控事件重新读取摘要。
- 费用计算与聚合移到主进程。十进制用量、价格、比例与换算使用 `bigint` 有理数计算，最终以受限十进制字符串输出，避免 renderer 使用二进制浮点累加金额。
- 摘要固定以 `CNY` / `人民币` 输出。原始费用本身为人民币时直接计入；非人民币费用只有在主进程注入已批准换算事实后才计入。
- 新增 `CurrencyConversionFactResolverPort`。换算事实必须包含源币种、人民币目标、正十进制换算率、HTTPS 无查询参数来源地址、来源标题和有效核对日期；重复币种或非法事实使读模型失败关闭。
- renderer 不接收换算率、价格规则、路由快照、包/适配器、endpoint、凭证、运行时策略或远端操作信息；只接收人民币聚合、换算来源说明、待换算币种计数和项目读取问题。
- 没有批准换算事实的非人民币费用保持“待换算”，不混入人民币总额，也不通过直接修改单位伪装成人民币。
- 时间柱状图返回连续 UTC 日历桶并补零；供应商按稳定 `providerId` 聚合，同名不同 ID 不合并。
- 供应商占比展示前 5 个分组，其余合并为“其他”；主进程分配基点并保证占比严格合计 100%。
- UI 统一使用人民币格式，显示待换算、缺价格、缺用量、格式异常和部分项目不可用等真实状态，并明确“本地估算不等于服务商正式账单”。

## 未完成项与边界

- 当前生产组合没有注入任何获批准的外币兑人民币换算事实，因此现有 USD 等费用会显示为“待换算”，人民币总额不会包含它们。这是安全边界，不是自动汇率服务。
- 后续接入换算事实前，负责人需批准来源、核对日期、更新机制与失效策略；不得在 renderer、价格规则或 UI 中写死汇率。
- 该摘要仍是本地调用事实估算，不做服务商账单同步、税费处理或财务对账。
- 本次统一范围是任务中心消费图表；调用记录详情仍展示其原始官方计价币种，避免伪造单次调用的人民币金额。
- 生产 Electron 可见启动、窗口响应与退出清理已经通过；尝试使用 Windows UI Automation 自动进入任务中心时，当前 Electron 窗口没有向该接口暴露导航语义，因此没有把“真实项目下逐项核对待换算提示与零金额空态”伪记为自动化通过。页面结构、人民币文案、单次摘要端口与状态分支由 UI/IPC 合同覆盖，真实数据逐项视觉检查继续作为非阻断人工回归项。

## 下一步建议

1. 负责人批准人民币换算事实来源与更新/失效规则后，在 Electron 主进程组合层实现 `CurrencyConversionFactResolverPort`，并单独验收离线、过期和来源撤销场景。
2. 后续人工回归可在真实项目数据上核对人民币格式、日期桶、供应商“其他”和待换算提示，不发起服务商调用。
3. 若后续需要调用详情也统一为人民币，应另立范围并同时保留原始币种、原始金额和换算事实，不能覆盖原始官方计价事实。
