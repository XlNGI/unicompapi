# 阶段 9 E5.6｜原子发布与 Work 登记验收记录

## 一、实际修改

- 新增 `publishDocumentCandidate` 原子发布协调器和 `DocumentPublishPort` 注入接口。
- 发布前严格校验：文档类型、扩展名、临时/目标句柄、文件大小、SHA-256、期望 revision、幂等键、内容指纹和诊断通过标记。
- 发布前调用临时文件验证端口，要求文件存在、Office 包有效、大小和 Hash 与候选一致。
- 通过 `readCurrentRevision` 做乐观并发检查；`publishAtomic` 由主进程负责安全 rename/CAS。
- 幂等键重复且 Hash 相同返回 `idempotent_replay`，不重复写入或登记；同键不同 Hash 返回 revision 冲突。
- 原子发布成功后才调用 `registerWork`；发布前任一失败、取消、冲突或诊断不通过均不登记新的 Work。
- 发布协调器不向 LLM/renderer 暴露绝对路径，真实路径和 Work/FileReference 持久化由注入端口控制。
