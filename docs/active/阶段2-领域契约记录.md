## 二、本次实现

- 建立带类型品牌的项目、草稿、素材、文件、任务、执行和作品 ID。
- 建立规范 UTC ISO-8601 时间戳校验，并拒绝状态时间倒退。
- 建立项目、草稿、素材、文件引用、任务、执行记录和作品实体。
- 草稿通过显式确认工厂生成任务提交快照；保存草稿、提示词增强和跨页面进入不会自动创建任务。
- 任务状态从最新执行记录投影，不在任务实体上维护第二套可写状态。
- 建立执行状态机，区分提交、排队、处理、远端完成、下载、写入、校验、本地完成、取消未知、失败和过期。
- 重试必须创建新执行 ID；取消状态未知时禁止盲目重试。
- 建立文件状态机，覆盖写入、校验、可用、丢失、只读、断开、损坏和删除。
- 文件只有在字节数和 SHA-256 校验值齐备时才能进入可用状态。
- 作品登记要求任务、执行和文件来源一致，且执行本地完成、文件校验通过。
- 接入 Vitest 2，并让测试 TypeScript 文件参与类型检查。
- 建立项目相对路径安全校验和固定项目目录布局：实体、索引、文件和临时目录。
- 建立文件索引纯函数，保证一个路径只归属一个文件 ID，并支持更新、删除和查询。
- 建立项目存储原子 JSON 写入接口和项目、草稿、素材、任务、作品仓储端口；尚未绑定具体操作系统文件 API。

## 三、明确边界

- 领域层不依赖 React、Electron、Node 文件系统、localStorage 或后台 SDK。
- 未写死服务商、模型、价格、时长、分辨率、数量或远端取消能力。
- 未接后台接口，未实现真实图片或视频任务。
- 未实现本地存储、目录索引、原子写入、文件校验执行器或 IPC。
- 未实现视频编辑领域；阶段 7 仍需先完成独立强制技术架构。
