## 二、实际修改

### EditDraft V1

新增独立 video_basic_edit 草稿，不把视频生成草稿混入编辑联合。

草稿包含：

- 独立 VideoEditDraftId、VideoClipId 和 TextOverlayId；
- 项目、标题、revision、来源意图和创建/更新时间；
- 画布比例、适应/填满和纯色/模糊背景；
- 一个顺序视频主轨和 removedClips 墓碑；
- 片段来源、媒体身份快照、裁剪、速度、画面变换、原声和基础转场；
- 多个基础文字层；
- 零或一条背景音乐；
- 视频选帧、本地图片或项目图片封面；
- 只保存动态能力选择意图的输出偏好；
- 有界、可持久化的 undoStack/redoStack。

持久化时间统一使用非负安全整数微秒。片段时间线时长由裁剪、速度和基础转场计算，不保存可漂移的 timelineStart 第二事实。

### 严格校验

运行时拒绝：

- 未知 schema、kind 或额外字段；
- 空 ID、重复片段/文字 ID 和活动/已删除片段冲突；
- 越过源媒体时长的裁剪；
- 非法速度、裁切、透明度、音量、文字时间和音乐时间；
- 最后片段仍声明到下一片段的转场；
- 超过相邻片段有效时长的转场；
- 越过当前时间线的文字、音乐或封面选帧；
- 文件名路径分隔符、绝对路径、任意媒体命令和编辑器内部字段。

### 编辑命令与撤销重做

新增可序列化的严格命令联合：

- set_title；
- insert_clip；
- trim_clip；
- split_clip；
- remove_clip / restore_clip；
- duplicate_clip；
- move_clip；
- set_clip_speed；
- set_clip_transform；
- set_clip_transition；
- set_source_audio；
- upsert_text / remove_text；
- set_background_music；
- set_cover；
- set_canvas；
- set_output_preference。

命令保存 before/after 或完整可逆事实。apply、undo 和 redo 都创建新 revision，不覆盖原命令记录。历史默认上限为 100 条；超出后推进 baseRevision，不无限增长。

分割由主进程生成新 Clip ID，并校验左右片段来源一致、范围连续。复制只能复制原片段内容，不能借命令替换成其他源文件。

### 仓储与自动保存

新增项目内版本化仓储：

    entities/video-edit-drafts.json

仓储继续复用项目范围隔离、写队列、临时 JSON、文件同步和原子替换。

每次成功领域命令立即尝试原子保存。保存失败时：

- 已执行草稿保留在主进程内存；
- IPC 返回脱敏 recoverableDraft；
- 后续 get/list/update 继续读取该 revision；
- 再次成功保存后清除内存脏状态；
- 项目 Session 切换前重新尝试落盘，失败则阻止静默切换。

复制草稿生成新 ID、revision 0 和空历史，同时保留当前非破坏式编辑状态与来源引用。

### 安全 IPC

新增受控操作：

    create
    get
    list
    update
    undo
    redo
    copy

update 只接受意图 DTO。before 状态、分割/复制新 ID 和完整领域命令均在主进程生成。

renderer DTO 只返回：

- 草稿当前状态；
- fileId、assetId、workId 等受控标识；
- 脱敏媒体元数据；
- revision、canUndo 和 canRedo。

renderer 不接收：

- 绝对或项目相对路径；
- 原始 SHA-256 和修改时间指纹；
- undoStack、redoStack 或持久化命令；
- 媒体引擎命令、进程句柄、仓储位置或内部堆栈。

### 来源边界

新草稿支持：

- blank；
- from_work；
- from_video_draft。

from_work 必须是当前项目的视频 Work；from_video_draft 必须是当前项目已存在的视频生成草稿。B1 只记录来源意图，不自动导入文件、不创建时间线片段、不创建任务。
