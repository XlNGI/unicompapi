# 阶段 4｜本机安全凭证库记录

日期：2026-07-22
分支：`feature/secure-credential-vault`
负责人：开发者 B｜领域与平台

## 一、本次实现

- 建立版本 1 本机加密凭证库，载荷只写入应用用户目录下的 `secure-credentials.json`。
- Electron 主进程通过 `safeStorage` 使用 Windows DPAPI / macOS Keychain 对应的操作系统加密语义。
- 支持首次保存、替换、本地删除、状态查询和本地安全存储可读性检查。
- 凭证引用与加密载荷分离；服务商注册表只保存引用和状态。
- 新凭证写入后若注册表保存失败，会清理新建的孤立密文条目。
- 密文文件以同目录临时文件、`fsync` 和原子替换方式保存；支持并发写入串行化。

## 二、renderer IPC

```text
window.unicomp.providers.saveCredential(connectionId, value)
window.unicomp.providers.deleteLocalCredential(connectionId)
window.unicomp.providers.getCredentialStatus(connectionId)
window.unicomp.providers.checkCredentialStorage(connectionId)
```

安全边界：

- 不提供 `getCredential`、`readCredential` 或解密后返回 renderer 的接口。
- 错误只返回受控错误码和通用消息，不返回凭证、密文、路径或内部堆栈。
- `checkCredentialStorage` 只检查本机安全存储是否存在且可解密，不冒充远端鉴权成功。
- `deleteLocalCredential` 只删除本地副本，明确返回 `remoteRevocation: not_attempted`。
- 服务商侧撤销必须等待真实后台/服务商契约，当前不伪造远端操作。

## 三、主进程内部边界
