# 阶段 6 B4｜视频结果接收与作品登记记录

日期：2026-07-24

分支：`feature/video-result-receiver`

基线：`1b9605d Merge image to video workspace`

## 一、范围

本任务建立视频生成从远端完成事实到本地正式 Work 的结果接收边界，包括结果发现、流式下载、临时写入、可信视频探测、服务声明校验、SHA-256 校验、fsync、原子发布、FileReference、Execution 完成和 Work 登记。

本任务不猜测任何服务商 HTTP、轮询、回调、上传或下载地址，不提供真实视频生成/结果适配器，不伪造远端完成、进度或视频结果，也不实现阶段 7 时间线、媒体引擎、代理文件或导出。

## 二、远端结果端口

新增独立 `VideoResultPort`，把后台适配器能力拆成三个真实操作：

1. 读取远端完成事实；
2. 发现完成操作下的结果清单；
3. 为指定结果打开 Node 可读流。

每个远端结果必须声明内部结果 ID、显示名称、MIME、容器、字节数、SHA-256、时长、宽度和高度。声明缺失、非法、重复或未知时立即阻断，不下载并猜测缺失事实。远端 operation ID 和结果 ID 只在主进程端口与实体中使用，不返回 renderer。

Electron 默认注册仍未注入真实 `VideoResultPort`。因此新增的 `receiveResult(executionId)` IPC 会真实返回 `adapter_unavailable`，不会制造完成状态、文件或 Work。

## 三、流式下载与临时校验

下载使用适配器返回的可读流和 Node pipeline 写入项目 `tmp` 临时文件，不把完整视频送入 renderer，也不把完整视频缓冲进主进程内存。流式字节计数在超过服务声明时立即终止；下载完成后执行：

1. 临时文件 fsync；
2. 常规文件与符号链接检查；
3. B2 `VideoInspector` 可信探测；
4. 流式 SHA-256 与字节数计算；
5. MIME、容器、字节、Hash、时长和宽高与服务声明逐项严格匹配。

内置可信视频探测范围继续仅为 ISO BMFF MP4/MOV，不引入 FFmpeg，也不按扩展名推测媒体事实。

## 四、原子发布与本地持久化

每个通过临时校验的结果预先建立独立 FileReference ID 和 Work ID。临时文件 fsync 后，通过同一项目卷内的排他硬链接原子发布到 `files/results/<workId>.mp4|mov`，若目标已存在则失败，不覆盖历史文件。

原子发布后再次对正式路径执行可信视频探测和 SHA-256 校验。只有全部结果均完成正式文件校验、available FileReference 保存和文件索引写入后，Execution 才能从 verifying 进入 completed。

下载、探测、服务声明、Hash、fsync、发布、FileReference 或索引任一阶段失败时，不创建 Work；仍可转换的 Execution 保存真实失败阶段和重试性。未形成正式文件事实的临时文件或结果文件会清理。

## 五、多结果与 Work 登记

一个 Execution 可以发现一个或多个真实结果。每个结果分别建立：

- 独立项目文件；
- 独立 available FileReference；
- 指向同一来源 Task/Execution 的独立 Work；
- 独立安全 DTO 条目。

Task、Execution、FileReference 和 Work 的现有领域约束保持不变。Work 只在 Execution completed 后登记。若 Work 仓储登记失败，IPC 不返回成功；已经通过校验的本地文件、FileReference、索引和 completed Execution 会保留，避免把已持久化事实误删或伪装成未完成下载。

renderer 只收到 Execution ID、Work ID 和显示名称，不收到绝对路径、项目相对路径、原始 Hash、远端 operation/result ID、endpoint、凭证、内部命令或错误堆栈。正式视频 Work 的预览继续复用现有短期 `unicomp-media` 句柄和主进程 Range 响应。

## 六、状态与错误边界

结果接收只接受带远端 operation ID 的 queued/processing Execution。远端完成不等于本地完成，状态仍按以下顺序推进：

```text
queued/processing
  -> remote_completed
  -> downloading
  -> writing
  -> verifying
  -> completed
```

为保存远端完成后发现的真实失败，Execution 状态机允许 `remote_completed -> failed`。结果发现和下载错误可携带适配器声明的 retryability；媒体、声明和完整性不匹配默认不可重试；未知本地存储错误保持 unknown。

新增安全错误码：

- `result_discovery_failed`；
- `download_failed`；
- `result_verification_failed`；
- `result_registration_failed`。

## 七、验证

新增或更新测试覆盖：

- 远端完成、结果发现和可读流端口分离；
- 多个 MP4/MOV 结果分块流式下载并分别登记 FileReference/Work；
- 路径样式名称只保留跨平台安全显示名；
- MIME、容器、时长、宽高、字节数和 SHA-256 服务声明校验；
- 超出声明字节数时中止流；
- 临时与正式路径的两次可信探测/Hash 校验；
- 失败时不创建 Work 并清理未登记文件；
- 可重试的结果发现失败写入 Execution；
- Work 登记失败时保留 completed Execution 和正式文件事实；
- 默认无结果适配器时返回 `adapter_unavailable` 且不改变远端执行状态；
- IPC/preload 操作分离和 renderer DTO 受保护字段防泄漏。
