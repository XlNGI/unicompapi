# 当前项目任务状态栏范围修复记录

日期：2026-08-28

分支：`feature/current-project-task-status`

结论：底部生产任务状态栏与左侧最近任务活动已统一限定为当前打开项目；任务中心的全局视图、全局任务列表和项目筛选保持不变。

## 实际修改

- 共享 `task-read-store` 在唯一刷新链中并发读取全局任务投影与当前项目 Session，快照新增 `currentProjectId`；没有新增组件级任务轮询或重复 `listTasks()`。
- 新增纯项目范围投影：有当前项目时仅保留 `task.projectId === currentProjectId` 的任务；未打开项目或当前项目读取失败时返回空集合，不回退显示其他项目任务。
- 底部展开的“生产任务”列表、折叠状态栏的运行中/需处理计数，以及左侧“最近任务活动”的运行中/需处理/等待处理/已完成计数，全部使用当前项目投影。
- 原始共享快照仍保存全局任务集合，任务中心页面继续消费全局数据，其全局视图和项目筛选语义未改变。
- 项目切换事件到达时立即清空快照中的旧 `currentProjectId` 并进入加载态；若切换发生在刷新进行中，旧响应因项目范围 revision 不一致而不提交，同时补一次 latest refresh，避免旧项目任务短暂闪现或通知被 in-flight 合并吞掉。

## 回归覆盖

- 混合两个项目的任务输入只统计当前项目，其他项目的需处理任务不进入底部列表或计数。
- 未打开项目时，当前项目投影为空，运行中、需处理、已完成和可见任务均为 0。
- 项目范围从旧项目切换到新项目后，旧项目任务不进入新项目摘要。
- UI 合同固定两个状态区域必须先执行当前项目投影，禁止重新对全局任务直接调用摘要函数。
- 共享 Store 合同固定 `getProjectSession()` 与 `listTasks()` 同批刷新、项目切换立即失效旧范围、并发期间登记补刷新。
