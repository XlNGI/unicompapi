# 动态参数前端校验与必填适配验收记录

日期：2026-08-26

当前阶段：阶段 9 收口后的工程补充；阶段 10 未启动。

## 范围与标准

本次统一图片与视频创作页的动态参数交互标准：

- 所有候选模型 Schema 中 `required: true` 或 `exposure: user_required` 的字段必须渲染到动态参数表单，且以“必填”标识展示。
- 表单在编辑时直接校验空值与格式：枚举、数值/整数、最小值、最大值、步长、字符串数组、数值数组、JSON 对象与布尔值均返回中文字段错误。
- 空白、格式错误或本地输入解析错误时，生成按钮保持禁用；`prepare()` 也会再次校验并返回，不会进入草稿保存、主进程准备或实际提交。
- `false` 和 `0` 是合法的必填值，不能按空值处理。
- 快速生图和快速视频只有在当前候选没有任何动态字段时才隐藏表单并说明使用服务默认值；若模型投影中存在必填字段，仍须显示并填写，不能从枚举首项猜测默认值。

## 实际修改

- 新增纯前端校验模块 `src/components/dynamic-parameter-validation.ts`，输出字段级中文错误和首个错误。
- `DynamicParameterForm` 接收外部错误、使用可访问的错误状态，并让 JSON 对象和数值数组在输入阶段即报告非法格式，保留用户尚未修复的文本。
- `ImageFeatureSubmissionPanel` 与 `VideoFeatureSubmissionPanel` 使用同一校验结果驱动字段错误、生成按钮和 `prepare()` 的二次短路。
- 新增 domain 与 UI 合同测试，覆盖必填缺失、`false`/`0`、非法数值数组、范围约束、对象值，以及图片/视频面板的前端门禁与快速页显示规则。

## Schema 核对结论

- UniCompAPI 精确图像 Schema 已为 Seedream 5 和 Qwen Image 的 `size` 声明 `user_required` / `require_user_value`，因此会在前端展示并阻止空提交。
- Qwen Image Edit 当前合同证据中没有可确认的用户必填动态字段，不按模型名称推断参数。
- OpenAI 兼容视频默认 Schema 被多个模型共享。现有资料仅能证明部分 Sora 格式请求使用 `seconds`；没有精确模型到协议的完整映射前，不把 `seconds` 加为全局必填，以免在 HTTP 前拒绝使用 `duration` 的已有合法模型。未来新增视频必填项时，必须先补精确模型 Schema、路由和合同测试。
- UniCompAPI 的 `doubao-seedance-2-0-260128` 与 `doubao-seedance-2-0-fast-260128` 现通过精确映射使用 Seedance Schema，显示有证据的九个请求体字段；公开资料未确认模型级必填项或可枚举支持值，因此这些字段保持可选且不伪造下拉选项。普通 OpenAI-compatible 中转站的同名模型继续使用通用 Schema。
