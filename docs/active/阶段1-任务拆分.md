# 阶段 1｜任务拆分：桌面壳、导航、主题与基础组件

日期：2026-07-20

## 一、阶段目标

阶段 1 只做工程骨架和桌面壳，不做完整业务功能。

本阶段目标：

- Electron 桌面应用可稳定启动；
- 八项一级导航可切换；
- 建立基础 Layout、Sidebar、TopBar、PageShell；
- 接入 Design Tokens 的第一版使用方式；
- 建立项目、本地领域和后台/API 接入的目录边界；
- 为后续阶段留下清晰接口，不抢跑复杂业务。

## 二、共同规则

所有开发者必须遵守：

1. 从 `main` 拉自己的 `feature/*` 分支，不直接在 `main` 开发。
2. 每次提交前至少运行一次本地启动或构建检查。
3. 不得写死后台 Base URL、Token、API Key、模型、价格、时长、分辨率和数量。
4. 不得新增登录、会员、充值、云同步。
5. 不得恢复“首页”一级入口。
6. 不得把对话页做成直接生成入口。
7. 不得修改 `handoff/` 中的权威交接资料。
8. 如需形成工程结论，写入 `docs/active/`。

建议分支：

```text
feature/electron-baseline
feature/ui-shell
feature/domain-api
```

## 三、开发者 A｜Electron 工程与架构

### 任务名称

完善 Electron 工程基线

### 负责范围

- Electron 主进程；
- preload 安全边界；
- 开发启动命令；
- 构建命令；
- 后续打包方案；
- 跨平台窗口基础行为。

### 具体任务

1. 检查并完善 `electron/main.ts`：
   - 窗口尺寸；
   - 最小窗口尺寸；
   - 外链打开策略；
   - Windows / macOS 基础行为；
   - 开发环境和生产环境加载逻辑。

2. 检查并完善 `electron/preload.ts`：
   - 只暴露必要能力；
   - 禁止直接暴露 Node、文件系统、环境变量；
   - 为后续 IPC 留出安全结构。

3. 整理启动和构建命令：
   - `npm run dev`；
   - `npm run build`；
   - 如使用 pnpm，同步说明 `pnpm dev`、`pnpm build`。

4. 初步调研打包方案：
   - electron-builder 或 electron-forge；
   - Windows / macOS 目标；
   - 代码签名暂不实现，只记录后续要求。

5. 更新文档：
   - 如发现阻断项，写入 `PLANS.md`；
   - 如形成打包建议，写入 `docs/active/Electron打包方案草案.md`。

### 不做

- 不做业务页面；
- 不接后台接口；
- 不实现作品、任务、项目等业务逻辑；
- 不提交真实凭证。

### 验收标准

- `npm run dev` 能启动桌面窗口；
- `npm run build` 能通过或明确记录阻断项；
- preload 不暴露危险能力；
- 外部链接不在应用内部任意打开；
- 更新了必要文档。

## 四、开发者 B｜UI 与桌面壳

### 任务名称

实现阶段 1 UI 桌面壳

### 负责范围

- 主布局；
- 八项一级导航；
- 基础页面骨架；
- Design Tokens 初步接入；
- 视觉与权威设计图对齐。

### 具体任务

1. 拆分当前 `src/ui/App.tsx`：
   - `src/ui/layout/AppLayout.tsx`；
   - `src/ui/layout/Sidebar.tsx`；
   - `src/ui/layout/PageShell.tsx`；
   - `src/ui/navigation/navigationItems.ts`。

2. 实现八项一级导航：
   - 对话；
   - 项目；
   - 图片创作；
   - 视频创作；
   - 任务中心；
   - 作品库；
   - 模型与服务商；
   - 本地设置。

3. 每个一级页面先建立空状态骨架：
   - `src/pages/chat/ChatPage.tsx`；
   - `src/pages/projects/ProjectsPage.tsx`；
   - `src/pages/image-creation/ImageCreationPage.tsx`；
   - `src/pages/video-creation/VideoCreationPage.tsx`；
   - `src/pages/tasks/TasksPage.tsx`；
   - `src/pages/library/LibraryPage.tsx`；
   - `src/pages/providers/ProvidersPage.tsx`；
   - `src/pages/settings/SettingsPage.tsx`。

4. 接入 Design Tokens：
   - 参考 `handoff/UniComp-技术开发启动包-V1.0.0/03-最终UI交接包-已解压/UniComp-AI-最终UI与开发交接包-V1.2.1/tokens/UniComp-AI-Design-Tokens-V1.2.0.json`；
   - 先建立 `src/styles/tokens.css` 或 `src/styles/tokens.ts`；
   - 不要求一次性完整覆盖全部视觉细节。

5. 建立 UI 对照记录：
   - 写入 `docs/active/UI对照记录.md`；
   - 记录已对齐项、未对齐项和疑问项。

### 不做

- 不接后台接口；
- 不做完整图片/视频创作功能；
- 不新增“首页”；
- 不新增登录、会员、充值、云同步；
- 不把对话页做成直接生成入口。

### 验收标准

- 八项导航可切换；
- 每个一级页面都有骨架；
- 样式开始使用 Design Tokens；
- `npm run dev` 可正常显示；
- 不违反交接包禁止事项。

## 五、开发者 C｜本地领域与接口集成

### 任务名称

整理本地领域模型与后台接口边界

### 负责范围

- 领域类型；
- 本地状态；
- 后台/API 调用边界；
- 后续任务、作品、素材、模型服务商的数据基础。

### 具体任务

1. 建立领域目录：

```text
src/domain/
├─ project.ts
├─ asset.ts
├─ draft.ts
├─ task.ts
├─ work.ts
├─ provider.ts
└─ file-state.ts
```

2. 建立 API 服务目录：

```text
src/services/api/
├─ apiClient.ts
├─ apiTypes.ts
└─ endpoints.ts
```

3. 先写 TypeScript 类型，不直接接真实后台：
   - 项目；
   - 素材；
   - 草稿；
   - 任务；
   - 作品；
   - 服务商；
   - 模型；
   - 文件状态。

4. 文件状态至少覆盖：
   - 正常；
   - 文件丢失；
   - 文件损坏；
   - 只读；
   - 外置盘断开；
   - 预览失败；
   - 无权限。

5. API Client 只做抽象：
   - 不写死 Base URL；
   - 不写死 Token；
   - 支持从配置读取；
   - 预留超时、代理、错误码、重试和日志脱敏。

6. 输出后台需求清单：
   - 写入 `docs/active/后台接口需求清单.md`；
   - 列出需要后台提供的接口、请求示例、响应示例和错误码。

### 不做

- 不实现完整业务流程；
- 不写死后台地址；
- 不提交真实 Token / API Key；
- 不创建登录、会员、充值、云同步逻辑。

### 验收标准

- `src/domain/` 类型清晰；
- `src/services/api/` 边界清晰；
- 后台接口需求清单已输出；
- 类型不与 UI 强耦合；
- 不违反凭证和动态能力规则。

## 六、合并顺序建议

建议合并顺序：

1. 开发者 A：Electron 工程基线；
2. 开发者 B：UI 桌面壳；
3. 开发者 C：领域模型与 API 边界。

如果 B 和 C 并行开发，尽量避免同时修改 `src/ui/App.tsx`。B 负责 UI 组件，C 负责 `src/domain/` 和 `src/services/`。

## 七、阶段 1 完成标准

阶段 1 完成时，应满足：

- Electron 应用能在 Windows 上启动；
- 八项一级导航可切换；
- 每个页面有空状态骨架；
- 基础主题和 Design Tokens 接入；
- 主进程与渲染进程安全边界明确；
- 本地领域模型初稿完成；
- 后台接口需求清单完成；
- `PLANS.md` 更新真实验收结果。
