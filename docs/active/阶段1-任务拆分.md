# 阶段 1｜任务拆分：两名 UI 开发者版本

日期：2026-07-20

## 一、当前有效分工声明

以本文件为阶段 1 当前唯一有效任务分工。

此前“三线分工：Electron 工程 / UI 桌面壳 / 本地领域与接口集成”在阶段 1 暂不执行。当前阶段先集中做 UI：桌面壳、导航、页面骨架、Design Tokens 和基础组件。

本阶段不接后台接口，不做完整业务功能。

## 二、阶段目标

阶段 1 目标：

- Electron 应用能稳定启动；
- 八项一级导航可点击切换；
- 建立桌面应用主布局；
- 建立八个一级页面骨架；
- 建立第一版 Design Tokens 接入方式；
- 建立基础 UI 组件；
- 形成 UI 对照记录。

八项一级导航固定为：

1. 对话；
2. 项目；
3. 图片创作；
4. 视频创作；
5. 任务中心；
6. 作品库；
7. 模型与服务商；
8. 本地设置。

## 三、共同规则

两名 UI 开发者都必须遵守：

1. 从 `main` 拉自己的 `feature/*` 分支，不直接在 `main` 开发。
2. 每次提交前至少运行一次 `npm run dev` 或 `npm run build`。
3. 不得修改 `handoff/` 中的权威交接资料。
4. 不得新增“首页”。
5. 不得新增登录、会员、充值、云同步。
6. 不得把对话页做成直接生成入口。
7. 不得接真实后台接口。
8. 不得写死后台 Base URL、Token、API Key、模型、价格、时长、分辨率和数量。
9. 如需形成工程结论，写入 `docs/active/`。

建议分支：

```text
feature/ui-shell-layout
feature/ui-pages-tokens
```

## 四、UI 开发者 A｜桌面壳与导航

### 任务名称

阶段 1 UI 桌面壳与导航

### 负责范围

主要负责：

```text
src/ui/
src/ui/layout/
src/ui/navigation/
src/ui/App.tsx
```

尽量不改：

```text
src/pages/
src/components/
src/styles/tokens.*
```

### 具体任务

1. 拆分当前 `src/ui/App.tsx`：

```text
src/ui/layout/AppLayout.tsx
src/ui/layout/Sidebar.tsx
src/ui/layout/PageShell.tsx
src/ui/navigation/navigationItems.ts
```

2. 实现八项一级导航切换：

- 对话；
- 项目；
- 图片创作；
- 视频创作；
- 任务中心；
- 作品库；
- 模型与服务商；
- 本地设置。

3. 实现主布局：

- 左侧全局导航；
- 主内容区；
- 顶部页面标题区；
- 页面状态/标签区；
- 当前页面 active 状态。

4. 为页面切换预留接口：

- 可以使用 React state；
- 暂不引入复杂路由；
- 不接后台；
- 不做业务数据。

5. 保持 Electron 可启动：

- 不破坏 `electron/main.ts`；
- 不破坏 `electron/preload.ts`；
- 不引入不必要的 Node 能力。

### 不做

- 不做页面具体业务；
- 不接后台接口；
- 不做图片/视频创作流程；
- 不新增首页；
- 不新增登录、会员、充值、云同步。

### 验收标准

- `npm run dev` 可启动；
- 八项导航可点击切换；
- active 状态正确；
- 每个导航能显示对应页面标题或占位内容；
- 不修改 `handoff/`；
- 不违反交接包禁止事项。

## 五、UI 开发者 B｜页面骨架、Design Tokens 与基础组件

### 任务名称

阶段 1 页面骨架与 Design Tokens

### 负责范围

主要负责：

```text
src/pages/
src/components/
src/styles/
docs/active/UI对照记录.md
```

尽量不改：

```text
src/ui/layout/
src/ui/navigation/
electron/
```

### 具体任务

1. 建立八个一级页面骨架：

```text
src/pages/chat/ChatPage.tsx
src/pages/projects/ProjectsPage.tsx
src/pages/image-creation/ImageCreationPage.tsx
src/pages/video-creation/VideoCreationPage.tsx
src/pages/tasks/TasksPage.tsx
src/pages/library/LibraryPage.tsx
src/pages/providers/ProvidersPage.tsx
src/pages/settings/SettingsPage.tsx
```

2. 每个页面只做空状态骨架：

- 页面标题；
- 简短说明；
- 当前阶段标签；
- 后续能力占位；
- 不做真实业务操作。

3. 建立基础组件：

```text
src/components/Button.tsx
src/components/Card.tsx
src/components/EmptyState.tsx
src/components/StatusPill.tsx
```

4. 接入 Design Tokens：

参考权威 tokens 文件：

```text
handoff/UniComp-技术开发启动包-V1.0.0/03-最终UI交接包-已解压/UniComp-AI-最终UI与开发交接包-V1.2.1/tokens/UniComp-AI-Design-Tokens-V1.2.0.json
```

建议先建立：

```text
src/styles/tokens.css
```

第一版只需要覆盖：

- 背景色；
- 文本色；
- 边框色；
- 强调色；
- 圆角；
- 间距；
- 阴影；
- 字体层级。

5. 建立 UI 对照记录：

```text
docs/active/UI对照记录.md
```

记录：

- 已对齐的设计图；
- 已实现的页面；
- 暂未对齐的差异；
- 疑问项；
- 后续阶段需要补齐的视觉细节。

### 不做

- 不做真实业务流程；
- 不接后台接口；
- 不写死模型、价格、时长、分辨率、数量；
- 不新增首页；
- 不新增登录、会员、充值、云同步；
- 不把对话页做成直接生成入口。

### 验收标准

- 八个一级页面组件存在；
- 基础组件存在并可复用；
- 样式开始使用 Design Tokens；
- UI 对照记录已创建；
- `npm run dev` 可启动；
- 不修改 `handoff/`；
- 不违反交接包禁止事项。

## 六、合并顺序建议

建议合并顺序：

1. 先合并 UI 开发者 A 的 `feature/ui-shell-layout`；
2. 再合并 UI 开发者 B 的 `feature/ui-pages-tokens`。

如果两人必须并行：

- A 只负责 `src/ui/`；
- B 只负责 `src/pages/`、`src/components/`、`src/styles/`；
- `src/ui/App.tsx` 尽量只由 A 修改；
- B 如需接入页面组件，可以先导出组件，等 A 合并后再接入。

## 七、阶段 1 完成标准

阶段 1 完成时，应满足：

- Electron 应用能在 Windows 上启动；
- 八项一级导航可切换；
- 每个一级页面有空状态骨架；
- 基础主题和 Design Tokens 接入；
- 基础组件可复用；
- UI 对照记录完成；
- 未接后台接口；
- 未新增禁止功能；
- `PLANS.md` 更新真实验收结果。
