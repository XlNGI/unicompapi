# 阶段 4｜连接与能力服务端口记录

日期：2026-07-22
分支：`feature/provider-capability-services`
负责人：开发者 B｜领域与平台

## 一、本次实现

- 定义 `ConnectionValidationPort`、`ModelCatalogSyncPort` 和 `CapabilityValidationPort`，三类事实分别验证和保存。
- 建立手工模型登记；新模型默认停用，不自动创建能力证据。
- 建立用户能力证据更新，只允许明确记录 `user_confirmed` 或 `unsupported`。
- 建立连接验证证据写入，连接可用、身份验证和凭证验证分别保存。
- 建立目录同步，更新同名目录模型并追加新模型，不删除未返回的手工模型。
- 建立能力验证证据写入，来源固定为 `connection_verified`，不会冒充用户确认或厂商声明。
- 建立用途、模型、优先级和启用状态分离的路由偏好。
- 建立只读路由计划；候选按优先级排序，但不自动提交任务。

## 二、真实状态边界

- 当前没有后台 Base URL、鉴权、接口路径、请求/响应和错误码契约，因此 Electron 未注入任何真实服务商适配器。
- 调用连接验证、目录同步或能力验证时，当前明确返回 `adapter_unavailable`。
- 无适配器时不修改连接为可用，不生成模型目录，不写入已验证能力。
- 手工模型登记后能力保持无证据状态，不推断为支持。
- 路由计划中的费用、隐私和地区均为 `unknown`。
- 所有路由计划固定返回 `requiresSubmissionConfirmation: true`，不能绕过费用与外发确认。

## 三、renderer IPC

```text
window.unicomp.providers.validateConnection(connectionId)
window.unicomp.providers.syncModelCatalog(connectionId)
window.unicomp.providers.registerManualModel(connectionId, name, displayName)
window.unicomp.providers.validateCapability(modelId, capability)
window.unicomp.providers.recordUserCapability(modelId, capability, state)
window.unicomp.providers.saveRoutingPreference(purpose, modelId, priority, enabled)
window.unicomp.providers.planRoute(purpose)
```

所有错误使用受控错误码和通用消息，不返回 endpoint、凭证、绝对路径或内部堆栈。
