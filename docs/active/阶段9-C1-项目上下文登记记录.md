## 一、批准边界

项目负责人批准继续实施 C1 第二批“项目上下文登记”。本分支只实现 ProjectContext 领域契约、项目范围版本仓储和非 UI 应用服务；继续复用第一批应用级 Conversation 仓储，不建立第二套 Conversation 事实源。

本分支未修改 React、preload、Electron 主进程或 IPC，未实现供应商/模型适配器、HTTP、原生文件选择、附件解析、图片/视频 Task、Execution、Work 或任何自动外发行为，也未修改最终 UI 与开发交接包原件。

## 二、实际修改

- 新增 `ProjectContextId`、`ProjectContextDraftId` 和 `ProjectContextFragmentId` 强类型 ID；
- 新增项目上下文草稿，草稿必须显式记录目标 `projectId` 和唯一 `conversationId`；
- 草稿支持创建、预览、增加/移除消息片段和修改用户标签；草稿与正式上下文严格分离，草稿不会进入项目上下文候选列表；
- 一个草稿允许选择同一 Conversation 的多个 Message 片段，拒绝跨 Conversation 混合；
- 每个片段冻结 ConversationId、MessageId、Message revision、Message role、UTF-16 选择范围、选择顺序和 NFC/LF 规范化内容快照；
- 应用服务只按 ID 从第一批 ConversationRepository 读取已保存 Conversation，不接受临时 Conversation 对象；
- Conversation、Message 必须真实存在，Message 必须处于 completed；pending、streaming、failed 和 cancelled 均不能登记为正式上下文；
- 登记前再次核对消息 revision、角色、选择范围和规范化内容，来源变化时失败关闭；
- 正式登记必须收到显式确认，登记操作在项目仓储的一次原子写入中删除草稿并创建 context revision 1；
- 正式上下文使用稳定 contextId、连续递增 revision、不可变版本数组、currentRevision 指针和 active/deleted 状态；
- 内容、用户标签和 sourceStatus 更新均追加新 revision，不覆盖旧版本；
- 普通删除追加纯墓碑 revision，保留内容、标签和来源事实，不删除来源 Conversation；
- sourceStatus 支持 `available | source_deleted | source_unavailable`；来源 Conversation 后续删除时只追加 `source_deleted` revision，已登记内容快照继续有效；
- sourceKind 使用 Schema v1 的宽泛 `conversation_selection`，不包含供应商、模型或页面名称；`user_note`、`image_analysis` 和 `imported_content` 仅保留为后续正式来源类别，不在本分支伪造实现；
- 新增项目候选、当前详情、指定 revision 和来源状态查询；应用层 DTO 只返回受控 ID、revision、状态、标签、来源片段和内容快照；
- DTO 不返回路径、Hash、凭证、endpoint、仓储路径或内部适配器信息；
- 新增项目范围 `entities/project-contexts.json` 注册表，草稿和上下文共享一个版本化文档，避免登记跨文件半完成；
- 仓储实现严格 Schema 校验、显式连续迁移入口、文档 revision、草稿/context 乐观并发和同一存储适配器的串行写入；
- 项目存储适配器继续负责同目录临时文件、文件 `fsync`、原子替换和目录同步；
- 只有验证通过的主文件可以更新 `.bak`；主文件损坏时只读取有效备份且不覆盖损坏证据，主文件与备份均无效时失败关闭；
- 仓储保存正式上下文时验证历史只能追加一个新 revision，拒绝覆盖或重写旧版本。

## 三、自动化测试

- 多 Message 片段顺序与规范化快照；
- 跨 Conversation 片段拒绝；
- 未保存 Conversation 拒绝；
- pending Message 拒绝；

- 正式登记与草稿原子移除；

- 来源 Conversation 删除后上下文继续有效并追加 `source_deleted`；
- 来源 Conversation 不可读取时追加 `source_unavailable`，登记快照继续有效；
- 普通删除形成墓碑且不删除来源 Conversation；
- 项目范围、Schema 损坏、未来版本和缺失迁移拒绝；

- 损坏主文件的有效备份读取与双损坏失败关闭；
- 临时文件清理；
- 应用 DTO 的路径、Hash、凭证、endpoint、仓储字段边界。
