## 二、实际实现

### 2.1 项目级迁移读模型

新增 `ProviderContractsDataMigrator` 和项目级 `migrations/provider-contracts-v1.json`：

- 原始历史文件保持不变，新迁移结果以追加 run 保存，不覆盖或删除旧 Draft、Task、Execution、ProviderOperation、Work、Conversation、Message 或 ProjectContext；
- 迁移源按规范化事实计算内部 SHA-256 指纹，同一事实重复执行返回既有 run，不增加逻辑 revision；源集合顺序变化不改变结果；源事实变化时追加新 run；
- 写入使用共享项目存储协调、原子替换和 `.bak`，主文件损坏时可从上一有效备份读取；
- 每个 run 明确记录 `sourceFactsPreserved=true`、`providerInvocationFactsCreated=0` 和 `providerUsageFactsCreated=0`，禁止伪造历史上不存在的调用或用量事实。

### 2.2 Draft 与快速页参考素材迁移

迁移规则落实为：

- 旧快速生图无素材映射为 `text_to_image`；带一张图片映射到专业生图 `reference_to_image`；
- 旧快速视频无素材映射为 `text_to_video`；带一张图片映射到专业图生视频 `image_to_video`；带视频或无法确定的多素材进入只读阻断；
- `saved_conversation` 不自动外发，迁移结果标记 `saved_conversation_requires_project_context`，必须由用户显式登记 ProjectContext；
- 旧模型、Evidence、参数和确认全部清除并要求重新确认；只保存映射版本和旧稳定 ID，不猜测 Model/Profile/协议或能力；
- 本地视频编辑 Draft 标记为 `preserved_local`，不错误映射为服务商 ProductFeature。

### 2.3 历史调用、路由和 usage

旧 Task、Execution、ProviderOperation 和 Work 只生成安全只读调用投影：

- 不公开远端 operation ID、URL、Base64、file URI、Prompt、原始响应、路径或 Hash；
- 不创建 ProviderInvocationAttempt/Event，也不创建 ProviderUsageObservation；
- 历史 usage 固定为 `not_collected_legacy`，不补写为 `0`；
- 异步旧记录只有在存在显式、版本化的 execution→RouteSnapshot 映射时才标记 `mapped`；否则进入 `legacy_route_unavailable + unrecoverable`，禁止猜测适配器或自动恢复；
- Work 只按 `sourceExecutionId` 投影，不改写旧双向兼容字段。

### 2.4 Conversation、Message 与 ProjectContext

- `projectId=null` 的历史 Conversation 保持 `unbound_read_only`，不会自动归属当前项目；
- 项目所属 Conversation 保留 revision 和 Message 数量事实；
- 已登记 ProjectContext 保留 current revision 和来源 Conversation，迁移不复制消息正文或自动建立新的外发上下文。

### 2.5 Registry 包归属与恢复

新增显式 Provider/Connection Package ownership 迁移：

- 必须提供完整 package/template、CredentialSchema、EndpointPolicy、连接配置 revision 和 Adapter Binding；
- Adapter Binding 必须精确匹配该 Connection 下唯一的 protocol ID、protocol version 和 adapter kind，缺失或歧义时拒绝，不能按名称或 URL 猜测；
- 未映射 Provider/Connection 保持原状并列入 unmapped 结果，不自动分配 Package；
- 迁移通过 Registry CAS 保存，冲突时重新读取最新 revision；重复映射不增加 revision；
- Registry 每次覆盖前写入 `.bak`，显式恢复时 revision 在当前值基础上继续单调递增。
