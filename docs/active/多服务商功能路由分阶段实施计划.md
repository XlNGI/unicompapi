# 多服务商功能路由分阶段实施计划

日期：2026-07-31

状态：M0 已冻结；M1 已实现并通过自验收，未启动 M2

基线：`develop@01142f7`

权威方案：`docs/active/阶段9-UI与多服务商功能路由最终方案.md`

## 一、计划结论

本项属于较大规模的后台契约、协议适配器、路由快照、历史迁移和 UI 接线工程，不能一次性实现，也不应以一个大 PR 收口。

实施采用“一支一验收、一支一合并、一支一停止”的节奏。每支合并后，下一支必须重新从最新 `develop` 创建；本计划本身不批准任何实现分支、真实联网、凭证验证或收费调用。

## 二、启动闸门

只有以下条件全部满足，才进入第一支实现：

1. 阶段 9 已在 Windows x64 必需目标与 macOS 延期目标边界内收口，记录为 `develop@01142f7`；
2. 项目负责人确认快速页是否移除单参考素材；
3. 项目负责人明确批准第一支 `feature/local-json-persistence-foundation`；
4. 第一支的允许修改范围、测试范围、是否联网和费用上限明确记录；
5. 当前 Vidu 真实预算保持封存，不恢复流程 8 通道。

当前状态：第 1—5 项均已满足。项目负责人已批准 `feature/local-json-persistence-foundation`，允许普通工程联网并授权 Codex 按冻结门禁自行验收及在通过后非快进合并；本分支禁止真实 HTTP 和收费调用，因此实际费用为 0。

已冻结的第 2 项产品决策（2026-07-31）：

- 快速生图固定为纯文生图 `text_to_image`，不接收参考图或其他参考素材；
- 快速视频固定为纯文生视频 `text_to_video`，不接收参考图片、参考视频或其他参考素材；
- 参考图生图、图生视频及其他需要素材的功能继续进入对应专业页面，并由显式 `ProductFeature` 与受控素材槽位承载；
- 不得根据草稿中是否存在素材静默切换快速页协议或功能。

## 四、分支顺序

### M1：本地持久化基础

1. `feature/local-json-persistence-foundation`

范围：应用/项目文件边界、Schema envelope、revision/CAS、原子写入、备份、journal、恢复扫描、幂等和历史迁移底座。

禁止：供应商页面、真实适配器、真实 HTTP、Vidu 预算恢复。

验收结果：实现提交 `f0e6ecc` 已通过 Node 178 项与 Vitest 395 项，共 573 项完整回归，以及类型检查、Lint、生产构建、平台审计、交接校验和恢复审计。工程记录见 `docs/active/多服务商功能路由-M1本地JSON持久化基础记录.md`。

### M2：安全与后台基础契约

按以下顺序逐支执行：

1. `feature/vidu-runtime-authorization-closure`
2. `feature/provider-package-connection-contracts`
3. `feature/provider-registry-atomic-catalog`
4. `feature/provider-runtime-authorization-contracts`
5. `feature/provider-feature-contracts`
6. `feature/project-conversation-context-snapshots`
7. `feature/provider-invocation-usage-contracts`
8. `feature/provider-execution-route-snapshot`
9. `feature/provider-text-streaming-contracts`
10. `feature/provider-public-candidates-orchestration`
11. `feature/provider-contracts-data-migration`

关键产出：

- 运行授权与流程 8 验证授权彻底分离；
- Provider/Connection/Model/Feature/Profile 具备版本化、原子和可恢复合同；
- Context、Usage、RouteSnapshot 和候选选择令牌成为主进程唯一事实；
- 旧 Draft、Task、Execution、Message、Context 和路由记录具备明确迁移或不可恢复状态；
- 不以模型名称、URL 或任意 JSON 自动猜测协议能力。

### M3：后台应用服务与协议适配器

以下分支在各自合同依赖满足后执行；可并行实现，但必须分别验收：

1. `feature/provider-management-framework`
2. `feature/provider-invocation-read-model`
3. `feature/deepseek-chat-adapter`
4. `feature/volcengine-doubao-vision-adapter`
5. `feature/volcengine-seedance-video-adapter`
6. `feature/kling-video-adapter`
7. `feature/newapi-provider-package`
8. `feature/vidu-provider-package-migration`

每个适配器必须先完成官方合同证据、参数映射、合成成功/失败响应、取消、结果解析和 UsageSchema 测试。真实联网、凭证验证和收费测试不包含在本计划默认授权内。

### M4：后台与适配器集成验收

1. `feature/provider-backend-integration-acceptance`

必须覆盖：

- 官方连接与兼容自定义连接的安全合同；
- 模型发现、精确 Profile、启停和候选选择；
- 快速页纯文本输入、快速/专业参数投影，以及专业图生图/图生视频单图约束；
- 对话、项目上下文和媒体外发快照；
- 同步、异步、文本调用的状态、取消、恢复和用量完整性；
- 全部使用合成 transport，真实 Token、网络和收费次数为 0。

该分支通过前，不得启动任何 `feature/ui-*` 分支。

### M5：UI 后置接线

每支均需项目负责人单独批准：

1. `feature/ui-provider-management-wiring`
2. `feature/ui-conversation-context-wiring`
3. `feature/ui-image-feature-wiring`
4. `feature/ui-video-feature-wiring`
5. `feature/ui-task-call-records-wiring`
6. `feature/ui-provider-acceptance-closeout`

UI 只消费已合并的安全 DTO、ParameterSchema、选择令牌、调用读模型和提交端口，不在 React 中新增模型名称、协议判断、usage 字段路径或适配器分支。

## 五、单支执行门禁

每支分支都必须完成以下闭环：

1. 从包含全部依赖的最新 `develop` 创建；
2. 只修改该支声明的合同、适配器、测试和工程记录；
3. 补齐成功、失败、取消、恢复、并发、迁移和安全边界测试；
4. 运行：

   ```text
   npm.cmd test
   npm.cmd run typecheck
   npm.cmd run lint
   npm.cmd run build
   npm.cmd run audit:platform
   npm.cmd run verify:handoff
   npm.cmd run verify:recovery-audit
   git diff --check
   ```

5. 涉及 Electron、preload 或 UI 时增加 Windows Electron 启动、可见窗口和清理烟测；
6. 更新对应工程记录、证据和 `PLANS.md`；
7. 项目负责人验收后，非快进合并 `develop`，保留本地与远程功能分支；
8. 合并后停止，不自动启动下一支。

## 六、联网与数据安全闸门

- M1-M4 默认只允许临时目录、内存 transport、合成响应和零网络测试；
- 真实服务商请求、凭证验证、费用和用量验证必须建立新的专项批准，不由本计划继承；
- Vidu 两项已用尽预算不得恢复，Image V1 不得因本计划晋级；
- Token、API Key、绝对私有路径、原始响应、签名 URL、Prompt、媒体和原始日志不得进入 Git 或证据；
- 任何未知提交结果必须进入 `unknown_outcome`，禁止自动重试；
- 任何未完成本地校验的远端结果不得登记 Work。

## 七、停止条件

出现以下任一情况，立即停止当前支，不增加调用次数或静默切换协议：

- 依赖分支未合并或最新 `develop` 事实不一致；
- 迁移可能覆盖历史、丢失数据或无法恢复；
- DTO、日志、诊断或证据泄漏凭证、路径、Hash、Prompt 或原始响应；
- 适配器只能靠模型名称猜测能力，或把未知 JSON 当作兼容协议；
- 测试出现失败、未解释跳过、假进度、假用量或假 Work；
- 需要真实联网、凭证或收费但没有新的专项批准。

## 八、当前下一步

M1 已通过自验收并按授权非快进合并后停止，不自动启动 M2。下一次项目负责人批准应明确写出：

- 是否批准 `feature/vidu-runtime-authorization-closure`；
- 该支允许修改的文件范围；
- 是否允许联网（默认否）；
- 费用上限（默认 0）；
- 验收负责人和合并条件。

下一支只有在 M1 合并后重新读取最新 `develop` 并获得单独批准才可创建。
