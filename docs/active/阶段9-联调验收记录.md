## 八、阶段 9 智能文档工作流扩展决策（2026-09-01）

项目负责人重新制定阶段 9 后续规则：在既有跨平台工程基线上新增智能文档工作流扩展。该扩展不改写本记录前述 Windows x64 收口结论，也不表示相关能力已经实现。

批准的目标流程为：

```text
用户自然语言
→ LLM 意图/参数判断
→ 完整性与歧义检查
→ 必要时追问
→ 企业资料分层 RAG
→ 经授权的联网搜索（可选）
→ 内容大纲与可选确认
→ 页面结构/视觉计划
→ 受控工具执行
→ PPTX 生成与 PDF/图片渲染
→ 结构/视觉校验
→ 有限修正计划与自动修正
→ PPT、来源和生成说明交付
```

新增扩展的工程约束：

- LLM 只输出 `DocumentIntentPlan`、`DocumentOutline`、`PresentationPlan` 和 `RepairPlan` 等受控结构，不直接决定路径、凭证、Provider、权限、费用、Work 或任意代码；
- Application 层负责计划 Schema、会话实体、项目范围、页面/表格范围、授权、预算和状态校验；Platform 层只执行白名单工具；
- 本地规则保留为明确请求的快速路径和 LLM 失败回退；复杂或歧义请求才调用 LLM；
- 企业资料优先本地检索，BM25 继续作为基础和回退。向量检索须经过脱敏评测、索引治理和负责人批准，不绑定具体数据库或 embedding 服务；
- 联网搜索必须用户明确授权，并具备外发脱敏、域名/来源策略、预算、超时、缓存、引用、内容 Hash 和离线回退；不得自动上传企业附件全文；
- 附件、项目上下文和外部网页均按“不可信参考资料”处理，不能覆盖系统指令；
- Agent 仅允许有限步数和有限修正次数，必须支持取消、失败隔离和恢复，禁止无界循环、无限重试和无依据整套重写；
- 大纲和中间计划属于草稿，最终文件仍须完成本地内容、布局、字体、溢出、重叠、Hash、原子发布和 Work 登记门禁；
- 扩展复用现有对话页和文档工作区，不新增业务一级页面；阶段 10 安装包、签名、公证、更新、SBOM 和正式发布边界不变。
