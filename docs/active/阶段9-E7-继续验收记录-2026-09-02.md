# Phase 9 E7 continuation acceptance record

Status: `approved/in_progress`. This addendum records the continuation implementation and does not mark E7 as passed.

## Implemented

- NewAPI and DeepSeek now expose a bounded native tool-calling bridge. Streamed deltas are assembled and checked against the eight document-tool allowlisted names. Tool execution is injected through `ControlledProviderToolBridge`; results are bounded and redacted before being sent back as `tool` messages. The bridge limits rounds to 1-4 and fails closed on cancellation, invalid JSON, oversized results, invalid calls, or loop exhaustion.
- The local Office/PDF/PNG adapter now validates PNG signatures and dimensions, PDF/image page-count parity, empty pages, text bounds, and overlapping text boxes using local PDF.js inspection. Error diagnostics reject the temporary candidate before publication. Renderer absence, timeout, and cancellation remain fail closed.
- Same-section complex revisions now emit multiple `replace_text` or `update_cells` patches where the proposal changes multiple Word paragraphs or Excel cells. Existing eight-target, duplicate-target, scope, and hash gates remain enforced.
- The conversation dispatch plumbing now preserves an optional `toolCalling` capability from the Application composition root through the chat adapter wrapper. When explicitly configured, the wrapper injects the allowlisted tool definitions and bridge into NewAPI/DeepSeek; the default Electron chat composition leaves this capability unset so ordinary chat cannot acquire document file scope or write authority implicitly.
