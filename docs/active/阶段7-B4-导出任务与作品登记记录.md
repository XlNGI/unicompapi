# 阶段 7 B4｜导出任务与作品登记记录

## 1. 实施范围

B4 在 `feature/video-export-pipeline` 完成阶段 7 后端导出闭环：

```text
VideoEditDraft
  -> preflight
  -> immutable VideoExportPlan
  -> video_editing Task + attempt Execution
  -> frozen source verification
  -> FFmpeg process / progress / cancellation
  -> independent ffprobe output verification
  -> fsync + no-overwrite publication
  -> verified FileReference + SHA-256
  -> Work registration
  -> completed Execution
```

导出计划保存在 `entities/video-export-plans.json`，并在 `tmp/editor/<taskId>/<attempt>/export-plan.json` 留存尝试快照。计划包含草稿 revision、输入身份、时间线、画布、文字、音频、封面、输出冲突策略、引擎版本和计划 Hash；仓储读写会重新计算并校验 SHA-256。

## 2. 状态与故障语义

- 正常路径为 `queued`、`validating_sources`、`preparing_media`、`encoding`、`writing_file`、`verifying_file`、`registering_work`、`completed`。
- `needs_user_action` 必须携带持久化 `requiredAction`，当前代码为 `source_unavailable` 或 `destination_unavailable`；可创建新的 attempt，旧尝试不被覆盖。
- `cancel_requested` 只有在媒体进程确认停止后才能进入 `cancelled`；取消不会登记 Work。
- 失败保留 `Execution.failure` 和原 attempt；可重试失败创建递增 attempt。
- 启动恢复会扫描仍处于导出阶段的尝试，标记为 `interrupted` / `recovery_required`；`registering_work` 阶段会先验证 FileReference 和 Work 事实，完整时才恢复为 `completed`。
- 只有独立输出探测、文件校验、SHA-256、FileReference 持久化、Work 登记和 Execution 完成全部成功，才向作品库公开 Work。

## 3. 媒体引擎边界

当前批准的 FFmpeg 8.1.2 LGPL-only 工具链仅用于本地开发和测试，安装到被 Git 忽略的 `.tools/`。B4 使用参数数组启动 FFmpeg/ffprobe，禁止 shell 拼接；真实进度来自 `-progress`，取消等待进程确认，输出先写临时文件并同步后以不覆盖方式发布。

本阶段能力快照为软件 `libvpx-vp9` / `libopus` / WebM。由于批准的开发工具链没有已验证硬件编码器，硬件失败回退路径已保留为后续能力接入边界，本阶段没有伪造硬件尝试或硬件成功事实；软件导出不会因硬件不可用而被阻断。

FFmpeg 二进制、压缩包不得提交仓库，也不得进入生产构建或发布物。编解码器白名单、专利/商业分发审查、签名、跨平台构建和 macOS 实机证据仍属于后续批准工作。
