## 一、任务范围

本次只建立图片创作五模式的本地领域、持久化和受控 renderer 契约，不实现图片文件导入、上传、远端生成、识别、编辑、提示词分析、任务提交或结果接收。

- 图片工作区领域实体、类型与运行时不变量；
- 图片工作区仓储端口、版本化 JSON 仓储和项目目录路径；
- renderer 安全 DTO、preload 暴露和 Electron 主进程 IPC；

- `PLANS.md` 和阶段 5 工程记录。

## 二、实际修改

### 1. 五模式领域契约

新增 `ImageWorkspaceDraft` 判别联合，只允许：

1. `quick_image`；
2. `professional_image`；
3. `image_understanding`；
4. `image_editing`；
5. `image_to_prompt`。

公共契约包含当前项目 ID、草稿 ID、状态、来源、提示词快照、可选单图引用、上下文引用和时间戳。单图引用只能有一个，并按模式限制为参考图或源图；区域使用 0 到 1 的归一化坐标。

提示词继续区分用户原始输入、系统补充和最终提示词，持久化和派生时分别复制，不互相覆盖。

### 2. 动态能力与模式专属事实

- 快速生图和专业生图只保存模型 ID、能力证据 ID 和动态参数键值，不定义固定模型、尺寸、格式、数量或费用字段；模型与参数同时存在时必须引用同一能力证据。
- 图片识别分别保存可见事实、模型推断、不确定和无法识别四类模型原始结果，用户修订使用独立记录并可引用原始观察项，不覆盖原结果。
- 图片编辑保存源 Asset、可选蒙版、必须保持、必须修改、禁止内容和父草稿/Asset/作品版本关系；父 Asset 必须与当前单图输入一致。
- 图片转提示词保存用途、要求、事实/推断/不确定/无法识别结果，以及输入、区域、用途或要求变化后的过期原因；旧结果过期时仍保留用于追溯。
- 派生操作复制提示词、单图和上下文，但只创建新本地草稿，不创建任务、执行或作品。

### 3. 本地仓储与 IPC

新增 `ImageWorkspaceRepository` 和 `JsonImageWorkspaceRepository`，数据保存在项目目录的：

```text
entities/image-workspace-drafts.json
```

仓储使用版本 1 集合、项目作用域隔离、实体 ID 去重、运行时校验、原子 JSON 写入和进程内写入串行化。

新增受控 IPC：

- `create`：在当前项目创建本地空草稿；
- `get`：按草稿 ID 读取；
- `update`：以 `updatedAt` 做乐观并发检查，禁止修改项目、模式、创建时间和来源；
- `list`：列出当前项目图片草稿；
- `derive`：从现有草稿创建另一模式的派生草稿。

没有打开项目时上述操作返回 `project_not_open`。renderer DTO 只包含项目内实体 ID 和可展示的草稿事实，不包含项目根目录、绝对路径、原始 Hash、凭证、endpoint 或内部错误堆栈。
