# 对话内 Office 文档生成｜存储治理策略

日期：2026-08-23

状态：治理决策登记，代码落地按后续 PR 实施。

## 一、背景

对话内文档生成会在项目内持续产生两类文件：

- `files/documents/`：生成的 Office 文档（每次生成一个文件，改稿产生新版本）；
- `files/attachments/`：拖入的附件副本（txt/md/csv/docx/pdf/xlsx/pptx/图片），供提取、识图与配图使用。

两类文件均登记为项目 FileReference，其中已登记正式作品的文档不可随意删除（作品库与任务中心依赖）。

## 二、策略

1. **正式作品保留**：`mediaKind: document` 的 Work 及其文件默认永久保留，删除必须走作品级显式操作（当前无删除入口，后续单独设计）；
2. **附件保留与清理**：
   - 附件副本保留期默认 90 天无引用后清理（被当前项目素材、上下文或消息附件引用的不清理）；
   - 清理前展示待清理清单与大小，用户确认后执行；执行结果写入任务中心/日志；
   - 清理为可恢复操作：先移入项目回收目录，30 天后物理删除；
3. **文档版本管理**：改稿产生的新版本作为独立 Work 保留；可选“合并历史版本/仅保留最新”策略需负责人批准后实现；
4. **容量预警**：`files/` 总大小超过阈值（默认 2GB，可配置）时在设置页提示，不自动删除；
5. **备份兼容**：项目备份/恢复（阶段 2 机制）必须包含 `files/` 目录；清理操作不得破坏 FileReference 与校验链。

## 三、落地拆分（后续 PR）

- PR-存储1：附件引用计数与“90 天未引用”扫描服务 + 待清理清单 IPC/UI；
- PR-存储2：回收目录迁移与 30 天物理删除 + 容量预警；
- PR-存储3：文档版本合并策略（需负责人批准）。

## 四、智能文档扩展的索引与外部证据治理（负责人批准：2026-09-01）

阶段 9 智能文档扩展新增的 BM25 索引、向量索引、embedding 和联网搜索缓存均属于可重建的派生数据，不得成为企业原始资料或正式作品的唯一事实源。

1. **索引作用域**：每个索引条目必须绑定 `projectId`、`fileId` 或受控外部证据 ID；不得跨项目检索，不得把内部资料索引放入全局共享目录。
2. **内容一致性**：索引条目记录源文件 `contentHash`、索引版本和 embedding 模型版本。源文件变更、删除或权限撤销后，旧条目必须失效或删除；索引损坏时必须能够从源文件重建。
3. **备份与恢复**：项目备份可以包含可验证的本地索引，也必须支持不携带索引、从 `files/attachments/` 和已登记外部证据重建。索引不得包含 API Key、Token、私有路径或未经授权的完整外发响应。
4. **联网缓存**：外部搜索结果保存最小必要证据，至少包含来源、检索时间、发布时间（若有）、摘要和内容 Hash；缓存保留期、容量、清理和离线可用性必须在 E3 实施前明确，不得无限增长。
5. **删除联动**：附件、项目上下文、外部证据或用户授权删除后，关联 BM25/向量条目和联网缓存必须进入同一清理计划；未清理的残留不能继续参与生成。
6. **作品边界**：检索片段、embedding、网页缓存和中间计划不登记为 `Work`；只有最终文件通过既有本地校验、Hash、原子发布和登记流程后，才能成为正式作品。

具体索引实现、向量数据库/embedding 选型、联网缓存保留期和外部证据删除策略，分别在 E2/E3 PR 中提出并经过独立评测和负责人确认；未完成前继续使用现有 BM25 和项目内文件事实源。
