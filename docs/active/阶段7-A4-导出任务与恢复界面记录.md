## 实现范围

- 复用 B4 的 `preflightExport`、`startExport`、`getExport`、`cancelExport` 和 `retryExport`，不建立 renderer 侧任务仓储。
- 导出确认展示真实来源、目标、容器、编解码器、质量说明、软件编码能力和空间校验时机。
- 文件名与同名冲突策略必须先保存；存在未保存修改时不允许预检或开始导出。
- 展示后台任务阶段、真实进度、取消中、失败、需要用户处理、中断和恢复状态。
- 重试创建新 attempt，旧 attempt 继续保留在任务中心。
- 只有 `completed` 且存在已登记 `workId` 时，才创建受控媒体预览并开放文件定位与作品库入口。

## 边界

- 页面不接收文件路径、Hash、引擎命令或进程句柄。
- 不把进程退出、临时文件存在或进度到达 100% 当作导出成功。
- B4 当前只声明 `software_only`，A4 不伪造硬件编码或硬件失败回退 attempt。
- 预计输出体积来自预检；真实目标可写空间由 B4 在执行开始时检查。
- `.tools/`、FFmpeg 二进制和下载归档不进入 Git 或生产构建。

## Windows Electron 真实业务验收

项目负责人在隔离的临时项目和用户目录中执行以下真实流程：

1. 在生产 Electron 中创建项目与空白编辑草稿，通过受控原生选择器引用 640×360、3 秒 MP4。
2. 加载 `unicomp-media` 短期原片预览，媒体 `readyState=4`、时长 3 秒。
3. 修改导出文件名但不保存，确认保存按钮启用，预检与开始导出保持禁用；保存后草稿 revision 从 1 增至 2。
4. 使用已验证 FFmpeg 8.1.2 LGPL-only 开发工具链完成真实预检，确认 WebM、`libvpx-vp9`、`libopus`、`software_only` 和执行时磁盘空间检查事实。
5. 明确勾选确认后创建后台任务；页面先后显示排队、43% 编码进度和完成，completed 前没有成功或作品入口。
6. 独立 ffprobe 结果为 VP9 视频、Opus 音频、640×360、3.006 秒；输出 322364 字节，SHA-256 `f13b6dbe39a81b008db73c919d3c920e36f8b4ca31034ea4e3666369f9dd9854` 与 FileReference 登记值一致。
7. 只有完成 Execution、FileReference 和 Work 登记后页面显示“导出成功”；已登记作品预览 `readyState=4`，任务中心显示 1 个已完成视频编辑任务，作品库显示 1 个可用视频作品。
8. 离开并重新进入基础编辑页后，已完成任务、Work 和受控预览恢复；测试进程、临时项目、媒体和隔离用户目录随后清理。
