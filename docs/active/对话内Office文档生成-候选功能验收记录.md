## 一、批准边界

项目负责人批准按“对话式改稿 → 模板风格迁移 → AI 生图配图 → 关键词检索/RAG”顺序实施候选功能；AI 配图明确批准使用用户已配置的图片模型，生成前展示费用与外发确认，默认关闭。

## 二、实际修改

- **对话式改稿**：文档卡片出现后继续在文档模式发送修改要求，系统自动把上一版文档正文作为上下文交给模型改写，生成新版文档挂到新消息，旧版保留不覆盖（`composeDocumentRevisionInput`）；
- **PPTX 模板风格迁移**：拖入的 PPTX 附件可设为样式模板，主进程解析 `theme1.xml` 的 clrScheme 提取主题色，作为自定义主题覆盖生成（`pptx-theme-extractor.ts`）；
- **AI 生图配图**：
  - 文档模式“AI 配图”开关（默认关）+ 生成前确认弹窗；
  - 图片模型选择器（仅列可用且参数可自动省略的候选，不写死服务商/模型）；
  - 按分节标题生成图片描述，走现有 `text_to_image` 候选/路由/下载/SHA-256 校验/Work 登记；
  - 程序化调用产生的临时快速草稿在候选查询与生成完成后自动删除，图片工作区零污染；
- **成品模板 v1**：封面强调色带与装饰条、分节标题左侧主题色竖条、正文/表格/图表圆角卡片容器，全部由主题色确定性派生；
- **结构化内容契约与清洗**：转档前剥离“好的/以下…”开场白（`stripPreamble`），内容若为 JSON 大纲（含 ```json 包裹）走严格契约校验（`parseDocumentOutline`），失败回退 Markdown（`parseMarkdownToOutline`）；行内 Markdown 标记（加粗/斜体/链接/代码/删除线）在转档时统一剥离；
- **关键词检索与 RAG**：BM25 检索（中文按字符+双字 bigram 分词、打分、top-k）；`RagRetrievalService` 对项目附件全文按 500 字切块建索引；对话页“检索资料”开关开启时按需求检索 top-3 片段作为上下文交给模型，指令明确“必须基于资料撰写、不得编造”，检索空结果给出提示。
