## 一、任务范围

## 二、实际修改

### 1. 动态能力 Schema 与预检

阶段 4 `ModelCapabilityEvidence` 增加版本 1 动态参数 Schema。Schema 只定义通用字段结构：字段键、显示名、字符串/数字/整数/布尔/枚举类型、必填、枚举值和数值范围；不在应用中预置尺寸、格式、数量、质量或任何服务商参数名。

预检按图片模式映射用途：图片生成、图片识别、图片编辑和图片转提示词。候选必须同时满足：

- 存在启用的对应路由偏好；
- 模型已启用；
- 连接状态为 `available`；
- 存在 `verified_supported` 或 `user_confirmed` 能力证据；
- 能力证据包含动态参数 Schema；
- 草稿参数只包含 Schema 字段，必填、类型、枚举和范围均有效；
- 若草稿显式选择模型或能力证据，候选必须与其一致。

缺失事实不会推断为支持，分别返回无路由、能力未验证、Schema 缺失、参数非法或适配器不可用。

### 2. 确认快照、任务与执行

创建图片 Task 前必须显式确认接收方、外发范围、费用状态、最终提示词和模型。确认快照保存：

- 模式与用途；
- 模型、能力证据、服务商和连接 ID；
- 接收方显示名、访问类型和外发范围；
- 费用、隐私与地区状态，当前未知时保持 `unknown`；
- 动态参数值和最终提示词；
- 图片编辑父作品 ID（如存在）。

预检不创建 Task，创建 Task 不创建 Execution，创建 Execution 不调用远端。调用端口按图片生成、识别、编辑和提示词分析分开注入。Electron 当前没有注入真实端口，因此预检和调用均明确返回 `adapter_unavailable`。

调用成功后远端 operation ID 仅保存于 Execution 内部实体；renderer 只接收执行 ID、任务 ID、尝试次数、状态和可重试性。提交失败保留失败 Execution，允许重试时必须创建新 ID 和递增 attempt。

### 3. 结果接收与作品登记

结果接收器只处理具有远端 operation ID 的 queued/processing Execution，并按以下顺序执行：

1. 查询真实远端完成结果描述；
2. 标记 `remote_completed` 与 `downloading`；
3. 下载到项目 `tmp` 临时文件；
4. 按真实内容识别图片 MIME 和像素尺寸；
5. 校验实际字节数和 SHA-256，并与远端声明值比较；
6. 进入 `writing`，对临时文件执行 `fsync`；
7. 原子移动到 `files/results`；
8. 重新校验落盘文件；
9. 保存 available FileReference 和派生文件索引；
10. Execution 完成后才登记 Work。

下载、内容类型、字节、Hash、落盘或索引失败时不登记 Work。失败执行保留真实阶段和重试性；未形成正式文件事实的临时/结果文件会清理。图片编辑结果沿用确认快照中的父作品 ID，形成非破坏版本关系。

## 三、安全边界

- renderer 不接收绝对路径、SHA-256、endpoint、凭证引用、远端 operation ID 或内部错误堆栈；
- 未知费用、隐私和地区保持 `unknown`；
- 自动路由不绕过显式确认；
- 无适配器不伪造调用成功、队列、进度或结果；
- 未通过本地校验的下载结果不能登记为 Work；
- 保存草稿永远不触发预检、Task、Execution 或远端调用。
