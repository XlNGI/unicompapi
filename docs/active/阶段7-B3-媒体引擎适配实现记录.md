## 一、实现范围

本次实现新增通用 `MediaEngineAdapter` 端口和 FFmpeg 实现，适配器只运行在主进程，接受主进程持有的受控绝对路径和结构化计划：

- `getCapabilities()`：读取 FFmpeg 版本、编码器和容器报告，不把固定能力写入 renderer；
- `probe()`：使用 `ffprobe -print_format json -show_format -show_streams` 读取容器、时长和轨道事实；
- `buildPreview()`：复用现有代理、缩略图和波形缓存端口；
- `export()`：当前生产切片使用 WebM、VP9、Opus，参数通过数组传递，不拼接 shell；
- `cancel()`：保存真实子进程句柄，取消请求只返回 accepted，进程结束后才返回 cancelled；
- `verifyOutput()`：独立调用 `ffprobe` 检查非空文件、视频轨道和正时长，退出码不能单独证明成功。

导出先写同目录临时文件，验证通过后再原子重命名；失败、取消和验证不通过都会清理临时产物，不登记 Work。

## 二、Electron 接入

主进程优先使用同时配置 `UNICOMP_FFMPEG_PATH` 与 `UNICOMP_FFPROBE_PATH` 的 `FfmpegMediaEngineAdapter`，并将其预览能力接入现有视频编辑媒体控制器。renderer 只继续调用现有安全 IPC，不接收路径、命令、句柄或 FFmpeg 日志。

未配置或路径不是普通文件时，主进程继续返回真实 `adapter_unavailable`，不会生成假视频、假进度或假作品。

## 三、真实验证

- 使用项目 `.tools` 中已验证的 FFmpeg 8.1.2 生成真实 VP9/Opus WebM 样本；
- `getCapabilities()` 读取并发现 `libvpx-vp9` 与 `libopus`；
- `probe()` 读取真实视频/音频轨道和时长；
- `export()` 真实生成 WebM，记录 FFmpeg progress 事件，独立 `verifyOutput()` 通过后发布；
- 真实长任务取消返回 accepted，最终结果为 cancelled，目标文件和 `.part` 文件均不存在；
- 非法时间范围和输出覆盖均在启动 FFmpeg 前阻断；
- 参数数组测试确认没有 shell 拼接入口。

完整回归为 108 项 UI/IPC/工具链契约测试与 185 项领域/平台测试，共 293 项且 0 失败；TypeScript、ESLint、生产构建和差异检查通过。
