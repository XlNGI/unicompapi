日期：2026-07-22

## 一、本次实现

- 按权威页面建立顶部操作、服务连接列表、连接详情、模型目录和模型能力与路由三栏结构。
- 页面直接消费 `window.unicomp.providers.getRegistry()`，不创建页面私有业务状态或模拟服务商目录。
- 支持添加服务、添加自定义兼容接口、连接选择、连接状态筛选、连接启停和本地软删除。
- 支持模型目录同步、手工模型登记、模型选择和模型启停。
- 支持连接信息更新；endpoint 只显示是否已配置，不回显完整地址。
- 支持凭证输入、替换、本机安全存储检查和本地删除；常态只显示掩码。
- 分开展示连接、身份、凭证、目录、模型启用和具体能力证据状态。
- 支持查看历史能力证据和保存默认用途、备用顺序。
- 费用、隐私、地区和外发范围未获得真实事实时保持未知，并提示任务提交前确认。
- 深色、浅色和最小窗口宽度下保持现有应用壳布局。

## 二、联调修复

开发者 B 的管理写接口首次联调发现：停用连接后仍可启用其模型，路由计划也未排除停用连接。

已在独立修复分支完成根因修复：

- `setModelEnabled` 拒绝为已停用或已删除连接启用模型；
- `planRoute` 排除已停用或已删除连接下的模型；
- 回归测试覆盖停用连接残留启用模型和路由偏好时仍无候选模型。

## 三、安全与真实状态

- 页面未预置任何服务商、模型、价格、限制、时长、分辨率或数量。
- API Key、Token 和代理密码不进入页面状态之外的持久化、DTO、日志、截图或仓库。
- renderer 没有读取、复制或显示凭证明文的接口。
- 删除本地凭证明确提示不等于撤销服务商侧凭证。
- 删除连接保留历史连接、模型、能力、任务、作品和来源事实。
- 无真实 HTTP 适配器时，连接验证、目录同步和能力验证显示明确不可用，不伪造成功。
- 模型启用不改变能力证据；声明支持、用户确认和已验证支持分别显示。
- 自动路由不提交任务，费用、隐私和地区保持未知并要求提交前确认。
