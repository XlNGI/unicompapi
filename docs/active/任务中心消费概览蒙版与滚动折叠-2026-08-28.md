# 任务中心消费概览蒙版与滚动折叠

日期：2026-08-28

分支：`feature/remove-task-consumption-notices`

阶段：阶段 9 已收口后的独立 UI 优化；阶段 10 未启动。

## 权威依据与范围

- 依据项目负责人本次提供的任务中心截图与明确交互决策，将“人民币消费柱状图”和“供应商人民币消费占比”合并为同一蒙版面板。
- 保留最终 UI 与开发交接包 V1.2.1 的任务中心职责，不增加一级页面，不改变任务、调用、消费金额或本地作品事实。
- 修改范围仅包含任务中心页面、任务中心双栏工作区、页面样式、UI 合同测试及工程记录；未修改主进程读模型、服务商适配、价格、换算或凭证逻辑。
- 工作区开始时已有消费说明文案精简改动，本次保持该改动不被覆盖。

## 实际修改

- 两个消费图表由两张独立卡片改为同一 `uc-task-center__charts-mask` 外框，内部用主题边框分隔；窄窗口下分隔线从竖向自动切为横向。
- 任务中心整个页面捕获鼠标滚轮与触控板纵向滑动：累计向下 16px 后，消费概览以 320ms 蒙版裁切、上移和淡出动画收起，为任务区释放高度；因此鼠标位于概览、筛选、空白区、任务列表或任务详情上方均可触发。
- 删除任务列表与任务详情上的第二套 `scrollTop` 状态控制。首次验收发现它会在真实任务数据下与页面级滚轮控制竞争：向下滚轮刚收起概览，内部滚动区在顶部附近产生的 `scroll` 事件又立即展开，表现为反复抽搐。
- 现在只有任务中心根节点可以改变折叠状态：累计向下 16px 收起，累计向上 12px 恢复；内部任务列表和详情栏继续自然滚动，但不再写入概览状态。
- 每次折叠状态切换后设置 420ms 方向切换锁，覆盖 320ms 动画周期，避免触控板惯性或边界回弹在动画期间立即触发反向状态。
- 右侧详情内容不足以产生真实滚动时，触控板边界惯性仍可能在锁定期结束后继续输出反向增量。现将滚轮解析为完整手势：相邻事件间隔不足 180ms 时视为同一手势，同一手势中的方向反弹不会触发恢复；只有停止至少 180ms 后开始的反向输入才被视为新的展开手势。
- 折叠只改变 renderer 展示，不卸载消费摘要组件，不重复读取数据，也不改变任务列表和时间线的滚动模型。
- 折叠状态同步到 `aria-hidden`；全局 `prefers-reduced-motion` 规则继续把动画时长压缩到近乎即时。
- 展开容器禁止被父级 Flex 挤压，避免 1280×720 下七日柱状图被蒙版意外裁切。

## 未完成项与边界

- 本地浏览器没有 Electron 桌面存储与真实任务数据；页面任意位置的真实滚轮收起/恢复已经自动化通过。真实数据下的抽搐根因已通过删除相互竞争的内部滚动状态路径关闭，并由 UI 合同禁止回归。
- 当前功能分支基线早于最新本地 `develop`；本次没有在带有既有未提交改动的工作区擅自合并或改写分支历史。
- 本次不改变消费统计语义、数据刷新、任务选择、调用时间线或左右栏独立滚动行为。
