## 三、强制业务边界

- 图片创作必须属于当前已打开项目；未打开项目时不得创建草稿或任务。
- 选择图片只建立本地受控引用，不得自动上传、识别、编辑或分析。
- 单次工作区只接受一张明确选择的源图或参考图，不恢复多图参考。
- 保存草稿只保存本地草稿，不得自动创建外部任务。
- 进入其他创作模式只建立派生草稿，不得自动提交任务。
- 用户原始输入、系统补充内容和最终提交内容必须分别保存和展示。
- 模型、参数、尺寸、格式、数量、费用和文件限制必须来自动态能力事实，不得写死。
- 未验证能力不得标记为支持；费用、隐私、地区和外发范围未知时必须保持未知。
- 自动路由不得绕过费用、外发范围、接收方和最终提示词确认。
- 图片识别必须区分可见事实、模型推断、不确定、无法识别和用户修改。
- 用户修改不得覆盖模型原始识别记录。
- 图片编辑不得覆盖原图；每次成功结果必须成为可追溯的新版本。
- 图片转提示词在图片、区域、用途或关键要求变化后必须标记旧结果过期。
- 远端结果只有完成本地下载、类型/字节/Hash 校验和原子落盘后才能登记为正式作品。
- API Key、Token、endpoint、绝对路径、原始 Hash 和内部错误堆栈不得进入 renderer DTO、日志或截图。

### B1｜图片工作区领域契约

- 定义五种图片工作区草稿和模式状态，不新增其他图片模式。
- 建立当前项目约束、单图输入引用、来源用途、可选区域和上下文选择契约。
- 复用并补齐原始输入、系统补充和最终提示词快照，不允许互相覆盖。
- 定义快速与专业生图的共享事实边界；参数值只接受动态能力 Schema。
- 定义识别五类结果、用户修订记录、过期规则和保存范围。
- 定义图片编辑原图、蒙版/区域、必须保持、必须修改、禁止内容和父子版本关系。
- 定义图片转提示词的分析前、分析后、过期和派生草稿状态。
- 建立版本化仓储、运行时校验和不含路径/Hash 的 renderer DTO。

### B2｜本地图片输入与预览

- 通过原生文件选择器导入单张图片，不接受 renderer 任意路径。
- 校验真实文件类型、可读性、基础元数据和 SHA-256，失败时保持真实错误状态。
- 将受控副本或明确授权的外部引用登记为 Asset 与 FileReference。
- 复用短期 `unicomp-media` 句柄预览，不向 renderer 返回绝对路径。
- 图片、区域和用途变更时标记相关识别/提示词结果过期。
- 不上传图片，不自动分析，不创建任务。

### B3｜能力预检、提交与结果接收

- 按用途查询阶段 4 的动态模型、能力证据和路由偏好。
- 生成参数表必须来自动态 Schema；缺失或未知时阻止提交并说明原因。
- 建立费用、外发范围、接收方、最终提示词和模型的提交确认快照。
- 保存草稿、预检、创建任务、创建执行和远端调用必须是不同操作。
- 定义生成、识别、编辑和提示词分析端口；无适配器时返回明确不可用。
- 定义结果下载到临时文件、字节/类型/Hash 校验、原子落盘和作品登记顺序。
- 下载失败、校验失败或本地保存失败不得登记正式作品。
- 重试必须创建新执行记录，不覆盖原失败记录。

### A1｜公共工作区与真实状态

- 按冻结设计图建立图片创作工作区、项目状态、模式标题、输入区、画布/预览区和动态能力区。

- 不使用硬编码服务商、模型、参数、费用、尺寸、格式、数量、进度或结果图。

### A2｜快速生图与专业生图

- 快速生图和专业生图必须分别提交小 PR，不在一个分支中重写两个页面。
- 快速生图保留一句话输入、可选单张参考图、外发/费用确认和结果区。
- 专业生图区分项目素材、项目上下文、已保存对话上下文、单张参考图用途和提示词增强对比。
- 动态模型与参数来自 B 的 DTO；不可用项必须禁用并解释。
- 保存草稿、提交任务、重新生成、保存到项目和进入专业创作必须分别操作。
- 无真实适配器时只能保存本地草稿和查看阻断原因，不显示假结果或假进度。

### A3｜图片识别、图片编辑与图片转提示词

- 图片识别、图片编辑和图片转提示词必须分别提交小 PR。
- 图片识别按五类结果展示并允许用户修订，原始结果与修改记录分别呈现。
- 图片编辑提供单张原图、区域/蒙版、保持/修改/禁止内容、动态参数和版本关系视图。
- 图片转提示词覆盖分析前与分析后两个冻结状态，展示事实、推断、不确定、系统补充和可编辑草稿。
- 各页面进入其他模式时只创建派生草稿，不自动提交任务。
- 文件、区域、用途或要求变化后，旧分析结果必须显示过期。
