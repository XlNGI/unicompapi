## 一、架构结论

阶段 7 V1.0 采用“本地优先、非破坏式、轻量单轨、后台导出”的架构：

1. 编辑草稿只保存结构化编辑意图和受控文件引用，不保存媒体二进制，不修改源文件。
2. 页面操作统一转换为严格判别联合的编辑命令，由纯领域归约器更新 EditDraft。
3. 快速预览与正式导出共享同一草稿语义，但分别生成 PreviewPlan 和冻结的 ExportPlan。
4. 媒体引擎通过 MediaEngineAdapter 隔离；业务层不得拼接任意 shell，也不得依赖具体 FFmpeg 命令格式。
5. 正式导出创建本地 Task、冻结计划和独立 Execution/attempt，在后台进程中执行。
6. 输出到受控临时文件，经探测、可读性、容器、字节和文件同步校验后，再以不覆盖方式发布并登记 Work。
7. 硬件路径失败必须保留失败尝试，并创建软件编码新尝试；硬件失败不能阻止导出。
8. Windows 与 macOS 共享领域状态、错误语义和测试契约，文件、权限、字体、进程与硬件差异由适配层承担。

本文件仅批准架构边界，不批准媒体引擎二进制、编解码器、许可条款或实现代码。任何第三方引擎在完成许可与分发审查前不得安装、绑定或进入发布物。

## 三、V1.0 能力边界

必须实现：

- 多个本地视频片段按顺序进入一个视频主轨；
- 裁剪首尾、播放头分割、删除与恢复、复制、排序；
- 无转场、淡入淡出或叠化等经当前引擎真实验证的基础转场；
- 画布比例、适应/填满、缩放、位置、裁切、旋转、水平/垂直翻转、纯色或模糊背景；
- 整段统一变速、单片段变速、恢复原速度；
- 多个基础文字层及其时间、字体、字号、对齐、位置、透明度和基础淡入淡出；
- 原声保留/静音/音量，以及一条背景音乐的裁剪、音量和基础淡入淡出；
- 从视频选帧、本地图片或项目图片选择封面；默认只影响作品展示；
- 自动保存、撤销/重做、另存为和复制草稿；
- 后台导出、真实进度、取消、失败、重试、重启恢复；
- 每次导出形成独立文件、FileReference、Work 和版本关系。

V1.0 明确不实现：

- 专业多轨、画中画、多层视频合成；
- 复杂关键帧、曲线变速、光流补帧；
- 自动字幕、逐字字幕、AI 配音、数字人；
- 自动剪辑成片、高级调色、专业特效、遮罩动画；
- 复杂音频混音、插件系统；
- 在基础编辑页调用图片或视频生成模型；
- 未经真实验证的格式、编解码器、硬件能力和进度预测。

## 四、EditDraft Schema

### 4.1 总体约束

- 时间统一使用非负整数微秒，禁止用浮点秒作为持久化事实。
- 坐标、裁切和透明度使用经过范围校验的标准化值；渲染层负责转换为像素。
- 草稿只保存 FileReferenceId、AssetId 或 WorkId，不向 renderer 暴露绝对路径或原始 Hash。
- 所有联合必须使用 kind 字段判别，运行时拒绝未知字段、未知版本和非法组合。
- revision 每次成功命令后递增；保存使用期望 revision，禁止后写静默覆盖前写。
- schemaVersion 的迁移必须是显式、可测试、单向迁移；无法迁移时只读保留原文件并提示恢复。

### 4.2 顶层草稿

    interface EditDraftV1 {
      schemaVersion: 1
      kind: 'video_basic_edit'
      id: EditDraftId
      projectId: ProjectId
      title: string
      revision: number
      sourceIntent?: {
        kind: 'blank' | 'from_work' | 'from_video_draft'
        sourceId?: WorkId | VideoWorkspaceDraftId
      }
      canvas: CanvasSettings
      videoTrack: readonly VideoClip[]
      removedClips: readonly RemovedClip[]
      textTrack: readonly TextOverlay[]
      backgroundMusic: BackgroundMusic | null
      cover: CoverSelection | null
      outputPreference: OutputPreference
      history: PersistedEditHistory
      createdAt: IsoTimestamp
      updatedAt: IsoTimestamp
    }

不把生成草稿并入 EditDraft 联合；从阶段 6 进入基础编辑只创建新的 EditDraft，并记录来源意图。

### 4.3 视频片段

    interface VideoClip {
      kind: 'video_clip'
      id: ClipId
      source: {
        fileId: FileReferenceId
        assetId?: AssetId
        workId?: WorkId
        identitySnapshot: MediaIdentitySnapshot
      }
      sourceRange: { inUs: number; outUs: number }
      speed: { numerator: number; denominator: number }
      transform: CanvasTransform
      sourceAudio: { muted: boolean; volumePermille: number }
      transitionToNext: BasicTransition
    }

片段的时间线起点不持久化为独立可编辑事实，而由当前顺序、裁剪范围、速度和基础转场计算，避免顺序与 timelineStart 双事实漂移。BasicTransition 至少支持 none；fade/dissolve 只有在媒体引擎能力真实验证后才进入可选 DTO，持续时间必须小于相邻片段的有效时长。

删除使用 removedClips 保存带原索引的墓碑，恢复生成新命令；不得删除源 Asset、FileReference 或 Work。

### 4.4 画布、文字、音乐和封面

CanvasSettings 必须是动态输出能力的编辑意图，不写死固定分辨率：

    type CanvasBackground =
      | { kind: 'solid'; color: RgbaColor }
      | { kind: 'blur_source'; blurStrength: number }

    interface CanvasSettings {
      aspectRatio: { numerator: number; denominator: number } | { kind: 'source' }
      transformPolicy: 'fit' | 'fill'
      background: CanvasBackground
    }

文字层：

    interface TextOverlay {
      kind: 'text_overlay'
      id: TextOverlayId
      content: string
      range: { startUs: number; endUs: number }
      font: { requestedFamily: string; resolvedFontId?: string }
      style: TextStyle
      position: NormalizedPoint
      entrance: 'none' | 'fade_in'
      exit: 'none' | 'fade_out'
    }

背景音乐严格为零或一条：

    interface BackgroundMusic {
      kind: 'background_music'
      fileId: FileReferenceId
      assetId?: AssetId
      identitySnapshot: MediaIdentitySnapshot
      sourceRange: { inUs: number; outUs: number }
      timelineRange: { startUs: number; endUs: number }
      volumePermille: number
      fadeInUs: number
      fadeOutUs: number
    }

封面使用严格联合：

    type CoverSelection =
      | { kind: 'video_frame'; clipId: ClipId; sourceTimeUs: number; prependToVideo: boolean }
      | { kind: 'local_image'; fileId: FileReferenceId; assetId?: AssetId; prependToVideo: boolean }
      | { kind: 'project_image'; workId: WorkId; fileId: FileReferenceId; prependToVideo: boolean }

prependToVideo 默认为 false；只有用户明确选择时才改变正式视频内容。

### 4.5 输出偏好

OutputPreference 只记录用户选择或“自动”，不写死所有设备均支持的容器、编码、分辨率、帧率、质量或硬件：

    interface OutputPreference {
      destinationId?: ControlledDirectoryId
      fileName?: string
      container: 'auto' | CapabilityValueId
      videoCodec: 'auto' | CapabilityValueId
      audioCodec: 'auto' | CapabilityValueId
      resolution: 'source' | CapabilityValueId
      frameRate: 'source' | CapabilityValueId
      quality: 'auto' | CapabilityValueId
      hardwareAcceleration: 'auto' | 'prefer_hardware' | 'software_only'
      conflictPolicy: 'fail' | 'create_unique_name'
    }

真实可选值由媒体引擎能力探测返回，renderer 只消费安全能力 DTO。

## 五、编辑命令、撤销/重做与自动保存

持久化命令必须是数据，不序列化函数：

    type EditCommandDto =
      | { kind: 'trim_clip'; clipId: ClipId; before: TimeRange; after: TimeRange }
      | { kind: 'split_clip'; clipId: ClipId; atSourceUs: number; createdClipId: ClipId }
      | { kind: 'remove_clip'; clipId: ClipId; previousIndex: number }
      | { kind: 'restore_clip'; clipId: ClipId; targetIndex: number }
      | { kind: 'duplicate_clip'; sourceClipId: ClipId; createdClipId: ClipId; targetIndex: number }
      | { kind: 'move_clip'; clipId: ClipId; fromIndex: number; toIndex: number }
      | { kind: 'set_clip_speed'; clipId: ClipId; before: Rational; after: Rational }
      | { kind: 'set_clip_transform'; clipId: ClipId; before: CanvasTransform; after: CanvasTransform }
      | { kind: 'set_clip_transition'; clipId: ClipId; before: BasicTransition; after: BasicTransition }
      | { kind: 'upsert_text'; before: TextOverlay | null; after: TextOverlay }
      | { kind: 'remove_text'; before: TextOverlay }
      | { kind: 'set_source_audio'; clipId: ClipId; before: SourceAudio; after: SourceAudio }
      | { kind: 'set_background_music'; before: BackgroundMusic | null; after: BackgroundMusic | null }
      | { kind: 'set_cover'; before: CoverSelection | null; after: CoverSelection | null }
      | { kind: 'set_canvas'; before: CanvasSettings; after: CanvasSettings }

领域层对命令执行严格前置校验并返回新草稿，不原地修改。history 保存有界 undoStack/redoStack、baseRevision 和命令版本；实现阶段必须明确容量和压缩策略，不得无限增长。

自动保存策略：

1. 每次有效命令先更新内存状态并标记 dirty。
2. 防抖后写入同目录临时 JSON，执行文件同步，再原子替换正式草稿文件。
3. 保存成功才推进 persistedRevision；失败保留内存状态、dirty 标记和可重试提示。
4. 关闭应用前检查 dirty 状态；不允许因保存失败清空编辑内容。
5. 复制草稿生成新 DraftId、清空导出关联和执行历史，但保留来源引用与编辑状态。

## 六、领域模块与依赖图

    Renderer UI
        ↓ 安全 DTO / 受控 IPC
    Editor Application Services
        ↓
    EditDraft + Timeline + Commands + ExportPlan Domain
        ↓ 端口
    Repositories / FileReference / MediaEngine / Process / Clock / Id
        ↓
    Electron Main + Node Filesystem + approved media engine

模块职责：

- EditProjectService：创建、打开、复制、另存为和关闭草稿。
- TimelineService：片段顺序、持续时间和播放头时间映射。
- ClipEditingService：裁剪、分割、删除、恢复、复制、排序、变速和变换。
- TextOverlayService：文字时间范围、样式、字体解析和冲突校验。
- AudioTrackService：原声与单背景音乐约束。
- CoverService：选帧、图片封面和 prependToVideo 显式选择。
- UndoRedoService：命令应用、反转、revision 和历史压缩。
- DraftAutosaveService：防抖、原子写入、失败保留和关闭检查。
- SourceRelinkService：丢失检查、候选探测、指纹比对和用户确认。
- PreviewPlanService：从草稿生成低成本预览计划。
- ExportPlanService：校验源文件并冻结不可变导出快照。
- ExportOrchestrator：任务、Execution/attempt、取消、恢复、发布和 Work 登记。

禁止依赖：

- domain 不依赖 Electron、Node path、child_process 或具体媒体命令；
- renderer 不依赖文件系统、绝对路径、原始 Hash、引擎命令或进程句柄；
- preview 不登记 Work，不把代理当正式源；
- media adapter 不直接修改 Draft、Task、Execution 或 Work 仓储。

## 七、源文件引用、复制、重定位与指纹

导入策略严格区分：

- external_reference：保留用户授权的外部文件引用；
- managed_project_copy：复制到项目素材目录并建立受管 FileReference；
- managed_work：引用作品库已校验文件。

默认不强制复制大视频。复制操作必须是显式动作，先写项目临时文件、校验、同步并原子发布，不能边复制边把引用标为 available。

MediaIdentitySnapshot 至少包含字节数、修改时间、时长、容器、宽高和可选内容 Hash；平台文件身份只能作为附加证据。重定位流程：

1. 主进程原生选择候选文件；
2. 可信探测器读取媒体事实；
3. 与 identitySnapshot 比较；
4. 完全匹配可直接更新 locator；
5. 部分不匹配必须展示差异并要求用户确认；
6. 用户确认后更新引用和新快照，同时使旧预览、旧代理和未提交预检失效；
7. 已冻结 ExportPlan 永不静默改用新文件。

## 八、预览、代理、缩略图和波形

双路径：

    EditDraft → PreviewPlan → 原播放器 / 低清代理 / UI 叠加 → 仅预览
    EditDraft → Frozen ExportPlan → 原始素材 / 正式媒体引擎 → 新作品

PreviewPlan 与 ExportPlan 使用同一时间计算、裁剪、变速、画布、文字和音频语义。允许预览降低分辨率、帧率或音频精度，但不得改变时间线结果。

代理、缩略图和波形均为可删除缓存：

- 按 source identity、处理参数、引擎版本和缓存版本建立键；
- 缓存只放受控 cache 目录，不进入作品库；
- 删除后可重建，不能破坏草稿；
- 任务优先级低于正式导出；
- 源文件变化、重定位或引擎版本变化后旧缓存失效；
- 缓存 DTO 不暴露本地路径。

## 九、MediaEngineAdapter

内部端口：

    interface MediaEngineAdapter {
      getCapabilities(): Promise<MediaEngineCapabilities>
      probe(input: MediaSource): Promise<MediaProbe>
      buildPreview(input: PreviewRequest): Promise<PreviewArtifact>
      export(plan: ExportPlan, events: ExportEventSink): Promise<ExportResult>
      cancel(jobId: string): Promise<CancelResult>
      verifyOutput(path: ControlledPath): Promise<OutputVerification>
    }

约束：

- MediaSource、PreviewRequest 和 ExportPlan 都是结构化对象。
- adapter 自己负责把结构化计划转换为引擎调用；用户文本、文件名和路径不得拼接为任意 shell。
- 进程启动优先使用参数数组或库 API，捕获 stdout、stderr、退出码和进度事件。
- 引擎进度只能来自可验证事件；无法确认百分比时只显示阶段。
- cancel 返回“已接受、已终止、无法确认或不支持”，取消请求不等于已取消。
- verifyOutput 必须独立于进程退出码检查正式输出。
- 具体引擎、版本、二进制来源、签名、许可证、编解码器和分发方式须独立审查批准。

## 十、ExportPlan 冻结快照

创建导出任务前必须重新校验草稿、源文件、字体、目标目录、空间和引擎能力。通过后生成不可变 ExportPlan：

- planVersion、planId、draftId、draftRevision；
- 输入 FileReference 与 MediaIdentitySnapshot；
- 片段顺序、裁剪、速度和变换；
- 画布、文字、解析后的字体、原声和背景音乐；
- 封面及 prependToVideo 选择；
- 已解析的容器、编码、分辨率、帧率、质量；
- 目标受控目录、文件名和冲突策略；
- 硬件策略、能力快照和媒体引擎版本；
- 预计空间依据、创建时间和计划 Hash。

用户继续编辑草稿不会改变已有计划。再次导出创建新 Task 和新 ExportPlan；仅“相同计划重试”可复用原计划，新参数必须生成新计划。

## 十一、导出任务与 Execution 状态机

编辑导出需要独立详细状态，不直接把现有远端生成状态硬套成本地编码状态：

    queued
      → validating_sources
      → preparing_media
      → encoding
      → writing_file
      → verifying_file
      → registering_work
      → completed

异常状态：

    needs_user_action
    failed
    cancel_requested
    cancelled
    interrupted
    recovery_required

状态规则：

- Task 表示一次冻结导出意图，Execution 表示一次具体尝试。
- 重试创建新 attempt，不覆盖原失败或硬件尝试。
- needs_user_action 用于源文件丢失、字体缺失、权限丢失或目标目录不可用；处理后创建或恢复到安全的新 attempt。
- cancel_requested 只有在进程确认停止并处理残留文件后才能进入 cancelled。
- 应用关闭或崩溃时运行中记录进入 interrupted；启动扫描后决定 failed、recovery_required、重新校验或从安全阶段恢复。
- completed 必须同时满足输出校验、最终发布、FileReference 持久化、Work 登记和版本关系成功。
- 详细导出状态投影到任务中心通用状态；实现时不得破坏图片/视频远端任务的既有状态语义。

## 十二、临时文件、原子保存与版本登记

建议项目内布局：

    entities/video-edit-drafts.json
    entities/video-export-plans.json
    tmp/editor/<taskId>/<attempt>/
      export-plan.json
      engine.log.redacted
      output.partial
      attempt.json
    cache/video-editor/
      proxies/
      thumbnails/
      waveforms/
    files/results/<workId>.<verified-extension>

正式导出：

1. 创建排他任务目录并原子写入 ExportPlan。
2. 输出到 output.partial，禁止直接写最终文件。
3. 等待引擎退出，执行文件同步和目录同步能力允许的校验。
4. 独立探测输出容器、时长、宽高、音视频流和可读性。
5. 计算字节和内容 Hash，确认与计划及引擎结果一致。
6. 使用 create_unique_name 或 fail 处理冲突，永不覆盖已有正式文件。
7. 优先同卷排他发布；跨卷目标采用“目标目录临时文件 → 同目录原子重命名”，并在复制后重新同步和校验。
8. 建立 available FileReference；随后登记 Work、parentWorkId/来源关系和导出版本。
9. 全部记录成功后才 completed；记录失败保留可恢复事实，不返回成功。
10. 清理只删除已确认无用的临时文件，失败证据按保留策略处理。

## 十三、硬件失败回退

硬件策略不是单次命令开关，而是可审计的尝试策略：

    prefer_hardware / auto
      → attempt N 使用已验证硬件能力
      → 硬件初始化、编码或驱动失败
      → attempt N 标记 failed，记录脱敏原因
      → 创建 attempt N+1
      → 使用 software_only 和同一 ExportPlan 内容语义
      → 重新从受控临时文件开始

仅用户明确选择 software_only 时跳过硬件。硬件失败不得修改草稿、覆盖旧输出或把软件尝试伪装为原尝试继续。若软件编码也失败，保留两次事实和分别的失败阶段。

## 十四、Windows 与 macOS 差异

共同规则：

- 相同 EditDraft、ExportPlan、状态机、错误码、作品版本和安全 DTO；
- 不把路径分隔符、盘符、文件权限位或硬件名称写入领域层；
- 不支持的能力动态隐藏或明确禁用原因。

Windows：

- 处理盘符、UNC、长路径、文件占用、杀毒软件延迟和 rename/link 行为；
- 使用 Job Object 或等效进程树控制，取消时不得遗留子进程；
- 硬件能力可能来自不同厂商，必须逐项真实探测；
- 文件仍被播放器占用时，发布和清理应返回可恢复状态。

macOS：

- 处理 sandbox、用户选择目录授权、安全作用域书签和权限失效；
- 处理应用休眠、App Nap、进程终止和硬件 VideoToolbox 能力差异；
- 字体解析和颜色渲染与 Windows 分开取证；
- 应用签名、公证和第三方二进制嵌入方式必须纳入分发审查。

两个平台都必须真实验证文件选择、外部盘断开、目录只读、空间不足、进程取消、重启恢复和软件回退。macOS 实机可在阶段 9 完成，但阶段 7 不能用 Windows 假设封死接口。

## 十五、许可与分发准入

媒体引擎进入代码或构建前必须形成独立决策记录，至少确认：

- 引擎与每个启用编解码器的许可证；
- 静态/动态链接和二进制再分发义务；
- Windows/macOS 构建来源、版本固定、完整性校验和供应链更新；
- 专利、商业使用、署名、源码提供或用户替换要求；
- Electron 打包、签名、公证、杀毒误报和增量更新影响；
- 不支持或不允许分发的编码能力如何动态隐藏。

规划阶段不得执行安装、下载、提交二进制或修改依赖。

## 十六、测试计划

领域单元测试：

- EditDraft 严格校验、版本迁移、时间整数和非法联合；
- 裁剪、分割、删除/恢复、复制、排序、变速时长和基础转场边界；
- 画布、文字、背景音乐、封面和单轨约束；
- 命令 apply/revert、undo/redo、revision 冲突和历史压缩；
- ExportPlan 冻结、计划 Hash 和草稿后续修改隔离。

仓储与文件测试：

- 防抖自动保存、临时写入、fsync、原子替换和保存失败保留；
- 外部引用、项目复制、源丢失、重定位匹配/不匹配；
- 文件名冲突、同卷发布、跨卷复制后校验、只读目录和空间不足；
- 临时目录清理不能删除正式文件或其他任务文件。

媒体适配契约测试：

- probe、preview、export、cancel 和 verifyOutput 的成功与失败；
- 参数数组和结构化计划，不允许任意 shell 注入；
- 真实阶段事件、无百分比事件、异常退出、假成功文件和损坏输出；
- 硬件失败创建软件新尝试；
- 代理、缩略图和波形缓存删除/重建。

状态机与恢复测试：

- 每个合法/非法迁移；
- cancel_requested 不提前变 cancelled；
- 崩溃发生在编码、写入、校验、发布和 Work 登记各阶段；
- 重启扫描、recovery_required、同计划重试和新参数新计划；
- completed 的七项完成条件缺一不可。

UI/IPC/安全测试：

- 页面符合冻结基础编辑图和现有导航；
- renderer 不取得路径、Hash、命令、进程句柄或内部堆栈；
- 未打开项目、空草稿、保存失败、源丢失、字体缺失、代理失败、空间不足和适配器不可用；
- 不显示假进度、假硬件能力或未验证格式；
- 基础编辑页不存在生成模型调用。

媒体样本与故障注入：

- 短/长、横/竖、不同帧率、带/不带音频、旋转元数据和可变帧率样本；
- 损坏、截断、容器伪装、超大声明、源文件处理中变化；
- 外接盘拔出、权限撤销、进程强杀、磁盘写满和字体删除；
- 样本必须合法可分发，小文件优先，并记录来源和 Hash。

门禁：

- 现有全部测试零失败；
- 新增领域、平台、IPC 和 UI 契约测试零失败；
- TypeScript、ESLint、生产构建和 git diff --check 通过；
- Windows Electron 真实窗口完成关键流程；
- macOS 接口和测试夹具不被 Windows 实现破坏，实机证据按阶段 9 计划记录；
- 第三方引擎未获许可批准前，只能使用测试替身，不宣称真实导出完成。
