# 阶段 8｜本地设置任务拆分

日期：2026-07-27
状态：B1、A1、B2、A2、B3 已合并；B4 已完成待合并；A2、B3、B4 功能分支本地与远程保留
基线：a38b58a Merge phase 7 integration closeout

## 一、阶段目标

按冻结的 10 个分类交付真实、设备本地、跨平台的设置中心。阶段完成时，普通偏好可以自动保存和重开恢复；平台与组件状态来自真实探测；高风险操作通过影响计划和明确确认执行；不支持或尚未获批的能力不会伪装成可用。

技术架构以以下文件为强制依据：

    docs/active/阶段8-技术架构.md

项目负责人于 2026-07-27 通过“继续下一步”明确批准本规划。B1 已通过 `1eb3dd8 Merge phase 8 B1 local settings contracts` 合并 `develop`；A1 已通过 `b1bd313 Merge phase 8 A1 local settings shell` 合并 `develop`；B2 已通过 `eb160c9 Merge phase 8 B2 storage performance and media` 合并 `develop`。

## 二、现有基线与缺口

可复用：

- Electron + React + TypeScript 桌面壳、主题、状态组件和固定“本地设置”一级入口；
- 项目 Session、原子 JSON 写入、严格运行时校验和 revision 模式；
- Task、Execution、Work、FileReference 与全局任务/作品读模型；
- 本机 `safeStorage` 凭证库边界；
- FFmpeg 开发工具链、媒体能力探测、预览缓存和软件导出事实；
- 受控文件选择、短期媒体句柄、文件状态、Hash 与恢复规则。

缺口：

- `SettingsPage` 仍是阶段 1 占位页；
- 没有设置 Schema、应用级设置仓储、迁移和设置 IPC；
- 没有能力矩阵、设置状态聚合或高风险操作协议；
- 没有目录迁移、应用级存储统计和分级清理；
- 没有统一任务策略、代理、通知、快捷键、诊断或更新端口；
- 没有生产更新源、签名/回退链路、生产媒体组件分发或 macOS 实机证据。

## 三、分支原则

- 所有功能分支从最新 `develop` 创建，合并后保留本地和远程分支；
- B 负责设置领域、仓储、受控 IPC 和平台端口；A 负责固定分类导航、10 个面板、真实状态和确认交互；
- B1 先建立稳定 DTO；A1 只接 B1，不在 UI 中创建第二套设置事实；
- 每组平台能力以小 PR 进入，不在一个分支中同时重写设置页、主进程和全部服务；
- 未获批更新、媒体组件或硬件能力只能通过端口返回不可用，不能用 mock 进入正式 UI；
- A/B 避免同时修改 `electron/preload.ts`、`electron/main.ts`、`src/vite-env.d.ts` 和 `SettingsPage.tsx`；后合并方先同步最新 `develop`。

## 七、阶段验收门禁

- “本地设置”是独立一级页面，第二列固定 10 分类且顺序正确；
- 普通设置自动保存，失败、冲突、待重启和恢复状态真实；
- 设置文件版本化、原子保存、可迁移且损坏不被默认值覆盖；
- 设置只保存在当前设备，不进入项目或云端；
- 目录迁移、代理、并发、硬件、清理、重置和清除数据均需明确确认；
- 高风险操作执行前重新校验影响计划和当前事实；
- 目录迁移失败不切换有效目录，不覆盖正式文件；
- 并发与代理只影响后续任务/请求，活动任务不被静默破坏；
- 代理凭证只在安全存储，renderer、设置 JSON、日志和诊断包无明文；
- 通知失败不改变业务状态，快捷键冲突不能保存；
- 诊断包本地生成、默认脱敏且不自动上传；

- 无生产更新器时不宣称最新、可修复、可回退或可安装；
- `.tools` 和 FFmpeg 仍不进入生产构建或发布物；
- 不新增登录、会员、充值、云同步、全盘扫描或后台剪贴板读取；
- renderer 不接收绝对路径、Hash、凭证、日志原文、更新 URL 或平台句柄；
