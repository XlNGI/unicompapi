# 阶段 4｜服务商领域契约记录

日期：2026-07-22
分支：`feature/provider-domain-contracts`
负责人：开发者 B｜领域与平台

## 一、本次实现

- 建立 Provider、ProviderConnection、ProviderModel、ModelCapabilityEvidence 和 RoutingPreference 领域实体。
- 服务商身份、连接状态、凭证状态、模型启用状态和能力证据相互独立。
- 建立最终规范要求的七类能力状态。
- 接入类别支持在线、本机、局域网和自定义远程，不预置具体厂商。
- 建立版本 1 本地服务商注册表，覆盖服务商、连接、模型、能力证据和路由偏好。
- 注册表保存前及读取时执行运行时结构和引用完整性校验。
- 建立只读 `providers:get-registry` IPC，为开发者 A 提供离线/空白页面数据源。

## 二、安全边界

- 注册表只保存凭证引用和凭证状态，不保存凭证明文。
- renderer DTO 不返回 endpoint、凭证引用、API Key、Token、Secret 或内部错误堆栈。
- 连接 DTO 仅返回 `endpointConfigured` 布尔值。
- 当前 IPC 只读，不提供凭证创建、替换、测试或删除；这些进入 B2 安全凭证库。
- 不包含真实 HTTP 请求，不预置服务商、模型、价格或能力。

## 三、共享 DTO

```text
window.unicomp.providers.getRegistry()
```

返回：

- 服务商摘要；
- 连接状态摘要；
- 模型摘要；
- 能力证据摘要；
- 路由偏好摘要。
