## 一、范围与边界

本支是 M3 第一支，只实现通用供应商模板、连接、结构化凭证、无费用连接验证、模型目录、精确手工模型登记、连接/模型启停、本地删除和应用级管理审计产品流。

本支只依赖 Provider Package、Registry、Credential Vault 和管理适配器端口，不硬编码具体厂商模型、价格、时长、分辨率或数量；未修改 React、preload 或 Electron 页面组合，未启动 UI 分支；未发起真实服务商 HTTP，未读取或验证真实凭证，未产生收费调用；未执行 macOS 实机与媒体工具链；阶段 10 未启动。

## 二、实际实现

### 2.1 安全模板、连接与适配器归属

- `ProviderManagementFramework.listTemplates()` 只返回 Package Registry 的安全模板 DTO，不向 renderer 暴露 adapter、protocol、endpoint policy 或固定 URL；
- 连接创建复用 Package-owned `ProviderConnectionContractService`，保留结构化凭证、EndpointPolicy 和补偿式原子保存边界；
- 管理适配器 Registry 按 `packageId + adapterId + adapterVersion + protocolId + protocolVersion` 精确注册和选择，缺失、歧义或未安装版本均停止，不猜测协议、不回退其他连接；
- 畸形连接创建请求返回受控 `invalid_request`，不会抛出未处理异常或写入凭证。

### 2.2 凭证、验证与模型目录

- 凭证轮换生成新的凭证版本并清除旧验证事实，新提交只能看到最新版本；活跃 operation 引用的旧版本通过保留端口延迟销毁，非活跃旧版本从 Vault 删除；
- 连接验证只在模板明确声明无费用验证且存在精确管理适配器时执行，只更新 Connection availability/identity/credential 状态，不创建 Profile、不授予 RuntimeAccessPolicy、不触发生成；
- 模型目录同步只接受精确 model key 与安全显示名，不按名称推断功能；目录消失模型保留为 `missing`、强制停用并关闭相关路由偏好；重复 model key 或畸形目录在 Registry 写入前拒绝；
- 没有目录接口的兼容模板只允许登记精确 model/deployment ID，初始保持停用且不自动创建 Profile。

### 2.3 启停、删除与历史保留

- 模型只有在 Connection 可用、目录状态为 `present`、Binding 精确且活动 Profile 为 `verified` 时才能启用；
- 连接或模型停用会同步关闭相关路由偏好；供应商管理只能修改 Package-owned 记录，冻结的未迁移 Vidu legacy 数据不会被误改；
- 本地删除必须显式高风险确认；存在活跃 operation 时默认拒绝，只有显式放弃后才记录旧凭证不可用并继续；
- 删除采用软删除，清除当前 endpoint 和凭证引用、停用模型与路由，但保留 Provider、Connection、Model、Profile、Task、Execution、Message、Work 和历史来源事实；不尝试远端撤销。

### 2.4 应用级管理审计

- 新增追加式 `JsonProviderManagementAuditStore`，为连接创建、凭证轮换、验证、目录同步、精确模型登记、启停和删除保存安全事件；
- 事件只包含稳定 ID、安全状态码、数量和时间，不保存凭证值、endpoint、Prompt、原始响应、签名 URL、路径或 Hash；
- 不同 Store 实例通过共享绝对路径协调串行追加，sequence 连续单调；主文件损坏时可读取上一有效 `.bak`，不把管理事件写成项目级生成调用记录。
