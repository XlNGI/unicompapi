# 阶段 7 B3｜媒体引擎许可与分发决策

日期：2026-07-24
状态：项目负责人已批准选型方向，并批准仅限本地开发/测试的临时例外；正式二进制接入仍等待编解码器与分发审查

## 一、项目许可证

- UniComp 自有代码采用 Apache-2.0；许可证文件为仓库根目录 `LICENSE`。
- `package.json` 的 `license` 字段登记为 `Apache-2.0`。
- 第三方组件不被本项目许可证重新授权，必须按各自许可证和 NOTICE 要求分发。

## 二、媒体引擎选型

项目负责人批准将 FFmpeg 作为 V1.0 的候选媒体引擎，版本固定为 `8.1.2`，同时使用对应版本的 `ffprobe`。

选择理由：

- Windows 与 macOS 具有统一的探测、滤镜、音频混合和导出语义；
- 适合通过 `MediaEngineAdapter` 以独立进程调用；
- 可以在硬件能力失败后建立软件回退尝试；
- 官方提供版本源码、发布签名和许可说明。

## 三、许可与构建边界

- 目标构建为 LGPL-only；不得启用 `--enable-gpl` 或 `--enable-nonfree`；
- `libx264`、`libx265`、`fdk-aac` 等组件不得在未完成独立许可与专利审查前启用；
- 不使用来源、构建参数或许可证无法核验的预编译 npm 媒体包；
- 优先从 FFmpeg 官方签名源码自行构建 Windows/macOS 各架构二进制；
- 发布时必须附带对应源码、构建说明、Hash、许可证和第三方声明。

## 四、工程集成边界

- renderer 不接触媒体引擎路径、命令行、进程句柄或内部日志；
- `MediaEngineAdapter` 只接受结构化 `PreviewPlan`/`ExportPlan`，转换为参数数组或受控库调用；
- 禁止把用户输入、文件名或模型返回内容拼接为任意 shell；
- 必须支持 probe、preview、export、cancel、verifyOutput、异常退出和软件回退测试；
- 未配置真实适配器时继续返回 `adapter_unavailable`，不得显示假进度或假作品。

## 五、尚未批准的项目

以下内容仍需独立审查，完成前不进入正式发布构建：

1. 实际启用的编码器/解码器白名单；
2. H.264、H.265、AAC 等格式的专利与商业分发边界；
3. Windows/macOS 工具链、签名、公证和安装包验证；
4. 每个发布架构的可复现构建、SBOM 和供应链更新策略。

因此，本记录批准的是 FFmpeg 8.1.2 LGPL-only 的工程选型方向和仅限本地开发/测试的外部路径例外；不批准将引擎写入仓库、依赖、生产构建或发布物，也不宣称正式导出已经完成。

## 六、当前工程验证

- 新增开发适配器仅限显式本地开发变量启用，生产构建默认保持不可用；
- 适配器使用参数数组启动外部进程，缓存产物写入临时文件后原子重命名；
- 新增 3 项适配器契约测试，当前完整回归为 100 项 UI/IPC/安全契约测试与 177 项领域/平台测试，共 277 项且 0 失败；
- TypeScript 类型检查、ESLint、生产构建和差异检查通过；
- 当前工作机未发现可审计的 `ffmpeg.exe`，因此尚未执行真实 FFmpeg 进程烟测。

## 七、临时本地开发例外

项目负责人已明确批准 FFmpeg 仅用于本地开发和测试。该例外必须同时满足：

- 只在 `npm run dev` 的开发进程中启用；
- 必须设置 `UNICOMP_ENABLE_LOCAL_FFMPEG=1` 和绝对路径 `UNICOMP_FFMPEG_PATH`；
- 引擎二进制由开发者在仓库外自行管理，不提交 Git、不进入 npm 依赖、Electron 安装包或发布物；
- 生产启动 `npm start`、生产构建和没有显式开发变量时继续返回 `adapter_unavailable`；
- 只用于受控本地样本的探测、代理预览、缩略图和波形验证，不创建正式 Work；
- 真实发布前仍需重新完成源码、构建、编解码器、专利、签名和分发审查。

开发者示例：

```powershell
$env:UNICOMP_ENABLE_LOCAL_FFMPEG = '1'
$env:UNICOMP_FFMPEG_PATH = 'D:\tools\ffmpeg\8.1.2\bin\ffmpeg.exe'
npm.cmd run dev
```
