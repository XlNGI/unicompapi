# 动态参数 UI 优化验收记录

日期：2026-08-20

开发分支：`feature/dynamic-parameter-ui`

状态：阶段 9 收口后的工程补充；阶段 10 未启动。

## 一、范围与依据

- 依据最终 UI 与开发交接包 V1.2.1，并按项目负责人最新反馈将填写约束收进参数详情。
- 仅优化共享动态参数表单的呈现、状态反馈与可访问性，不新增业务一级页面。
- 不修改动态字段 ID、参数类型、默认值、原始选项值、变更回调或提交合同。

## 二、实际修改

- 参数区改为轻量双列网格，字段之间使用分隔线组织，避免卡片嵌套；窄宽断点切换为单列。
- 桌面端普通输入与下拉控件最大宽度收敛为 18rem，数字输入收敛为 14rem；控件仍受容器宽度约束，窄窗口自动缩小，JSON 多行输入继续使用整行宽度。
- 字段标题提升为清晰正文标签，并保留必填与说明信息。
- 参数说明从常驻正文收进参数名旁的信息图标；鼠标悬停、键盘聚焦或点击聚焦时显示不占布局高度的详情浮层。
- 数字字段的最小值、最大值、整数或步长约束收进参数详情；数组字段的逗号分隔要求与对象字段的 JSON 格式要求同样在详情中展示，对象字段继续保留明确错误态。
- 可选文本与数组字段增加默认值占位说明；布尔字段改为带“开启/关闭”文本的开关。
- 为选择器、输入框、数字框、JSON 文本域、媒体槽和开关补充显式可访问名称。
- 新增 UI 合同断言，覆盖状态、约束、开关语义、可访问名称、响应式布局与 JSON 错误态。
- 修复图片与视频动态参数编辑期间的表单跳动：草稿等待自动保存时保留已加载候选与参数合同，只暂停候选请求，避免动态表单卸载、焦点丢失和滚动位置变化；真实阻断或候选读取失败仍会清空候选。
- 专业生图将“项目上下文”和“提示词增强”收敛为紧凑操作行；上下文数量使用按钮内计数标识，不再重复展示说明卡片。
- 点击“提示词增强”后在操作行下方展开“增强模型”动态选择器与“确认增强”按钮；加载期间保留稳定的紧凑选择器，避免大尺寸空状态引发布局跳动。
- 增强候选继续由 `listCandidates()` 动态读取，不写死服务商或模型；未选择可用模型时“确认增强”保持禁用，只有点击该按钮才执行 `prepare()` 与带确认 ID 的 `submit()`。
- 紧凑模式只由专业生图显式启用，图片编辑与视频页继续使用原有共享组件布局；上下文弹窗、隐私校验和候选按需读取逻辑未改动。
- 专业生图移除模型选择器下方重复的“已锁定参数合同 / 费用 / 可准备”展示块；候选可用性、参数 Schema 版本、费用事实与确认快照仍由原提交链路校验，快速生图的共享默认展示不变。
- 按最新界面反馈进一步压缩动态参数表单：移除每个非布尔字段右上角常驻的“使用默认值 / 已设置”状态与圆点，空值含义仅通过未填写时的“可留空”占位表达；字段 ID、实际值、默认值语义与提交合同不变。
- 普通字段最小高度由 7.25rem 收紧为 3.25rem，控件最小高度由 2.75rem 收紧为 2.25rem；字段内间距与上下留白同步减少。控件填满横向表单行中标签列以外的剩余空间，JSON 多行输入仍跨双列并保留编辑高度。
- 按确认稿将参数字段内部改为横向表单行：左侧约 7rem 参数名与详情图标，右侧为自适应控件。动态参数增加无视觉外层测量容器并使用 CSS Container Query；父级有效宽度不足 620px 时参数列表为单列，达到 620px 后自动分为两列，不再依赖整个窗口宽度。JSON 对象字段始终跨两列。
- 按最新反馈将“1 - 8 · 仅限整数”一类范围、步长和格式约束从控件下方移入参数详情浮层，并以“填写要求”分组展示；约束不再占用表单行高度，字段值与校验逻辑不变。
- 模型选择器不再向用户展示内部 `runtime_not_allowed` 原因，图片、视频与提示词增强也不再为该原因弹出错误通知；候选仍保持不可用、生成按钮保持禁用，提交瞬间返回该错误时静默撤销进度提示，底层在线运行授权门禁未改变。其他可操作的模型不可用原因继续显示。

## 三、验收结果

- 浏览器桌面尺寸：参数稳定双列，JSON 文本域跨双列，字段标题、详情与控件无重叠。
- 浏览器窄宽断点：参数切换单列，7 个字段内部 `scrollWidth` 均未超过 `clientWidth`；应用壳既有 `800px` 最小宽度约束保持不变。
- 交互检查：数值范围与“仅限整数”等约束通过参数详情查看，不改变表单行高度；布尔开关可从“关闭”切为“开启”。
- 回归合同检查：图片与视频的 `needsSave` 分支均不得清空候选，自动保存期间动态参数表单保持挂载。
- 专业生图与上下文选择器定向契约测试 19 项通过；覆盖紧凑工具组、展开状态、动态候选、确认门控、上下文计数与原有隐私边界。
- `pnpm.cmd test`：Node/UI 307 项与 Vitest 742 项，共 1049 项通过，0 失败、0 跳过。
- `pnpm.cmd typecheck`、`pnpm.cmd lint`、`pnpm.cmd build` 与 `git diff --check` 通过；构建仅出现既有 Vite CJS API 与大 chunk 警告。
- 一次将全量测试与类型、Lint、构建并行执行时，6 个无关平台 I/O 用例超过固定 5 秒超时；取消资源争用后单独重跑并在本次 UI 调整后再次执行全量测试，最终 1049 项全部通过，未修改相关平台实现或测试。
- 本地浏览器可进入专业生图离线页且控制台未用于注入项目数据；由于浏览器环境不具备 Electron 项目与草稿端口，真实紧凑控件区不挂载，未伪造桌面数据进行视觉验收。最终效果以项目负责人已确认的 `compact-enhance-model-picker.html` 方案和本次 DOM/CSS 契约为准。
