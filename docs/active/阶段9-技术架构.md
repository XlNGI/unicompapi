## 一、架构结论

阶段 9 采用“同一业务事实、平台适配隔离、真实设备执行、证据驱动收口”的架构：

1. Windows 与 macOS 共用领域实体、状态机、IPC 语义、页面信息架构和验收用例；文件、权限、窗口、输入、通知、快捷键、进程、休眠、媒体和安全存储差异由平台适配层承担。
2. 阶段 9 不新增一级页面或业务功能，主要工作是审计跨平台假设、补齐适配器、修正平台缺陷、建立可重复验收矩阵并在真实设备上形成证据。
3. 能力状态必须来自当前设备探测。`unknown`、`unsupported`、`unavailable`、`failed` 和 `not_run` 不得投影成成功，也不得因为另一平台通过而继承通过。
4. 每个目标操作系统与架构是独立验收单元。目标矩阵由项目负责人批准；每个必需单元必须在对应真实系统执行，跨平台编译、模拟值或测试替身不能替代实机结论。
5. 阶段 9 完成的是未打包 Electron 应用的跨平台工程验收。安装包、代码签名、公证、生产更新、生产媒体组件分发、SBOM 和正式发布准入仍属于阶段 10。
6. `.tools/` 与 FFmpeg 继续只限本地开发/测试。任何 macOS 开发媒体工具链必须先单独批准固定版本、来源、架构、SHA-256、许可和验证规则；二进制与下载包不得提交。
7. 阶段 9 不以“能启动”替代完整验收。核心页面、项目/文件、任务/作品、服务商、图片/视频工作区、视频编辑、本地设置、失败恢复和安全边界都必须进入双平台验收矩阵。

## 三、目标平台矩阵

阶段 9 首个任务必须冻结 `PlatformTargetMatrix`，至少记录：

- `os`、操作系统版本、`arch`、Electron/Node 版本；
- 显示缩放、主题、语言与区域；
- 文件系统是否区分大小写、路径与 Unicode 规范化特征；
- 是否具备项目负责人批准的本地开发媒体工具链；
- 本次要求执行的用例集合与明确不适用原因。

最低矩阵包含当前 Windows x64 基线和至少一台项目负责人批准的 macOS 真实设备。若阶段 10 计划支持多个 macOS 架构，则 Intel 与 Apple Silicon 必须分别有证据，或明确把未验证架构排除在支持声明之外。

每个用例状态严格限定为：

    passed | failed | blocked | not_run | not_applicable

`not_applicable` 必须有经审核的平台事实；`blocked` 和 `not_run` 不能计入通过。CI 的 Windows/macOS runner 可用于重复门禁，但不能替代可见 Electron、权限提示、文件选择、外接存储、通知、快捷键、休眠恢复和媒体闭环的实机证据。

不得记录设备序列号、用户账号、完整本地路径、凭证、原始日志或其他个人标识。

## 四、平台边界与适配层

领域层和页面业务逻辑不得根据 `process.platform` 改变实体、状态机或成功条件。平台差异通过显式端口和能力 DTO 投影：

    PlatformRuntimeFactsPort
    WindowLifecyclePort
    DirectoryPermissionPort
    SecureStoragePort
    NotificationPort
    ShortcutPort
    ProxyPort
    ProcessRunnerPort
    PowerLifecyclePort
    FontCapabilityPort
    MediaEngineAdapter

平台事实统一使用稳定原因码，不把异常消息、原生对象或平台句柄直接传给 renderer。允许在 Electron 组合根选择 Windows/macOS 适配器；不允许把路径分隔符、系统设置 URL、快捷键、字体、窗口按钮或进程信号散落在领域与页面组件中。

必须建立静态审计清单，覆盖：

- `process.platform`、`process.arch` 与 Windows/macOS 字面量；
- 反斜杠、盘符、大小写敏感、保留文件名和超长路径假设；
- `spawn`、进程树终止、信号、休眠和退出顺序；
- `safeStorage`、目录授权、系统设置入口、通知和全局快捷键；
- 字体回退、键盘修饰键、标题栏安全区、Dock/任务栏与窗口生命周期；
- 开发媒体工具链的扩展名、归档格式、来源和架构。

## 五、文件、目录与安全存储

跨平台验收必须覆盖：

- 项目创建、打开、关闭、重开、只读、断盘和损坏恢复；
- 原子 JSON 写入、备份读取、并发 revision、临时文件清理和崩溃窗口；
- FileReference、SHA-256、索引重建、重定位和同名不同内容拒绝；
- 外部引用、项目托管副本、Work、缓存和正式输出的边界；
- 路径分隔、大小写差异、Unicode 文件名、空格、长路径、符号链接和目录逃逸；
- 原生选择器授权、撤销授权、外接卷断开与重新挂载；
- `safeStorage` 在两平台上的可用、不可用、解密失败和旧凭证保留策略。

正式结果仍需本地文件、可信媒体探测、字节与 Hash 校验后才登记 Work。任一平台失败都不能通过默认值、临时文件或另一平台结果伪造成功。

## 六、窗口、输入、视觉与可访问性

- Windows 与 macOS 保持同一八项一级导航、图片五项和视频四项二级导航；不恢复“首页”或废止能力。
- macOS 使用原生标题栏安全区和窗口生命周期；关闭最后窗口不等于退出，Dock 重新激活必须恢复可用窗口。
- Windows 自定义窗口控制与 macOS 原生控制不能互相遮挡品牌、主题、搜索、导航或页面内容。
- `Ctrl`/`Command`、`Alt`/`Option`、删除、撤销/重做和全局快捷键通过动作注册表映射，不在页面写死。
- 深色、浅色、跟随系统、字体回退、缩放、减少动态效果和高 DPI 必须在两平台对照。
- 所有核心操作键盘可达，焦点可见，标签、状态、错误、对话框和进度语义可被辅助技术识别。
- 最小窗口和常见窗口尺寸不得出现横向溢出、文字裁切、按钮越界或固定层无意义遮挡。

阶段 9 不新增业务 UI。仅允许修复平台布局、真实状态、可访问性和现有交互缺陷。

## 七、网络、通知、快捷键与权限

- 系统代理、直连和自定义代理继续使用同一两阶段事务；切换只影响新请求，探测不携带项目、提示词或服务凭证。
- 代理凭证只进入本机安全存储；设置 JSON、便携导出、日志、诊断包和 renderer DTO 不得包含明文或可逆引用。
- macOS/Windows 通知权限、系统通知、应用内降级和声音分别记录事实；通知失败不改变 Task/Execution。
- 快捷键使用同一动作 ID、平台独立默认值和冲突规则；只有原生注册成功才显示启用，退出与崩溃恢复时释放。
- 打开系统设置使用平台白名单目标；未知权限状态保持 `unknown`，不得伪造成已授权。
- Electron renderer 继续保持 `contextIsolation`，禁止 Node 集成与任意文件/外链权限；外部链接只经受控系统浏览器打开。

## 八、进程、媒体、硬件与电源生命周期

- 子进程必须使用结构化参数数组，不经 shell 拼接；取消、超时、应用退出和崩溃恢复必须终止本次受控进程树并清理临时文件。
- Windows 与 macOS 分别验证进程退出码、取消确认、强制终止、僵尸/残留进程和启动恢复。
- 睡眠、唤醒、锁屏、后台和关闭窗口时，活动 Task/Execution 不得静默完成、重复提交或丢失恢复要求。
- 媒体探测、预览、缩略图、波形和软件导出必须在项目负责人批准的当前平台开发工具链上真实执行；没有批准工具链时保持不可用并将对应验收单元标为阻断。
- 硬件能力按当前机器探测。未批准或未验证时显示不可用；硬件失败不得阻止软件导出。
- `.tools/`、压缩包、可执行文件和本机安装路径继续由 Git 忽略，不进入生产构建。

阶段 9 可以形成 macOS 本地开发/测试媒体工具链决策，但不得批准生产分发。生产版本、源码构建、编解码器白名单、专利/商业审查、签名和组件更新仍进入阶段 10。

## 九、完整验收域

完整验收按真实能力覆盖以下域：

1. 桌面壳：启动、退出、窗口、导航、主题、响应式、键盘和焦点；
2. 项目与本地存储：创建、打开、重开、只读、断盘、损坏、备份、重定位和索引；
3. 全局页面：项目、任务中心、作品库和对话页的真实空白、失败、恢复与禁止入口；
4. 服务商：本机安全凭证、连接状态、动态能力和未配置/失败状态；
5. 图片创作：工作区草稿、本地单图、能力预检、提交边界、结果校验和作品登记；
6. 视频创作：三种工作区、单参考素材、能力预检、提交边界、结果校验和作品登记；
7. 视频基础编辑：草稿、媒体来源、预览、编辑、软件导出、取消、失败、恢复、任务和 Work；
8. 本地设置：10 分类、设置持久化、目录/代理/性能/权限/通知/快捷键/诊断/更新真实状态；
9. 安全边界：renderer DTO、日志、诊断包、凭证、路径、Hash、外链和本地文件权限；
10. 禁止能力：首页、多图参考、批量创作、直接对话生成、账号/会员/充值/云同步和虚假生产能力均不存在。

外部后台契约或生产基础设施未提供时，验收目标是稳定、真实、可理解的阻断状态，不是伪造业务成功。任何未执行的真实生成、下载、更新或硬件能力都必须在总表中明确标为 `blocked` 或不在已批准支持范围。

## 十四、C2 Vidu 官方 API 接入范围例外（2026-07-28）

## 十五、Windows 必需目标与 macOS 延期目标决策（2026-07-31）

项目负责人明确决定阶段 9 不执行 macOS 实机与本地开发/测试媒体工具链，保留未来补齐入口。目标矩阵调整为：

- `windows-x64-primary` 继续为 `required=true`，九类套件和 Windows 人工项仍须按阶段 9 收口规则处理；
- `macos-primary` 保留在同一矩阵，允许架构、`real_device` 证据模式和九类套件均不删除，但改为 `required=false`；
- 验证器继续要求矩阵中存在 macOS 目标，防止后续实现删除 macOS 适配和证据入口；
- macOS 当前结果继续记录为 `not_run/deferred`，不得改写为 `passed`、不得用于发布支持声明，也不阻塞本次 Windows 阶段 9 收口；
- 未来重新启用 macOS 时，必须另行批准真实设备、媒体工具链版本/来源/架构/SHA-256/许可，并独立执行九类套件。

该决策只调整阶段 9 必需目标范围，不删除跨平台代码约束，不改变阶段 10 的 macOS 打包、签名、公证和发布准入边界。
