## 一、批准边界

本支只实现安全公开候选、短期一次性 routeSelectionToken、全量绑定事实失效、项目元数据单元与应用级授权账本协调的媒体/文本提交编排和恢复决策。未修改 React、preload、Electron 页面、Renderer IPC、真实协议适配器、历史数据、阶段 10 或 macOS 实机目标。

本支禁止真实服务商 HTTP、真实凭证读取/验证和收费调用。Vidu 两项已用尽预算继续封存，Image V1 未验证事实不变。

## 二、实际实现

- 新增显式 `draft | conversation_response_draft` 候选主体，ProductFeature 只从持久化主体解析，不接受 renderer 单独传入，也不按素材存在性推断或切换功能。
- 新增安全候选 DTO 和稳定排序；只公开不透明 candidate ID、安全显示名、投影后的 ParameterSchema、UsageSchema 版本、费用事实和可展示不可用原因，不公开 Profile/Evidence、adapter/protocol、endpoint、凭证、远端 ID 或下载 URL。候选查询不签发令牌，也不自动选择唯一候选。
- 新增内存短期 `RouteSelectionTokenVault`。prepare 重新执行功能与参数 preflight，冻结草稿/回复草稿 revision、参数、素材、上下文、外发文本、接收方、费用、精确路由、Schema、Runtime Policy 和候选可用事实的规范化 SHA-256 指纹；renderer 只得到随机不透明令牌、过期时间和确认 DTO。
- 提交前原样复核确认 ID并重新解析全部绑定事实。令牌篡改、未知、过期、已消费、主体 revision、参数、素材、Context、候选、连接、模型、Profile、Binding、Adapter、Schema、运行授权 revision、费用或外发事实变化均返回明确失败，HTTP 为 0。
- 新增 `ProjectSubmissionAcceptanceStore`，使用 `ProjectMetadataUnitOfWork` 原子接受 SubmissionIntent、完整 RouteSnapshot、媒体 Task/Execution 或 ConversationResponseExecution、ProviderInvocationAttempt/Event 和幂等键；跨控制器并发通过 CAS 重试和 idempotency key 保证只接受一次。
- 新增 `submitDraft` 与 `submitConversationResponse` 两个领域分离入口。项目事实先落盘，再以预生成 claim ID 对应用级 RuntimeAuthorizationLedger 原子 claim；claim 失败时意图进入 `authorization_not_claimed` 且 attempt 进入 `failed_before_submission`，不调用适配器。
- 适配器提交端口必须在任何请求字节前回调 `beforeRequestStarted`。回调前失败会释放 claim 并记录远端调用 0；回调后异常进入 `unknown_outcome`、`retryAllowed=false`。异步接受、同步完成和主进程 ProviderOperationRecord 都只在项目事实中追加；相同 token/idempotency 重放不会产生第二次提交。
- 新增项目接受事实恢复扫描，区分未完成 claim 协调、可释放 claim、请求结果未知和按提交时快照恢复 query/cancel/receive_result。
