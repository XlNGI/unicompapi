## 一、范围与边界

本支是 M3 第二支，只实现媒体与文本 Provider 调用的跨项目安全读模型、严格用量解释和受控 Electron IPC/preload 查询端口，不修改任务中心 React 页面，不启动任何 UI 分支。

本支未新增具体厂商适配器或 Package，未发起真实服务商 HTTP，未读取或验证真实凭证，未产生收费调用；Vidu 预算继续封存，未执行 macOS 实机与媒体工具链，阶段 10 未启动。

## 二、实际实现

### 2.1 跨项目调用列表与详情

- 新增 `ProviderInvocationReadModelController`，从项目目录聚合 ProviderInvocationAttempt/Event、不可变 RouteSnapshot、UsageObservation、LocalResultObservation 和 Work 登记事实。
- 列表支持按项目、ProductFeature、Provider、Connection、Model、状态和创建时间筛选，提供稳定排序、偏移分页、总数和项目不可用/数据无效问题列表。
- 详情返回调用主体、脱敏时间线、终态耗时、显式重试关系、用量白名单事实、本地结果属性和 Work 登记状态。
- 重复 invocation attempt ID、缺失路由快照、跨项目事实不一致、缺失精确 UsageSchema 或损坏数据均失败关闭，不拼接或猜测历史事实。

### 2.2 用量与显示名快照

- 新增 `ProviderUsageSchemaRegistry`，只按 `UsageSchema ID + revision` 精确解释已记录用量；存在观察但缺少精确 Schema 时不返回推测用量。
- 无用量观察的调用保持可读，并诚实返回 `not_reported` 或 `unknown_outcome`。
- RouteSnapshot 新增可选的 Provider、Connection、Model 提交时显示名；提交编排器在生成不可变快照时写入候选显示名，旧快照缺失时返回 `displayNameAvailability=unavailable`。
- 调用事件仓储支持一次读取项目全部事件，避免按 attempt 重复读取，同时继续保留按 attempt 精确查询能力。

### 2.3 安全 IPC 边界

- 新增命名 `listCallRecords` 与 `getCallDetails` IPC、共享 DTO 和 preload API；所有请求拒绝未知字段和越界分页。
- 公开 DTO 不包含 RouteSnapshot ID、Package/Adapter、Endpoint、凭证、运行授权、Prompt、路径、Hash、远端 operation、原始响应、签名 URL 或原始日志。
- 本支只提供读取端口，不新增调用修改、自动重试、自动路由或 Work 登记入口。
