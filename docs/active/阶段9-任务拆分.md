## 三、分支与证据原则

- 所有功能分支从最新 `develop` 创建，合并后保留本地与远程分支。
- A 负责桌面壳、页面、交互、可访问性和界面证据；B 负责平台契约、文件/进程/安全/媒体适配、故障与证据工具。
- 同一开发者按 B1-B4 或 A1-A4 顺序执行；满足前置后，A/B 可并行。
- 每个 PR 只处理一个可审平台域，不允许以“跨平台重构”为名重写整个应用。
- 实机失败先形成最小复现、目标单元和证据，再修复；不得用平台判断跳过失败。
- 证据只提交脱敏的小型文本、JSON、截图和必要 Hash，不提交用户文件、大媒体、凭证、完整路径、原始日志或二进制。

本节新增任务建立在阶段 9 Windows x64 基线之上。原 B1-B4、A1-A4、C1、C2 流程和阶段 9 收口证据保持有效；E1-E4 已按独立小 PR 完成本地合同与自动化验收，E5-E6 仍为 `planned/not_started`，完成前不得宣称完整智能文档 Agent 已支持。

### E1｜LLM 意图与需求计划

建议分支：`feature/phase9-document-intent-plan`

范围：

- 新增封闭 Schema 的 `DocumentIntentPlan`；
- 新增封闭 Schema 的 `RevisionPlan`，记录目标文档、基础版本、页面/章节/表格/单元格范围、补丁操作、保留条件、幂等键和回滚信息；
- 支持 chat/create/revise、Word/Excel/PPT、主题、受众、目的、页数、风格、约束、资料策略、置信度和缺失项；
- 保留现有本地规则作为高置信度快速路径和 LLM 失败回退；
- 由 Application 层解析候选文档和页面/表格/章节范围，LLM 不直接返回可执行路径或内部 ID；
- 增加中置信度确认、低置信度追问和普通聊天防误触发；
- 建立脱敏自然语言黄金样本集。

验收：意图、类型、目标和范围准确率有基线；目标不唯一或范围不完整时进入追问；低置信度不生成；模型不可用时规则回退；`RevisionPlan` 不含绝对路径、凭证、任意 URL 或任意代码；无 Prompt/思维链/凭证泄漏。

### E2｜企业资料分层 RAG

建议分支：`feature/phase9-document-retrieval`

范围：

- 统一项目附件、产品资料、品牌规范、模板元数据和历史确认内容的资料 DTO；
- 现有 BM25 保持可用并作为回退；
- 评测通过后再增加 embedding 与本地可重建向量索引，不绑定具体数据库或服务商；
- 每个片段记录 project/file/source/page/sheet/section/contentHash/indexVersion；
- 支持来源引用、删除/重建、资料过期和索引版本升级；
- 检索结果作为不可信资料，不可覆盖系统指令。

验收：Recall@k、MRR、延迟、空结果率、引用准确率和资料支持率有脱敏报告；附件变更可增量更新；索引损坏可从源文件重建；BM25/向量任一路径失败时不阻断本地生成。

### E3｜受控联网搜索

建议分支：`feature/phase9-document-web-research`

前置：E1 资料策略和 E2 来源 DTO 通过验收；联网和收费调用需再次批准。

范围：

- `internal_only/web_only/mixed` 资料策略；
- 用户明确授权、外发范围提示和取消入口；
- 受控搜索适配器、域名/来源策略、超时、条数、预算、缓存和离线回退；
- 外部证据 DTO：标题、URL、域名、发布时间、检索时间、摘要、Hash 和引用关系；
- 搜索结果清洗、去重、时间有效性和提示词注入隔离；
- 禁止自动上传企业附件全文，不接受模型任意 URL 或任意工具参数。

验收：授权前不发网络请求；拒绝、超时、无结果和网络中断均有明确状态；每个外部事实可追溯到来源；外部内容不会改变系统指令；未授权时完全回退本地 RAG。

### E4｜内容大纲与页面视觉计划

状态补充（2026-09-01）：已完成 `PresentationPlan` 中间表示、模板/版式复用、来源引用、容量快照和 revision 作用域保留条件；定向自动化验收通过。

建议分支：`feature/phase9-document-presentation-plan`

范围：

- 将内容大纲、页面结构、布局、数据来源和保留约束拆为独立中间表示；
- 将旧版文档解析为可寻址结构，支持页面、章节、表格、图表、形状和单元格级补丁目标；
- 将用户修改要求转换为可重放的 `RevisionPlan`，未被计划覆盖的结构形成显式保留条件；
- 支持大纲草稿和按风险/置信度的可选用户确认；
- 生成页面类型、版式、容量、图表和素材计划；
- 复用现有五套 PPT 模板和版式引擎，不新增一级页面。

验收：大纲确认/拒绝/修改状态可持久化；页面计划与 `RevisionPlan` 可重放；用户指定页面或数据范围之外的内容有可验证保留约束；目标 revision 变化时拒绝静默覆盖；旧版文档不被覆盖。

### E5｜受控工具、渲染与质量校验

状态补充（2026-09-01）：E5.1 工具注册表、E5.2 有界 Agent 调度循环、E5.3 结构化文档读取/补丁适配层、E5.4 临时版本/确定性诊断合同、E5.5 RepairPlan/有限修正循环和 E5.6 原子发布合同已完成本地自动化验收；真实 Office 文件/渲染接入和 E6 仍未启动。

建议分支：`feature/phase9-document-agent-tools`

范围：

- 建立工具注册表、工具版本、输入/输出 Schema、权限、幂等性、超时、费用/资源级别和可取消能力；
- 白名单工具：资料提取、数据汇总、图表生成、素材选择、Word/Excel/PPT 结构读取与补丁、PPTX 创建、PDF/图片渲染、布局检查；
- 建立 Application 层 Agent 调度器：一轮只执行一个注册工具，执行前校验 `baseWorkId`、`expectedRevision`、项目作用域、目标范围、用户授权和预算，执行后只向 LLM 返回结构化脱敏观察 DTO；
- 修改工具必须采用结构化补丁并先写临时版本，支持 Word 段落/章节/表格、Excel 工作表/范围/列/公式、PPT 页面/形状/布局/图表级操作；不得依赖“整篇重新生成并尽量保持不变”保证修改范围；
- 受控 IPC 和结构化 DTO；renderer、LLM 和不可信资料不得获得绝对路径、内部文件句柄、凭证、任意 URL 或未登记工具参数；
- OOXML、字体、布局、溢出、重叠、一致性、内容来源和 Hash 校验；
- 确定性修复优先，LLM 仅根据结构化诊断输出限定范围的 `RepairPlan`；修正计划必须重新经过 Schema、权限、范围、revision 和预算校验；
- 最大工具步数、最大修正次数、总超时、费用/资源预算、取消、连续相同诊断熔断、失败隔离和恢复；具体阈值在本任务验收时冻结并由配置/策略提供，不写死服务商、价格或对外文案；
- 将等待响应、revision 冲突重试和 Agent 工具循环分为独立状态与审计事件，禁止把生命周期轮询计作模型规划步骤或在 Agent 超限后静默整体重写；
- 仅在最终临时版本通过全部校验后原子发布并登记新 Work；失败、取消、超限或 revision 冲突不登记新 Work，旧版本保持可打开。

E5 建议拆为六个小 PR：

1. E5.1 工具注册表、Schema、权限和策略合同；
2. E5.2 Agent 调度器、状态机、观察 DTO、幂等和取消；
3. E5.3 Word/Excel/PPT 结构读取与补丁工具；
4. E5.4 临时版本、PDF/图片渲染和质量诊断；
5. E5.5 确定性修复、`RepairPlan` 和有限复检循环；
6. E5.6 原子发布、Work 登记、恢复、审计和 Windows x64 收口。

验收：工具越权、任意路径、任意 URL、超预算、无限循环、重复相同诊断和取消均被拒绝；只修改 PPT 第 2 页时其他页面内容 Hash 不变；Excel 只增加指定列时其他单元格不变；Word 只替换指定段落时其他章节不变；相同幂等键不重复写文件或产生费用；revision 冲突不静默覆盖；渲染结果可打开；结构/视觉问题可重现；修正失败不登记 Work，旧版本可打开。

### E6｜交付说明与完整验收

范围：

- 交付 PPTX、预览、使用的内部/外部来源、检索时间、生成参数和修正摘要；
- 交付中记录基础版本、实际修改范围、工具步骤摘要、确定性修复与 LLM 修正次数、终止原因和最终校验结果，但不暴露内部 Prompt、思维链、绝对路径或凭证；
- 任务中心与会话展示真实阶段；
- 建立端到端 Windows x64 验收矩阵，并保留 macOS `required=false/not_run/deferred` 边界；
- 全量测试、类型、lint、build、平台审计、交接校验、差异检查和安全字段扫描。

阶段 9 扩展的完成条件：E1-E6 全部有实现提交、自动化门禁、Windows 实机证据、脱敏来源/费用审计和失败矩阵；当前 E6 仅完成自动化 preflight，Windows 实机人工证据尚未补齐，任一环节未完成，只能记录为 `planned` 或对应失败状态，不得宣称完整 Agent 能力。

### E7｜生产 Agent 接入与语义局部修改闭环（负责人批准，2026-09-01）

状态：`approved/not_started`。E7 建立在 E1-E6 本地合同之上，属于阶段 9 收口后的独立 Office 扩展；不重开原跨平台基线，不启动阶段 10。

范围：

- 将对话文档请求接入 Application 层 `runDocumentAgentLoop`，Provider 仅通过受控 tool calling 产生工具请求；
- 接入真实 Office 文件结构读取、局部补丁、预览渲染和布局检查执行器；
- 支持“清空/改写指定章节、页面、工作表范围或段落”等语义操作，保留标题、层级、版式及非目标内容；
- 每次修改使用 `baseWorkId`、`expectedRevision` 和临时版本，校验通过后原子发布并登记新 Work；
- UI 展示真实阶段和修改摘要，不把模型机器 JSON 作为最终回复。

验收门禁：

- “清空第二章”等自然语言请求必须产生真实读取与补丁工具调用；
- 目标范围发生实质语义变化，非目标内容 Hash 保持不变；
- docx/xlsx/pptx 可在 Windows Office 打开，渲染和布局诊断可复现；
- 取消、超时、预算、权限、revision 冲突、重复诊断和失败恢复均有审计状态；
- 自动化门禁、Windows Office 人工证据、失败矩阵和交付审计齐全后方可将 E7 标记为 `passed`；未满足前不得进入依赖 E7 的后续阶段。
