# 专业生图流程优化分阶段实施计划

日期：2026-08-06

状态：产品决策已由项目负责人确认；**PR1–PR3 已在分支 `feature/professional-image-feature-gate` 完成实现，待合并 develop**

权威前置文档：`AGENTS.md`、`PLANS.md`、`docs/active/阶段9-UI与多服务商功能路由最终方案.md`、`docs/active/阶段5-A2-专业生图页面记录.md`

决策来源：项目负责人 2026-08-06 口头确认（见「二、产品决策冻结」）；2026-08-06 下令开工；同日要求直接完成整个计划。

## 一、计划结论

**本计划目的：优化生图功能**（以专业生图为完整范式）。

只优化**专业生图**（`professional_image`）中的文生图与图生图体验，形成「功能 → 模型 → 动态参数 → 页内提交流程」；可选「提示词增强」服务于生图提示词，是生图工作流内的纯文本改写，不是新的一级业务，也不是对话入口。

**本轮不动**：快速生图产品行为（以后按本方案简化）、对话页、图片转提示词一级入口、视频创作。

实施按 PR1 → PR2 → PR3 顺序；本轮因负责人要求「直接完成整个计划」，三项均在同一功能分支落地，合并后保留本地与远程分支。

## 二、产品决策冻结（2026-08-06，项目负责人）

1. **功能门禁**：未选择文生图（`text_to_image`）或图生图（`reference_to_image`）前，**不展示模型选择与参数表**；
2. **动态参数**：继续只用已登记、版本化的 ParameterSchema（现状），不新建「运行时拉取远端 OpenAPI」路径；
3. **生图进度 UI**：留在专业页内，步骤为 **准备 → 请求中 → 等待上游返回数据 → 完成**（失败单独呈现）；
4. **提示词增强**：可选；**单独能力**；用户选择 LLM（`text_chat` / `text_reasoning`）；**不得创建图片 Task**；
5. **增强结果写入**：方案 **A**——只写入「系统补充」（`systemSupplements`）；最终提交提示词由用户确认/合并；
6. **增强进度 UI**：与生图同四步——准备 → 请求中 → 等待上游返回数据 → 完成；
7. **增强入口位置**：与提示词区**并列可选**，不挡选生图模型；
8. **入口分工**：专业页增强明确为「纯文本改写」；「图片转提示词」页继续只负责看图出稿，**互不合并入口**；
9. **范围**：只动生图能力相关专业页；专业生图做最详细流程；快速生图将在后续按本方案简化，本轮不改其产品行为目标；
10. **草稿自动保存（2026-08-06 追加）**：专业生图由后台自动保存草稿；用户流程为选功能 → 选模型 → 填动态参数 → 提交请求，**不得再强制用户手动点「保存本地草稿」才能下一步**。

## 三、与现状对照

| 需求 | 现状 | 本计划 |
|---|---|---|
| 选功能后再选可用模型 | 已有文/图切换与按 feature 过滤候选；提交面板仍有推断兜底 | PR1 收紧门禁并去掉专业页推断兜底 |
| 按锁定 Schema 显示参数 | 已有 `DynamicParameterForm` | PR1 沿用，不改权威来源 |
| 提交后页内流程 UI | 专业页仅消息文案；细节在任务中心 | PR2 页内四步条 |
| 提示词增强 + 选 LLM | 仅有三层提示词壳，无真实增强 | PR3 独立文本改写路径 |

## 四、技术边界（必须遵守）

1. 不得恢复「首页」一级入口；不得把对话页做成直接生成入口；
2. 图生图继续单张参考图约束；不得恢复多图参考或批量创作；
3. 增强不得创建图片 Task / Execution；保存草稿与增强均不得自动触发生图；
4. 增强外发与生图外发分离：各自准备/确认/提交（费用与接收方可能不同）；
5. 模型名、价格、分辨率、数量等不得写死；参数仅来自已登记 Schema；
6. 凭证不得明文进代码、日志或 Git；
7. 远端结果须经本地校验规则后方可登记为正式作品（生图路径保持现有纪律）。

## 五、里程碑与改动归属

### PR1｜专业页信息架构与模型门禁 — **已完成**

**分支：** `feature/professional-image-feature-gate`

**用本 PR 的决策：** 决策 1、2

主要改动：

- `ImageFeatureSubmissionPanel` 增加 `requireExplicitFeature`（仅专业页开启）；
- 未显式选择文生图/图生图时：不拉取候选、不展示模型与参数表；
- 专业页不再依赖「有参考图则推断图生图」的面板兜底；
- 快速生图默认不传该开关，行为保持。

验收：

- 未选功能：无模型下拉、无参数表；
- 选文生图 / 图生图：仅出现对应功能可用模型；参数随所选候选 Schema 变化。

### PR2｜生图提交页内四步进度 — **已完成**

**用本 PR 的决策：** 决策 3

主要改动：

- 新增 `SubmissionProgressSteps`（准备 → 请求中 → 等待上游返回数据 → 完成）；
- 专业页 `showProgressSteps` 映射 prepare / confirm / submit 执行过程；保留确认外发。

### PR3｜提示词增强（纯文本改写） — **已完成**

**用本 PR 的决策：** 决策 4—8

主要改动：

- 新增 `image-prompt-enhance` IPC / `ImagePromptEnhanceService`：复用文本候选目录与 chat 适配器，不创建图片 Task；
- `ImagePromptEnhancePanel`：并列可选，选 `text_chat` / `text_reasoning`，独立准备/确认/提交与四步进度；
- 成功结果写入 `systemSupplements`（source=`enhancement`）；用户可手动合并到最终提示词；
- 不改图片转提示词页，不跳转对话页。

## 八、停止条件

- 需要新增一级业务页面或恢复禁止能力；
- 增强被要求自动创建图片 Task 或与生图一次外发捆死；
- 要求改为运行时抓取未登记远端 API 文档作为参数权威；
- 范围扩展到快速生图/对话/转提示词本轮一并改造。
