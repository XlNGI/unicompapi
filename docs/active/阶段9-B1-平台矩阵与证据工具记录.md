## 二、实际修改

### 平台与证据契约

新增严格的 `PlatformTargetMatrix`、`PlatformRuntimeFactsPort`、验收状态、套件 ID、结果和证据 manifest 契约。运行时事实只记录操作系统、版本、架构、Node/Electron 版本、路径分隔符、大小写/Unicode 观测状态、语言区域和时区，不记录主机名、用户名或绝对路径。

证据引用必须保持在 `docs/active/evidence/phase9/` 内，拒绝绝对路径、盘符和目录逃逸。目标完成判定要求每个必需套件至少有结果且全部为 `passed`。

### 平台假设审计

新增静态审计清单和命令，覆盖 `electron/`、`scripts/` 与 `src/` 中的 TypeScript、TSX 和 MJS 文件。审计冻结：

- 直接 `process.platform` / `process.arch` 访问；
- `win32`、`darwin`、`windows`、`macos` 平台字面量；
- Windows 用户绝对路径、POSIX 用户主目录和 `shell: true` 禁止模式。

新匹配、失效白名单或禁止模式都会使命令失败，后续任务必须在明确的平台组合层或适配器中处理差异。

### 校验与采集工具

新增以下命令：

    npm.cmd run verify:handoff
    npm.cmd run audit:platform
    npm.cmd run collect:platform-evidence -- --source-commit <commit>

交接校验逐项验证 `SHA256SUMS.txt`，并验证资源 manifest 的 SHA-256 与字节数。证据采集只接受目标矩阵中的真实运行时，默认把所有套件写为 `not_run`；操作者必须显式声明实际完成的套件状态。
