# 阶段 2｜任务拆分：双人重新分工

日期：2026-07-21

## 一、阶段目标

阶段 2 建立不依赖在线服务的本地领域基础：

- 项目、草稿、素材、文件、任务和作品实体；
- 本地目录与索引边界；
- 草稿、任务、执行、下载、校验和作品登记状态边界；
- 文件丢失、只读、外置存储断开和恢复语义；
- 渲染进程与 Electron 主进程之间的最小受控接口；
- 可供后续页面使用的状态组件与测试数据。

本阶段不接真实后台，不实现图片或视频生成，不实现完整业务页面。

## 二、共同规则

1. 所有任务从最新 `develop` 创建短期 `feature/*` 分支。
2. 领域类型和状态机是唯一事实来源，UI 不得另建一套业务状态。
3. 主进程不向渲染进程暴露通用 Node 或文件系统能力。
4. 不在代码、项目文件、任务、日志或测试数据中写入真实凭证。
5. 不将远端完成结果直接登记为作品；本地下载、写入和校验完成后才允许登记。
6. Windows 与 macOS 使用同一领域契约；平台差异隔离在适配层。
7. 后台接口契约尚未提供，作为阶段 4 启动前置依赖，不在本阶段猜测或写死。
8. 每个 PR 必须包含测试结果、未完成项和跨平台影响说明。

## 三、开发者 B｜本地领域与平台

建议分支：

```text
feature/local-domain-foundation
```

负责范围：

```text
src/domain/
src/platform/
electron/
tests/domain/
```

任务：

1. 定义项目、草稿、素材、文件引用、任务、执行记录和作品实体。
2. 定义稳定 ID、时间字段、版本字段和实体间引用规则。
3. 定义本地目录、索引、临时文件和原子写入边界。
4. 定义任务及文件状态机，覆盖失败、取消、重试、过期、丢失、只读和恢复。
5. 建立存储、文件校验和受控 IPC 的接口，不接真实后台。
6. 为领域规则、非法状态转换和恢复场景建立自动化测试。

不做：

- 不实现真实模型或服务商调用；
- 不实现图片、视频生成；
- 不实现视频编辑引擎；
- 不把 API Key、Token 或用户绝对路径写入日志和测试夹具。

## 四、开发者 A｜UI 状态系统

建议分支：

```text
feature/ui-state-system
```

负责范围：

```text
src/components/
src/pages/
src/styles/
tests/ui/
docs/active/UI对照记录.md
```

任务：

1. 基于 B 提交的领域契约建立空白、加载、失败、过期、服务不可用、文件丢失、只读和恢复状态组件。
2. 建立纯测试夹具和 Story-like 状态展示入口，不接真实后台或文件系统。
3. 补齐组件焦点、禁用、错误、只读和键盘状态。
4. 保持深色、浅色和跟随系统主题的语义 Token 一致。
5. 维护 UI 对照记录，为阶段 3 全局页面准备可复用状态组件。

不做：

- 不复制领域状态机；
- 不在 UI 中推断远端能力、价格、耗时、分辨率或数量；
- 不提前实现阶段 3 完整业务页面。

## 五、合并顺序

1. B 先提交领域类型、状态枚举和状态转换契约的小 PR。
2. 契约合并到 `develop` 后，A 基于最新 `develop` 开始状态组件。
3. B 继续提交存储、索引、文件校验和恢复实现。
4. A 提交状态组件、测试夹具和 UI 验收记录。
5. 两人在 `develop` 联调，禁止互相复制尚未合并的提交。

## 六、阶段 2 验收门禁

- 项目、草稿、素材、文件、任务和作品实体存在且边界明确；
- 本地目录和索引有稳定契约；
- 状态机拒绝非法转换；
- 文件丢失、只读、外置存储断开和恢复有真实可处理状态；
- 基础壳在没有在线服务时可运行；
- IPC 保持最小权限，没有暴露通用 Node 能力；
- 自动化测试、类型检查、Lint 和生产构建通过；
- Windows 验收通过，macOS 差异记录到阶段 9；
- `PLANS.md` 更新实际结果，失败项和阻断项如实记录。
