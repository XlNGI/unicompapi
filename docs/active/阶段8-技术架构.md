## 一、架构结论

阶段 8 采用“本机单一事实、能力驱动展示、普通设置自动保存、高风险操作两阶段确认”的架构：

1. 本地设置是应用级、项目无关、设备本地的数据，不进入项目目录，不云同步，也不与服务商凭证混存。
2. `SettingsDocument` 使用显式 `schemaVersion`、`revision` 和严格运行时校验，通过同目录临时文件、文件同步和原子替换持久化。
3. renderer 只消费设置值、安全状态和能力 DTO；绝对路径、代理密码、日志原文、更新下载地址和平台句柄留在主进程。
4. 普通偏好按成功响应自动保存；目录迁移、代理、并发、硬件加速、清理、重置和清除数据必须先生成影响计划，再由用户明确确认执行。
5. 设置选择与设备事实分离。操作系统、硬件、媒体组件、通知、快捷键、网络和更新能力均由平台适配器动态探测，不能靠默认值伪造成可用。
6. 并发、代理和媒体策略只影响新任务或新 attempt；运行中的 Task/Execution 保留创建时的策略快照，不能被设置页静默改写。
7. 目录迁移采用可恢复事务，不覆盖目标文件，不修改历史 Work 身份；失败时保留原位置为有效事实。
8. 诊断包默认本地生成并严格脱敏，不自动上传；更新功能在没有真实、签名且获批的更新源时只能返回 `unavailable`。
9. Windows 与 macOS 共用领域契约，差异由能力矩阵和平台端口承担；不支持的设置动态隐藏或明确显示不可用。

即使本规划获批，也只批准阶段 8 的工程边界，不批准生产更新源、FFmpeg 生产分发、硬件编码器、系统级代理修改或新的遥测上传。

## 四、设置数据模型

### 4.1 顶层文档

    interface SettingsDocumentV1 {
      schemaVersion: 1
      revision: number
      updatedAt: IsoTimestamp
      general: GeneralSettings
      storage: StorageSettings
      performance: PerformanceSettings
      media: MediaSettings
      privacy: PrivacySettings
      network: NetworkSettings
      notifications: NotificationSettings
      shortcuts: ShortcutSettings
      diagnostics: DiagnosticSettings
      updates: UpdateSettings
    }

约束：

- 设置文件位于 Electron `userData` 下的应用管理目录，不进入活动项目；
- 所有字段必须有类型、范围、默认来源和迁移策略，拒绝未知版本、未知字段和非法组合；
- `revision` 使用乐观并发，更新请求必须携带 `expectedRevision`；
- 默认值来自版本化默认工厂和当前能力，不从 UI 控件反推；
- 设备事实、容量、运行中任务、最近错误、组件版本和权限状态不写入设置文档；
- 平台不支持某项选择时保留用户意图，但有效值由解析结果 DTO 明确降级，不能宣称已生效。

### 4.2 作用域

阶段 8 只允许以下作用域：

- `application`：语言、主题、界面、关闭行为、通知行为、日志级别、更新偏好等本机应用偏好；
- `device`：目录句柄、并发建议、媒体与硬件选择、代理模式、系统能力相关快捷键。

不提供项目级设置覆盖，不把设置复制进项目，不提供账号或云端作用域。导入/导出设置时必须排除代理凭证、绝对路径、目录授权、设备探测、日志、诊断包和其他设备绑定信息。

### 4.3 选择、解析值与状态

读取 DTO 同时返回三类信息：

    interface SettingsSnapshotDto {
      revision: number
      values: PortableSettingValuesDto
      resolved: ResolvedSettingValuesDto
      capabilities: SettingsCapabilityDto
      statuses: SettingsStatusDto
      pendingRestart: readonly SettingKey[]
    }

- `values` 是用户保存的意图；
- `resolved` 是在当前平台、权限和能力下真正会使用的值；
- `capabilities` 描述可见性、可编辑性、允许值和不可用原因；
- `statuses` 是动态事实，不可由 renderer 修改；
- `pendingRestart` 只标记真实需要重启才能生效的设置。

## 五、持久化、迁移与恢复

### 5.1 原子保存

1. 在主进程校验完整文档和 `expectedRevision`。
2. 将新文档写入同目录排他临时文件。
3. 同步临时文件；能力允许时同步目录。
4. 保留最近一个已验证备份，再原子替换正式文件。
5. 重新读取并校验后才返回新 revision。
6. 任一步失败均保留旧正式文件，返回可重试错误，不更新 UI 的已保存状态。

同一进程内所有写入串行化；多窗口或迟到响应通过 revision 冲突拒绝静默覆盖。

### 5.2 Schema 迁移

- 迁移按 `Vn -> Vn+1` 单向、纯函数、逐版本执行并测试；
- 迁移前保留原文件，不在原文档上就地修改；
- 迁移失败进入只读恢复状态，可导出脱敏诊断，不用默认值覆盖损坏文件；
- 导入旧设置先生成差异与兼容性计划，经确认后才写入；
- 导入失败不影响当前有效设置。

### 5.3 恢复默认与清除数据

必须区分：

- 恢复分类默认：只重置所选普通偏好；
- 恢复全部设置默认：重置设置文档，保留项目、作品、任务、服务商注册和本地凭证；
- 清理缓存/日志：只删除可重建缓存或满足保留规则的日志；
- 清除本机应用数据：按影响计划列出范围，默认不包含用户项目目录和外部文件，执行前要求明确选择与确认。

## 六、受控 IPC 与高风险操作

普通 IPC：

    settings:get-snapshot
    settings:update-values
    settings:restore-category-defaults
    settings:export-portable
    settings:prepare-import

高风险操作统一使用两阶段协议：

    settings:plan-operation -> OperationPlanDto
    settings:execute-operation -> OperationResultDto

`OperationPlanDto` 至少包含一次性短期 token、操作类型、设置 revision、影响范围、运行中任务阻断、预计文件数量/字节、可回退性、需要重启项和用户必须确认的风险。执行时重新检查 token、revision、能力、磁盘、权限和任务状态；过期或事实变化必须重新规划。

必须走两阶段协议的操作：

- 默认目录迁移；
- 代理模式或认证信息切换；
- 并发与高性能策略切换；
- 硬件加速策略切换；
- 缓存、日志和临时文件清理；
- 分类或全部设置重置；
- 清除本机应用数据；
- 安装、修复、回退或重启应用更新。

renderer 不接收绝对路径、凭证明文、原始 Hash、更新签名密钥、任意文件删除列表或平台对象。所有路径选择通过主进程原生选择器，DTO 只返回用途、显示名、可用性和受控标识。

## 七、分类设计

### 7.1 常规

- 启动行为、启动后页面、恢复上次会话、检测未完成任务、最小化/关闭行为；
- 主题、界面缩放、密度、动画、减少动态效果、侧栏状态和工具提示；
- 界面语言、日期、时间和文件大小单位；
- 开机自启动与关闭行为必须根据平台能力展示；
- 影响较大的设置标记影响与重启要求，普通偏好自动保存。

阶段 8 不新增登录态、账号头像或云端同步设置。

### 7.2 存储与文件

- 项目、作品、图片输出、视频输出、视频编辑输出、下载和缓存位置；
- 磁盘使用统计、目录权限、外接盘断开和组件状态；
- 缓存/代理/临时导出/旧日志的清理计划；
- 文件命名与冲突策略等普通偏好；
- 恢复默认、迁移缓存和清除本机应用数据分成不同风险等级。

目录迁移流程：选择目标 -> 权限和空间探测 -> 冲突扫描 -> 冻结迁移计划 -> 用户确认 -> 临时复制 -> 字节/Hash 校验 -> 原子切换目录设置 -> 延迟清理旧副本。失败时原目录仍是有效事实，不能把未校验目标标记为可用。

### 7.3 任务与性能

- 节能、平衡、高性能和自定义模式；
- 在线生成、本地图片、本地视频、下载和缩略图等队列的并发意图；
- 后台运行、休眠/电池行为和任务恢复；
- CPU、GPU、内存、温度、电源和当前负载只作动态事实展示。

并发上下限和推荐值来自当前机器能力与任务调度器，不写死为所有设备通用。设置变更只作用于新排队任务；活动 Task/Execution 不被取消、抢占或重写。降低并发后等待现有槽位自然释放。

### 7.4 本地媒体处理

- 图片、视频解码/编码、音频、缩略图、字体渲染等组件真实状态；
- 媒体引擎版本、来源、能力范围和故障原因；
- 硬件探测、自动回退和最近验证结果；
- 预览代理生成、保留原始素材和自动清理规则；
- 检查、修复和恢复操作只能调用已批准适配器。

`.tools/` 中的 FFmpeg 8.1.2 LGPL-only 仍只允许本地开发/测试。阶段 8 不得把它标为生产组件、打入构建或提供虚假的生产修复。硬件能力未获批或未验证时返回不可用，软件导出继续可用。

### 7.5 隐私与权限

- 只访问用户主动选择或已授权的文件与项目目录；
- 剪贴板只在用户触发粘贴时读取，禁止后台读取；
- 禁止整盘和用户目录扫描；
- 图片、视频、项目上下文和费用未知外发保留提交前确认；
- 正式作品和原始素材默认不进入自动清理；
- 平台权限展示真实授权状态和打开系统设置入口。

任何普通设置都不能关闭项目规定的强制外发、费用或危险操作确认。

### 7.6 网络与代理

代理模式使用严格联合：

    type ProxyMode =
      | { kind: 'system_default' }
      | { kind: 'system_proxy' }
      | { kind: 'custom'; protocol: ProxyProtocol; host: string; port: number; credentialRef?: SecretRef }
      | { kind: 'direct' }

代理密码保存到现有本机安全凭证边界的独立命名空间，设置文件只保存不可逆引用。连接测试只发送最小探测请求，不携带项目内容、提示词或服务商凭证；服务连接测试仍由阶段 4 的具体连接端口负责。

代理切换只影响后续网络请求；运行中请求和状态未知任务不得盲目重提。测试失败保留旧有效配置，必须明确显示 DNS、证书、认证、超时或不可判定状态。

### 7.7 通知

- 通知类型至少覆盖任务完成、任务失败、需要确认、下载完成、导出完成、空间不足、服务连接失效、更新可用和本地组件异常；
- 渠道按平台能力提供应用内、系统通知和声音；
- 任务失败、需要确认和存储不足等关键提醒不能被静默降为完全不可见；
- 系统权限被拒绝时保留应用内通知，不伪造系统发送成功；
- 通知发送失败不改变 Task/Execution 的业务状态。

### 7.8 快捷键

- 快捷键来自版本化动作注册表，不允许 UI 创建未知业务动作；
- Windows 和 macOS 分别保存并显示按键，不能跨平台覆盖；
- 修改前检测应用内重复、系统保留键和不可修改动作；
- 冲突未解决时拒绝保存，恢复默认可按单项、分类或平台执行；
- 全局快捷键只有在真实注册成功后才显示启用，卸载或退出时释放。

### 7.9 日志与诊断

- 日志本地保存，按类别、级别、大小和保留期滚动；
- 凭证、Token、Cookie、代理密码、请求头、完整本地路径、用户原始素材和完整提示词默认排除或脱敏；
- 诊断预览先显示将包含和排除的清单，再由用户生成本地压缩包；
- 诊断包只写用户选择的本地位置，不自动上传；
- 打开日志目录、清理日志和诊断缓存都通过受控主进程操作。

### 7.10 应用更新

- 更新项按应用、获批媒体组件、内置适配器、服务商预设和帮助资源分别建模；
- 每项必须返回当前版本、渠道、检查能力、签名状态、可用版本和不可用原因；
- 更新前检查运行中任务、未保存草稿、本地导出、组件修复任务和磁盘空间；
- 下载完成后必须验证完整性、来源和签名，安装与重启由用户确认；
- 未实现或未获批的修复、回退、组件更新和应用更新不得出现在可执行 UI 中。

当前仓库没有生产更新源、签名清单、打包器更新适配或回退产物，因此阶段 8 初始实现只能提供真实版本状态和 `unavailable` 原因；不得为了匹配设计图伪造“已是最新”或“可回退”。

## 八、平台端口与能力矩阵

建议端口：

    SettingsRepository
    SettingsCapabilityDetector
    DirectoryAccessPort
    StorageUsagePort
    TaskPolicyPort
    MediaComponentPort
    PermissionPort
    ProxyPort
    NotificationPort
    ShortcutPort
    DiagnosticPort
    UpdatePort

能力状态统一为 `available | unavailable | permission_required | unsupported | unknown | failed`，并携带稳定原因码。`unknown` 和 `failed` 不能投影成可用。

Windows/macOS 差异至少覆盖：开机自启动、关闭/最小化、系统通知、Dock/任务栏、目录授权持久化、外接盘、代理、系统保留快捷键、更新安装与重启。macOS 实机完整证据仍在阶段 9，但阶段 8 端口和测试夹具必须提前保持跨平台。

## 九、故障、一致性与安全

- 设置保存失败：保留 UI 待保存值和服务端旧 revision，允许重试或重新载入；
- revision 冲突：返回最新快照与冲突键，不静默覆盖；
- 目录不可写/断盘：保留旧目录和迁移计划，不修改历史 FileReference；
- 清理中断：已删除项可重建，未删除项保留；不得以完成状态掩盖部分失败；
- 代理状态未知：查询远端任务状态后再决定继续，禁止盲目生成新请求；
- 快捷键注册失败：回滚新注册并恢复旧有效绑定；
- 诊断生成失败：删除不完整包，保留原日志；
- 更新检查失败：显示真实错误和上次成功检查时间，不宣称最新；
- 设置文件损坏：尝试已验证备份，否则进入只读恢复，不覆盖证据。

## 十、测试与验收

自动化必须覆盖：

- V1 Schema、默认值、严格校验、逐版本迁移和损坏恢复；
- revision 冲突、并发写入、临时文件、原子替换和备份恢复；
- 便携设置导入/导出明确排除凭证、路径和设备事实；
- 所有高风险操作均无法绕过 plan/confirm/execute；
- 目录迁移成功、空间不足、目标冲突、断盘、复制中断和校验失败；
- 并发降低不破坏活动任务，策略只影响新任务/attempt；
- 代理凭证不进入设置文件和 renderer，失败保留旧配置；
- 通知权限拒绝后应用内降级，业务状态不被通知结果改变；
- 快捷键应用内冲突、系统保留键、注册失败回滚和平台隔离；
- 诊断脱敏、预览、生成失败清理和不自动上传；
- 更新适配器缺失、签名失败、任务阻断和未实现能力隐藏；
- renderer DTO 不含路径、Hash、秘密、日志原文、更新 URL 或平台句柄；
- 固定 10 分类、冻结视觉、键盘可达、焦点、错误、保存和确认状态；
- Windows Electron 真实设置保存/重开、目录选择、代理失败、通知权限、快捷键冲突、诊断导出和不可用更新状态；
- 完整 Node/Vitest、TypeScript、ESLint、生产构建和差异检查。

阶段 8 收口不能因为设计图展示某项能力就把 `unknown` 或 `unavailable` 改写成成功。macOS 实机完整验收、生产更新链路、生产媒体组件分发和签名继续进入阶段 9/10 准入。
