# 提示词增强通用化与非流式改造验收记录

日期：2026-08-12

实施分支：`feature/prompt-enhance-generalization`

分支职责：承载通用提示词增强合同、`prompt_once` 非流式文本推理、项目上下文强制增强规则、可复用 UI/宿主适配和生成门禁；不修改会话页业务规则，不新增一级页面，不恢复已禁止能力。分支按项目规则保留，当前未合并 `develop`。

状态：PR1 → PR6 已按批准计划完成，自动化门禁通过，等待合并验收。

## 一、实际实现

- 新增与图片/视频类型无关的 `PromptEnhancePolicy`、输入快照、SHA-256 指纹、来源引用和当前结果匹配规则。
- 新增 `PromptEnhanceService` 与 `PromptEnhanceSubjectPort`。核心服务只处理通用主体快照、候选、确认、授权和结果，不依赖图片 Task；专业生图通过 `ImagePromptEnhanceSubjectAdapter` 读取草稿与固定版本项目上下文并写回系统补充。
- 公共 IPC/preload 使用 `promptEnhance`、`subjectId`、`subjectRevision`；保留 renderer 侧 `imagePromptEnhance` API 别名作为首个宿主的迁移兼容，不保留旧 IPC channel。
- 新增 `PromptEnhancePanel`。组件固定显示“文本推理 · 非流式”，移除增强面板中的 `text_chat` / `text_reasoning` 切换；有上下文显示必须增强，无上下文显示可选增强。
- DeepSeek/NewAPI 增加普通 JSON `requestChatCompletion`，`prompt_once` 发送一条包含系统优化规则、固定版本上下文正文和原始输入的 `user` message，并强制 `stream: false`；响应只接受单个完整 `chat.completion` 和 `finish_reason=stop`，不进入 SSE 收集器。
- 发请求前校验 package/version、adapter/version、连接配置版本、模板/凭证 Schema、endpoint policy、参数/结果/用量/约束 Schema 与模型身份；旧令牌、变化的原始输入或上下文快照均被拒绝。
- 提交令牌在主进程第一次异步操作前同步切换为 `submitting`，同一令牌的重复 IPC/双击只允许一个调用继续，失败后保持已消费并要求重新准备。
- `prompt_once` 复用项目 route snapshot、provider invocation 和 usage observation 仓储，调用记录新增 `prompt_once` 主体；只保存路由、生命周期和标准 token usage，不保存提示词正文或原始服务商响应。
- 已选择 `includeInPrompt=true` 项目上下文时，专业生图准备和提交都要求当前增强结果，且 `finalPrompt` 必须采用该结果；无项目上下文时保持可选。

## 二、关键边界

- `productFeature=text_reasoning` 表示模型能力；`executionMode=prompt_once` 决定非流式传输，两者独立。
- 会话页仍使用原有 `text_chat | text_reasoning` 与 SSE 流式适配器，本次没有修改其 UI、状态或传输合同。
- 提示词增强只产生最终提示词候选和来源追踪，不创建图片/视频 Task、Execution 或 Work。
- 上下文正文来自固定版本快照，不使用候选列表预览；输入过长直接阻断，不静默裁剪。
- 本次只实现当前已证据支持的 OpenAI Chat Compatible 单条 `user` message 路径；仅 `prompt` 字段的未来服务商需新增独立适配分支并提供真实合同证据。
