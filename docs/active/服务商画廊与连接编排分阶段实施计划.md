## 一、计划结论

本项包含「模型与服务商」页面前端重构（画廊首屏）、连接保存编排（验证→落库→拉目录一体化）、各供应商真实管理探针、Vidu 特权拉平与代码收敛五部分，不以单一大 PR 收口。

实施沿用「一支一验收、一支一合并」节奏，每支从最新 `develop` 创建，合并后保留本地与远程分支。

代码量目标：PR 1—3 新增约 2,500 行换取完整新体验；PR 4—5 通过冻结种子退役、验证脚手架归档和适配器收敛收回 4,500—7,000 行。**计划结束时功能增加，代码净量不高于现状（src 基线 85,630 行，2026-08-05 实测）。**

## 二、产品决策冻结（2026-08-05，项目负责人）

1. **页面两分**：进入「模型与服务商」默认看到供应商卡片画廊（添加视图），管理视图为第二视图承载已有连接列表与详情；
2. **画廊内容**：只展示真实适配的官方供应商（Vidu / DeepSeek / 火山引擎 / 可灵）与自定义兼容入口；搜索框按名称过滤；官方 / 自定义可筛选；未适配供应商不展示，画廊末尾设「求适配」反馈卡；
3. **保存即自动化**：添加视图点保存后主进程自动编排——先测试连通性，通过则保存连接并自动获取该供应商可用模型，不通过则报错；
4. **强制保存逃生口**：验证失败弹窗提供「返回修改」与「仍要保存」，后者落库为 `unavailable` 状态；
5. **目录按供应商能力分支**：有模型列表 API 的自动拉取；没有的跳过并开放手动登记；手动登记对所有已验证连接开放（含 catalog 类，作为目录外模型的补充入口）；
6. **目录失败不拖死保存**：验证通过但目录拉取失败时，连接照存（`available`）并提示可稍后重试；
7. **模型一律声明态**：自动拉取与手动登记的模型统一落为「已声明、未启用」，启用永远由用户手动完成；
8. **墓碑默认隐藏**：管理视图默认不显示 `deleted` 连接，筛选入口保留；
9. **Vidu 拉平**：创作路由改为按能力动态选择可用连接，冻结种子与联调脚手架随 PR 4 退役。

## 三、技术决策

1. **验证策略三类**：`catalog_probe`（GET 模型列表一次完成验证+目录，OpenAI 兼容系）、`account_probe`（免费账户查询端点）、`deferred`（无免费端点，保存标待验证，首次真实调用时验证）；每个模板的策略以对应供应商官方 API 文档为唯一依据；
2. **单次编排 IPC**：新增 `providers:addConnection`，主进程内串联 验证 → 落库 → 拉目录，经 preload 向渲染层推送 `testing → saving → syncing → done / failed` 步骤事件；
3. **明文凭证安全**：保存前验证使明文凭据短暂经过主进程，必须不落盘、不进日志、失败即弃；验证失败时磁盘不得存在任何凭证痕迹（专项测试锁定）；
4. **探测超时与错误分类**：默认 12 秒超时；错误按 凭证无效（401/403）/ 地址不可达（DNS/连接失败）/ 超时 / 其他 分类呈现；
5. **画廊数据来源于现有 Package Registry**：包描述符仅追加 `logo`（本地 SVG 入仓库）、`shortDescription`、`category` 三个展示字段，不新建版本化证据链；
6. **代码收敛原则**：不单独设立纯重构分支，收敛随功能分支完成；DeepSeek 与 NewAPI 的 OpenAI 兼容部分共用探针套件。

## 七、联网与数据安全闸门

- 开发期默认合成 transport、临时目录、零真实网络；
- 真实供应商验证端点的首次联网调用须按供应商逐项批准并记录端点、频率与费用上限；
- Vidu q3-lite 图片与 viduq3-turbo 视频预算已用尽，任何验证路径不得触发生成接口；
- Token / API Key / 原始响应 / 私有路径 / Prompt 不进 Git、日志、证据；
- 验证阶段明文凭据不落盘、不进日志、失败即弃；
- 任何未完成本地校验的远端结果不得登记为正式作品。

## 八、停止条件

- 供应商官方文档无法支撑验证策略，或免费验证端点不存在且未批准 `deferred`；
- 迁移可能覆盖历史连接、凭证引用或作品事实；
- DTO / 日志 / 证据泄漏凭证、端点细节或原始响应；
- 测试失败、未解释跳过、假进度或假验证结果；
- 需要真实联网或收费但无该项专项批准；
- 画廊展示未真实适配的供应商。
